# 3D 테트리스 AI 시뮬레이터

기존 2D 앱의 후보 생성·가상 착지·평가·미래 탐색을 공간 보드로 확장했습니다. 진입 주소는 `/#3d`입니다. 2D 화면의 새 버튼으로도 이동합니다. 차원을 바꾸면 해당 차원의 새 실험을 시작합니다.

## 게임과 좌표

보드는 가로 x, 높이 y, 깊이 z입니다. **3D의 y=0은 바닥**이며 위로 증가합니다. 2D 화면의 위에서 아래로 증가하는 y와 구분합니다. 셀은 `(y × depth + z) × width + x` 순서로 저장합니다.

큐브 4개로 이루어진 I/O/T/L/S/V/R/C의 8종을 사용합니다. X/Y/Z축의 90도 **회전만** 반복해 고유 방향을 열거합니다. 반사는 사용하지 않아 R/C 나선 블록은 구별됩니다. 방향 수는 각각 3/3/12/24/12/8/12/12입니다. V는 세 축으로 뻗는 가지 형태입니다.

상공에서 방향과 (x,z)를 정한 뒤 아래로만 낙하합니다. 출발 높이에서 보드 상단과 충돌하면 해당 후보는 불법입니다. 첫 충돌 지점에서 고정하며, 중간의 천장을 통과해 내부 구멍으로 이동하지 않습니다. 낙하 중 조작·벽차기·슬라이드·HOLD는 구현하지 않았습니다.

수평면의 모든 `width × depth` 칸이 차면 그 면을 삭제합니다. 동시에 완성된 면을 모두 제거하고, 위의 **전체 면**을 아래로 이동합니다. 개별 큐브를 중력으로 따로 흩어 떨어뜨리지는 않습니다. 따라서 면 삭제 후에도 큐브 아래 빈칸이 남을 수 있습니다.

[Blockout 공식 커뮤니티](https://www.blockout.net/)의 3D 낙하 블록 개념을 참고했습니다. 원작의 블록 세트·점수·시간 제약 전체를 복제한 버전이 아닙니다. [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)와 [OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)로 실제 입체 좌표를 렌더링합니다. 카메라 회전은 게임 보드나 블록 방향을 바꾸지 않습니다.

## 평가

각 (x,z) 열에서 가장 높은 큐브의 y+1을 `h(x,z)`로 정의합니다. 빈 열은 0입니다.

- H: 모든 열의 평균 높이.
- O: 같은 수직 열에서 큐브 아래에 있는 빈칸 수. 공기 연결 여부를 조사하는 폐쇄 공간 계산이 아니라 **수직 구멍** 지표입니다.
- B: x·z 두 방향의 모든 인접 열 높이 차이의 절댓값 합.
- A: 수평 이웃 쌍의 개수, `(width−1)×depth + (depth−1)×width`.
- M: 최고 높이. D는 상단 위험 기여로 `−8 × max(0, M−floor(0.75×height))²`.

```
F = −10×wHeight×H − wHoles×O − 10×wRoughness×B/A + W + D
R = wPlanes × (P + (P=4일 때 4, 아니면 0))
한 수 평가 = R + F
미래 경로 평가 Q = 경로 전체의 R 합 + 마지막 보드의 F
```

P는 이번 착지로 지운 면 수입니다. 4면 삭제의 추가 보상은 교육용 실험 값입니다. 원작 점수표가 아닙니다. 기본 가중치는 높이 1, 구멍 7, 굴곡 0.6, 삭제 18, 샤프트 2입니다.

샤프트는 `(width−1, depth−1)` 모서리의 세로 한 칸입니다. 바닥에서부터 샤프트만 비어 있고 나머지가 모두 찬 면의 연속 개수를 E, 샤프트 열의 높이를 S로 두면:

```
샤프트 전략: W = wShaft × (2×min(4,E) − S)
균형 전략: W = 0
```

준비된 면을 보상하고 샤프트를 막는 큐브를 벌점으로 처리합니다. I 블록이 오기까지의 생존이나 장기 최적 플레이를 보장하는 값은 아닙니다.

## 탐색과 상태

- Greedy는 모든 고유 회전과 (x,z)의 합법적인 착지를 비교합니다.
- 2-ply는 현재 블록의 모든 착지마다 공개된 다음 블록의 모든 착지를 계산합니다. 다음 수가 모두 막히면 해당 경로는 실패 점수로 처리합니다.
- Beam은 각 깊이에서 **전체 경로의 상위 K개**만 유지합니다. 깊이 1~3, K=1/4/8/16. 목표 깊이에 도달하지 못한 첫 수의 Q는 ‘미완료’로 표시합니다. 마지막 깊이까지 평가한 경로는 최종 빔에 남지 않아도 실제 Q를 표시합니다.
- 경로 점수가 같으면 구멍, 최고 높이, 회전 번호, z, x의 순서로 결정합니다. 보상은 경로 전체를 합하지만 보드 평가 F는 마지막 상태에서만 계산합니다.
- Worker에는 현재 보드·현재 블록·**공개 NEXT 3개**·설정만 전달합니다. 이후 공급 시퀀스를 전달하지 않습니다. 조건 변경 시 이전 Worker를 종료해 늦은 결과를 차단합니다.
- 공급은 시드 기반 8-bag입니다. 샤프트 예제는 학습을 위해 첫 블록을 I로 고정하고 이후부터 8-bag를 사용합니다. 나머지 예제는 처음부터 8-bag입니다.
- 후보/가중치 변경은 실제 보드를 바꾸지 않습니다. 놓기 동작에만 적용하고, 중복 클릭을 잠금으로 막습니다. 마지막 50개 변경을 되돌릴 수 있습니다.
- 층 편집·JSON 입력은 사용자 정의 보드로 표시합니다. 기존 실험 기록은 JSON에 포함되지 않습니다. JSON은 `version:1, dimension:3, board, piece`이며, 셀 0은 빈칸, 1~8은 블록 종류, 9는 편집/시나리오 큐브입니다.

## 초기 사례

5×5×12 보드에서 아래 4개 면의 모서리 한 칸씩만 비워 둡니다. 세워진 I가 그 네 칸에 놓이면 4개 면이 동시에 완성되어 삭제됩니다. 최종 보드는 비고 R=18×8=144입니다. Greedy·2-ply·Beam에서 이 배치를 선택하는지 자동 검증합니다.

새 CSS와 Three.js 모듈은 3D 진입 시에만 읽습니다. 실행 중 외부 API·모델 서버·3D 리소스 다운로드를 사용하지 않습니다. WebGL이 없으면 안내와 단면 화면을 제공하며 엔진 계산·편집·배치는 계속 사용할 수 있습니다.
