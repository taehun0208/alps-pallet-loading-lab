# 로봇 혼합 팔레타이징 설계 비판적 검토

**전제:** 링크된 데모에는 접속하지 않았고, 요약된 설명만 근거로 검토했습니다. 아래 내용은 모두 설계와 수식 수준의 분석입니다. 실행시간, 붕괴 확률, 성능 수치는 제시하지 않으며, 측정이 필요한 곳은 "측정 필요"로 표시했습니다.

---

## 0. 먼저 확인된 산술 및 논리 오류

| 위치 | 주장 | 문제 |
|---|---|---|
| 5번 | 3 arms × 3 boxes × 2 rot × 20 pos = 360 | 곱셈은 맞습니다. 다만 데모의 "기본 후보 64개"와 연결되지 않습니다. 팔당 3×2×20 = 120인데 64는 어떤 분해인지 명시가 필요합니다. |
| 5번 | 360 × n=100 = 36,000 pair checks | 독립 팔레트라면 후보는 **자기 팔레트의 박스와만** 겹침 검사를 합니다. n=100이 4개 팔레트 전체 합계라면 과대계상이고, 팔레트당 100개라면 맞습니다. 정의를 명시해야 합니다. |
| 5번 | exhaustive joint = 21 choices/arm → 21³ = 9,261 | **앞 단락과 모순됩니다.** 팔당 유효 후보는 120개이므로 idle을 포함하면 121개이고, 121³ = 1,771,561, 121⁴ = 214,358,881입니다. 21은 "위치 20 + idle"로 보이며 박스와 회전 차원이 빠져 있습니다. |
| 5번 | shortlist 5+idle → 6³ = 216, 6⁴ = 1,296 | 산술은 맞습니다. 다만 조합마다 C(R,2)쌍을 검사하면 216×3 = 648, 1,296×6 = 7,776이 됩니다. 쌍별 호환표를 미리 만들면 서로 다른 쌍은 C(R,2)·5² = 75(R=3), 150(R=4)뿐입니다. |
| 3·5번 | 후보 = (box, robot, pallet, pose, **start time**) | 개수 계산에 start time 차원(×\|T\|)과 pallet 차원(Zhu 등처럼 한 팔이 여러 팔레트를 가지면 ×P_r)이 빠져 있습니다. |
| 3·5번 | "3 arms × 3 observed boxes" | 데모는 **셀 진입 박스만** 각 셀에서 선별합니다. 같은 3개 박스를 모든 팔이 동시에 본다는 가정은 데모 구조와 다르며, 실제로는 팔마다 B_r이 다릅니다. |
| 2번 | 동일 용량 팔레트 간 즉시 이용률 증가량 동일 | P가 고정일 때만 성립합니다. "사용 팔레트 수"로 P를 정의하면 **새 팔레트를 여는 배정은 P를 늘려 분모를 바꾸므로** 동일하지 않습니다. Hmax나 바닥 치수가 다른 팔레트가 섞여도 깨집니다. |
| 논문 요약 | 2,256 / 163,200 < 1.4% | 2,256/163,200 ≈ 1.38%로 맞습니다. 다만 이것은 **단계당** 불일치율입니다. 팔레트 하나에 수십 단계가 있고 오류가 독립이 아니므로 "팔레트당 한 번 이상 불일치" 비율은 이보다 훨씬 클 수 있습니다. 또 오수락(위험)과 오거절(효율 손실)이 섞인 합계라서 안전성 지표로 바로 쓸 수 없습니다. |

추가로 확인한 점이 있습니다. **균등 밀도 직육면체에서 지지면적 ≥ 92%이면 자기 무게중심은 지지 볼록껍질 안에 자동으로 들어갑니다.** 중심을 포함하지 않는 볼록집합은 중심을 지나는 반평면 안에 놓이므로 면적이 최대 50%이기 때문입니다. 따라서 92% 조건에서 "자기 COG ∈ hull" 검사는 중복이고, 실제 위험은 **상부 하중을 포함한 합력 작용점**과 **아래 박스로의 전파**에 있습니다. 경계 근처의 여유(margin)는 여전히 의미가 있습니다.

## 1. 핵심 수정사항 (5개)

### ① 계산량 표기를 내부적으로 일관되게 다시 쓰기
- joint 공간은 21^R이 아니라 (Σ후보_r + 1)^R입니다. shortlist 효과는 "(|B_r|·O·|E_r|+1)^R → (k+1)^R"로 표현해야 합니다.
- **미래 수용 손실 항이 숨은 최대 비용입니다.** 모든 후보에 대해 다른 관측 박스들의 배치 가능성을 다시 계산하면 후보 생성 비용에 (N_k−1)·O·|E| 배 정도가 곱해집니다. 따라서 이 항은 **top-k에만 계산**하도록 명시해야 합니다.
- 정밀 안정성 재검사는 "선택안 1회"가 아니라 "통과할 때까지 시도한 횟수 × C_exact"입니다. 최악의 경우 모든 후보를 시도할 수 있으므로 시도 횟수에 상한이 필요합니다.

### ② 안정성: 국소 검사를 영향받는 스택 검사로 바꾸고, 근사와 정밀의 지위를 분리
- 새 박스 A만 검사하면, A가 놓인 B의 **(B 자중 + A 하중) 합력점**이 B의 지지 껍질 밖으로 나가는 경우를 놓칩니다(반례 1).
- 다중 지지는 강체 가정에서 정역학적으로 부정정입니다. 면적비 분배는 하나의 가정일 뿐 평형을 보장하지 않습니다. 정밀 판정은 "음이 아닌 접촉력 분포가 존재하는가"라는 **실현가능성(LP) 문제**로 정의하는 것이 일관됩니다. 이것이 논문의 SME에 해당하는지는 원문에서 확인이 필요합니다.
- 1번의 "hard constraint"는 **근사 통과(approx-pass)**와 **정밀 검증(verified)** 두 등급으로 나눠야 합니다. 6번의 timeout 반환은 verified만 허용해야 합니다. 그러려면 탐색 시작 직후 greedy 1순위를 먼저 정밀 검증해 두는 **anytime 구조**가 필요합니다.
- 92%는 물리 상수가 아니라 정책 파라미터로 다루고, 민감도 실험 대상에 포함해야 합니다.

### ③ 중앙 오케스트레이터의 결합 구조를 정확히 모델링
- 독립 셀·독립 팔레트라면 팔 사이의 결합은 세 가지뿐입니다.
  - (a) 같은 박스 경합
  - (b) 순환 컨베이어의 **take/pass 순서**(박스는 셀 1→2→3→4 순으로 도달)
  - (c) 겹치는 운반 경로 예약
- 따라서 문제는 "R개 팔의 곱공간 탐색"보다는 **박스별로 take 또는 다음 셀로 pass를 정하는 순차 결정 + 경로 충돌 제약**에 가깝습니다. 경로 충돌이 희소하면 박스-팔 배정(이분 매칭)과 셀 순서 DP로 분해하는 편이 곱공간 열거보다 정확하고 저렴합니다.
- 로봇별 top-k를 로컬 점수로만 뽑으면 모든 팔의 top-k가 같은 박스로 몰릴 수 있습니다(반례 3). 대책은 다음과 같습니다.
  - **로봇·박스별 top-k(다양성 보장)**
  - idle/pass 행동을 명시적 후보로 포함
- 가산형 joint 점수에서 행동 점수가 음수일 수 있으면 최적화기가 idle을 선호합니다. **배치 자체의 기본 가치(처리량 항)**가 필요합니다.
- 커밋 프로토콜이 필요합니다. 팔레트 상태와 경로 예약에 대해 버전 기반 compare-and-swap을 적용하고, 실패하면 해당 로봇만 재계획합니다. 실제 완료 피드백이 오기 전까지는 예약을 "계획됨" 상태로 둡니다.
- 무한 재순환을 막아야 합니다. 어느 팔레트도 받지 못하는 박스는 계속 돌기만 하므로 **재순환 횟수 상한과 reject 경로**가 필요하고, 컨베이어 점유 포화도 KPI에 넣어야 합니다.

### ④ KPI와 점수의 게이밍 방지
- 이용률 sum(V)/(P·L·W·Hmax)는 **어려운 박스를 거부하거나 재순환시키면 오히려 올라갑니다.** 처리율(처리 박스 수/공급 박스 수)과 반드시 짝으로 보고하고, 미처리 박스를 숨기지 않아야 합니다.
- 팔레트 교체(마감) 규칙이 이용률을 직접 바꾸므로 마감 규칙을 정책의 일부로 고정하고 비교해야 합니다.
- 연속 공급에서는 makespan이 정의되지 않습니다. 둘 중 하나로 고정해야 합니다.
  - 고정 N박스: 전부 처리 또는 거부될 때까지 실행
  - 고정 시간창: 처리량 측정
- 이벤트별 min-max 정규화는 쓰지 않아야 합니다. 후보가 1~2개일 때 잡음을 증폭하고, 이벤트 간 점수 비교를 불가능하게 만듭니다. **고정된 물리 기준값**으로 정규화합니다(아래 2절).

### ⑤ 실험 설계의 공정성과 누설 차단
- 방법 간 비교는 **동일한 계산 예산(동일 deadline)** 아래에서 해야 합니다. 예산이 다르면 알고리즘 차이와 예산 차이가 섞입니다.
- 오라클 누설을 막아야 합니다. 시뮬레이터가 아는 실제 미래 박스열이 미래 손실 항에 들어가면 안 되며, **N_k(관측)로 계획하고 N_b(집기 가능)로만 실행**합니다.
- held-out 시드에 대해 Claude 제안 → 평가 → 수정을 반복하면 held-out이 사실상 학습셋이 됩니다. 마지막 1회만 쓰는 **lockbox 테스트셋**을 따로 두어야 합니다.
- 시드만 바꾸는 것으로는 부족합니다. 박스 크기 분포, 무게 분포, 도착률이 다른 **시나리오 군**에서 분포 이동을 검증해야 합니다.
- 브라우저 측정치(JIT 워밍업, 탭 스로틀링, GC)는 제어기 지연의 근거가 될 수 없습니다. p95/p99는 목표 런타임에서 측정이 필요합니다.

## 2. 권장 점수식

Hard constraint를 통과한 후보만 점수를 매기고, 제약 위반을 점수로 상쇄할 수 없게 합니다.

**배치 행동 a = (b, r, p, pose, t):**

$$
S(a) = w_P - w_F F - w_G G - w_H H - w_T T - w_O O + w_S M_S + w_L M_L
$$

**pass/idle 행동:**

$$
S(\text{pass}_b) = -w_R R_b, \qquad S(\text{idle}_r)=0
$$

**joint 결정:** 호환되는(같은 박스 중복 금지, 경로 예약 충돌 없음) 행동 조합 중 ΣS를 최대화합니다. 박스는 정확히 하나의 take 또는 pass를 받습니다.

### 항목별 정의와 정규화

| 항 | 정의 | 정규화 / 범위 |
|---|---|---|
| **P** (배치 가치) | 배치 시 상수 | w_P가 처리량 선호를 결정합니다. idle 편향을 막는 역할입니다. |
| **F** (미래 수용 손실) | 관측 집합 K(현재 박스 제외)에 대해 Σ v_j[feas_before(j) − feas_after(j)] / Σ v_j·feas_before(j) | 분모가 0이면 0입니다. 배치가 새 지지면을 만들어 오히려 가능해지는 경우가 있으므로 [−1,1]로 두거나 0 이하는 0으로 자릅니다. **top-k에만 계산**합니다. |
| **G** (잔여공간 파편화) | ΔV_unusable / (L·W·Hmax). unusable은 어떤 변이 d_min보다 작은 빈 공간이며, d_min은 **고정 카탈로그** 기준입니다(관측 박스 기준이면 이벤트마다 변동). | [−1,1]에서 clip합니다. 2D height map 기반이면 가려진 공간이 빠지므로 1차 근사로 표시합니다. |
| **H** (높이 증가) | (z_top,after − z_top,before)⁺ / Hmax | [0,1] |
| **T** (시간) | (t_end − t_now) / T_ref. T_ref는 해당 셀의 집기 시간창 길이(고정 설정값) | [0,1]에서 clip합니다. 시간창 초과는 hard constraint입니다. |
| **O** (팔레트 개설) | 새 팔레트를 열면 1 | {0,1} |
| **M_S** (안정 여유) | 영향받는 박스 집합 A에 대해 min_{i∈A} δ_i / (½·min(l_i, w_i)). δ_i는 합력점에서 지지 껍질 경계까지의 부호 거리 | 자연스럽게 [0,1]이고, 음수는 hard constraint에서 제거됩니다. 과보수를 보상하지 않도록 상한을 둘 수 있습니다. |
| **M_L** (하중 여유) | min_{i∈A} (1 − F_i / F_allow,i) | [0,1] |
| **R_b** (재순환 위험 대리값) | 1 − min(D_b, D_ref)/D_ref + c_b/c_max. D_b는 현재 관측 상태에서 b를 받을 수 있는 하류 셀 수, c_b는 재순환 횟수 | [0,2]입니다. **확률이 아니라 대리지표**로 명시합니다. |

### 운용 원칙
- 초기 가중치는 같은 크기로 시작해 train 시드에서 튜닝합니다. 항들 사이에 상관(예: H와 G)이 있으면 가중치가 식별되지 않으므로 **민감도 분석**을 함께 보고합니다.
- 대안으로 **사전식(lexicographic)** 방식이 있습니다. 처리 수를 먼저 최대화하고, 다음에 F+G, 다음에 여유 항을 봅니다. 가중합과 비교할 baseline으로 둘 가치가 있습니다.

## 3. 더 정확한 계산복잡도 표현

**기호:** R = 팔 수, B_r = 팔 r의 집기 가능 박스, O = 허용 회전, E_r = 후보 위치(extreme point 수 ≈ O(n_p)), n_p = 해당 팔레트 박스 수, m = 활성 경로 예약 수, k = shortlist 크기, |T| = 시작시각 이산화 수, |A| = 영향받는 접촉 하위그래프 크기.

**이벤트당 비용:**

$$
C_{\text{event}} \approx \underbrace{\sum_r |B_r|\,O\,|E_r|\,|T|\,\big(C_{\text{ov}} + C_{\text{sup}} + C_{\text{path}}\big)}_{\text{생성·근사검사}} + \underbrace{\sum_r k\,\big(C_{\text{load}}(|A|) + C_F\big)}_{\text{shortlist 정밀 점수}} + C_{\text{joint}} + \underbrace{a\cdot C_{\text{exact}}}_{\text{정밀 재검사}}
$$

각 항의 크기:
- **C_ov:** 단순 AABB는 O(n_p)이고, spatial hash를 쓰면 평균적으로 O(1+국소 이웃 수)입니다. 국소 이웃 수는 데이터에 의존하며 최악의 경우 개선이 없습니다.
- **C_path:** 대략 O(m·s)입니다(s = 경로 세그먼트 수).
- **C_load:** O(|A|)이고 최악의 경우 O(n_p)입니다. O(1) 갱신은 전체 질량중심(누적 질량·모멘트)에만 해당합니다.
- **C_F:** 대략 (|K|−1)·O·|E|·C_ov입니다. 모든 후보에 적용하면 생성 단계 전체에 이 값이 곱해지므로 shortlist로 한정해야 합니다.
- **C_joint:**
  - 순진한 열거는 O((k+1)^R · R²)입니다.
  - 쌍별 호환표를 미리 계산하면 O(R²(k+1)²)이고, 이후 열거나 분기한정을 수행합니다. 지수항 (k+1)^R은 열거 방식에서는 남지만, 결합이 박스 경합뿐이면 매칭으로 다항 시간에 풀립니다.
- **a:** 정밀검사 시도 횟수이며 상한이 필요합니다.
- **누적:** 단순 AABB 기준으로 팔레트 하나를 채우는 데 Σ_{i≤N} O(i) = O(N²) 회의 쌍 검사가 듭니다.
- **maximal empty spaces:** 박스가 늘수록 개수가 초선형으로 늘 수 있습니다. 개수 상한과 지배 공간 제거 규칙이 필요하며, 실제 증가율은 측정이 필요합니다.
- **병렬화:** 상수(벽시계 시간)를 줄일 뿐 위 차수를 바꾸지 않는다는 원안의 지적이 맞습니다.
