# 실행과 파일 안내

아래 명령은 보존한 README와 소스에 근거한 안내다. 이번 폴더 정리 중 제품 실행·테스트·재배포를 다시 하지 않았다.

## 로컬 화면 실행

Python 3.10 이상이 필요하며 기존 안내상 추가 Python 패키지는 필요하지 않다. 이 이어가기 폴더에서 터미널을 열었다면 다음을 실행한다.

```sh
cd snapshot/pallet-lab
python3 server.py
```

브라우저에서 `http://127.0.0.1:8765`를 연다. 서버는 기본적으로 로컬 주소와 8765 포트를 사용한다. 종료는 실행 중인 터미널에서 Ctrl+C다. 이 폴더를 옮겼다면 옮긴 위치의 `snapshot/pallet-lab`을 기준으로 한다.

기존 프로젝트에서 계속할 경우에는 원본 `pallet-lab`에서 같은 명령을 사용한다. 이 사본과 원본 중 어느 쪽에서 작업하는지 먼저 정한다.

## 개발 상태와 배포 상태

저장된 공개 주소: [Pallet Lab](https://pallet-lab-taehun.taehun20030208.chatgpt.site/). 마지막 저장된 배포 기록은 [v8](snapshot/pallet-lab/results/v8/site-deployment.json)이다. 이번 정리 중 공개 주소의 현재 가동 상태는 확인하지 않았다.

로컬판은 Python 서버가 계산한다. 웹 배포본은 방문자 브라우저의 Pyodide Web Worker에서 계산한다. 첫 로딩에 런타임 다운로드가 필요할 수 있고 방문자마다 상태가 분리된다. 공동으로 같은 실행 상태를 편집하는 시스템이 아니다.

[빌드 도구](snapshot/pallet-lab/share-site/tools/build_site.py)는 원본 소스와 화면을 `share-site/dist/`로 복사하고 통신 연결 부분을 변환한다. 읽기 전용 확인에서 핵심 원본 8개와 현재 `dist/source-manifest.json`의 해시가 일치했다. 이것은 로컬 빌드 파일의 일치이며 공개 서버의 최신 상태 확인은 아니다.

`docs/62`의 미래 공간 추가 평가와 50ms 비교는 **실험 파일 안에서만 적용**됐다. 현재 제품 엔진과 화면에 그 정책이 추가된 상태가 아니다. 복사에서 앱 배포 설정 `.openai`와 `.git`은 제외했으므로 이 폴더 자체가 공개 발행 권한이나 배포 연결을 포함하지 않는다.

## 보존해야 할 기술적 전제

1. 전체 종류·수량을 알아도 실제 미래 순서는 계획기에 전달하지 않는다. 가상 순서는 잔여 물량으로 만든다.
2. 현재 모델은 초기 배치 포함 최대 60개, 직육면체, 수평 0/90도 회전이다. 경계 좌표 기반 후보를 사용하므로 완전탐색이나 최적해 보장이 아니다.
3. 단일 팔레트 실행기의 관측 버퍼와 공정 실행기를 구분한다. 공정 실행기는 strict FIFO·버퍼 1, 공급 정지 가능, 고정 셀, 적재 중 AMR 정지·도킹을 가정한다. 격리 물량은 자동 재투입되지 않는다.
4. 내부 시간 예산은 협력식 중단 기준이다. 250ms 설정이 250ms 이내의 전체 응답을 보장하지 않는다. 기기·부하에 따라 완료한 탐색 범위가 달라질 수 있다.
5. 실측한 것은 판단 계산시간이다. 로봇·AMR·입고·격리·교체 시간은 모델의 근사와 설정값이다.
6. 물리는 준정적 근사이며 로봇은 고정 TCP·박스·툴 경로의 근사다. 관절 역기구학, 팔 링크 전체 충돌, 흡착, 동적 붕괴, 실제 박스 압축 강도, 운송 안정성은 검증하지 않았다.
7. 센서·PLC·실물 로봇·실제 AMR 제어 연동이 없다. 손상·누락 확인·규격 변경은 관측 입력으로 제공한다.
8. 기존 적재 상태는 재판단 중 임의로 옮기지 않는다. 무게와 강도를 같은 값으로 취급하지 않으며, 미션의 무거운 박스/가벼운 박스 규칙은 별도 정책이다.
9. 최신 최소 실험은 원본 제품 코드를 수정하지 않은 비교다. 연구 정책을 제품 화면에 적용하려면 별도 구현·검증이 필요하다.

## 테스트와 재실험 안내

코드를 수정한 뒤 관련 테스트를 실행할 수 있다. 전체 회귀 검사 명령은 기존 README에 다음과 같이 기록돼 있다.

```sh
# snapshot/pallet-lab 폴더에서
python3 -m unittest discover -s tests -v
node --test tests/*.mjs
```

관련 테스트 예시는 `test_engine.py`, `test_planner_v8.py`, `test_award_independent_v8.py`, `test_operations_v6.py`, `test_operations_independent_v6.py`다. 단순 문서 인수인계 때문에 이번에 다시 실행하지는 않았다.

v8 재실험 도구는 새 라벨을 사용한다. 예를 들어 아래 라벨이 아직 없는 것을 확인한 후 사용할 수 있다.

```sh
python3 award_experiments.py run --label comparison-02
```

세 방향 실험은 `study.py`의 `freeze`, `run`, `summarize` 흐름이다. 기존 결과 덮어쓰기를 거부하도록 되어 있으므로 다음 실험은 별도 결과 폴더와 새 입력으로 준비한다. `experiments.py`, `benchmark.py`를 무심코 재실행해 과거 결과와 섞지 않는다.

정적 배포 파일을 다시 생성하는 기존 명령은 `share-site` 폴더에서 `python3 tools/build_site.py`다. 로컬 빌드이며 공개 발행은 아니다. 공개 배포에는 별도 연결 확인이 필요하다.
