## Pallet Loading Lab — 온라인 혼합 박스 적재

**[팔레트 시뮬레이터 열기](http://127.0.0.1:5173/#pallet)** · 기본은 현재 입고 박스와 미입고 종류별 수량만 쓰는 **온라인 Greedy**입니다. 실제 미래 순서를 읽거나 미입고 큰 박스를 먼저 꺼내지 않습니다. 서로 다른 치수·무게·재질·허용 하중의 개별 박스 30개를 합성하며, 팔레트 분할 규격에 맞춰 치수를 보정하지 않습니다.

관통·돌출·지지·모든 아랫단의 누적 반력/강도/중심을 먼저 검사합니다. 과제 기본은 **무거운 상자를 가벼운 직계 받침 위에 놓지 않는 규칙**과 공구 포함 가반·작업공간·그리퍼/운반 상자의 접근·이탈 스윕을 켭니다. 잔량의 후속 위치도 같은 하드 검사로 비교하며 Rollout은 실제 입고와 독립인 같은 가상 순서와 고정 후속 정책을 씁니다. 안전 높이에서 파지 방향을 회전하며 회전 중 외곽·작업공간·경로 전체 TCP 도달 반경을 검사합니다. 확정 적재를 유지하는 조건/현재 관측 부분 재계획과 공통 패턴 점수·조건별 비교 기록도 제공합니다. 로봇 관절·IK·전체 링크 충돌과 포장 압축 변형은 미검증입니다.

세 정책 비교, 단계별 3D 프레임, 개별 아랫단 하중 중심, 탈락 사유, 독립 강체 검증을 제공합니다. 정상 박스의 검토 위치가 없으면 해당 박스와 잔량을 보존해 중단합니다. 주변 높이 맞춤 추가 전의 동일 입력 실험은 BL 7/30, Greedy 8/30, Rollout 7/30이며 전체 적재 성공이나 최적성을 주장하지 않습니다. 모든 박스를 꺼내 순서와 위치를 함께 고르는 방식은 **전체 재고 재정렬 연구 모드**로 구분했습니다.

사용법은 **[PALLET-TETRIS.md](PALLET-TETRIS.md)**, 최신 자세·도달·부분 재계획·패턴 점수·조건별 비교는 **[요구사항 보완 보고서](docs/MIXED-PALLETIZING-REQUIREMENTS.md)**, 온라인 탐색 수식은 [앞선 알고리즘 보고서](docs/ONLINE-MIXED-PALLETIZING.md), 실제 실행은 [측정 JSON](docs/pallet-online-measurements.json), 검증은 [VERIFICATION.md](VERIFICATION.md)에 있습니다. 과거 전체 재고 실험과 규격 박스 결과는 해당 조건의 기록으로 보존합니다.

## 네 로봇의 동시 작업과 수신 판단

**[4대 동시 시뮬레이터](http://127.0.0.1:5173/?palletDemo=relay#pallet)** · 각 팔은 독립적으로 집기·적재·보류·회수를 실행하며, 먼저 끝난 팔은 다른 팔의 완료를 기다리지 않고 다음 후보를 계산합니다. 동일 전달대와 겹치는 운반 경로만 배타 예약합니다.

## 세로 박스의 주변 높이 맞춤

**[수정된 혼합 적재 실행](http://127.0.0.1:5173/?palletDemo=compact#pallet)** · 긴 세로 박스가 이웃보다 홀로 솟지 않도록 가까운 눕힌 적재와 상단 높이를 비교합니다. 기본 돌출 한도는 **100mm와 박스 높이 25% 중 작은 값**입니다. 재고 선택 모드는 주변 층을 먼저 쌓고 보류한 세로 박스를 다시 검사합니다. **적재 제약 · 환경**에서 조정하고, **내부 공간과 박스 자세**에서 실제 높이 차를 확인합니다.

기본 같은 입력은 **16개 유지, 높이 1325→964mm, 내부 채움 72.1→87.5%**입니다. 랜덤 세 입력 모두 높이 조건 위반 0개이며 기존 강체 검사를 통과했습니다. 다른 두 입력은 적재 수가 15→9개, 19→17개로 줄었습니다. 버퍼 없는 순차 입고에서는 첫 세로 박스부터 막힐 수 있으므로, 재고 모아서 쌓기는 위 직접 링크를 사용하세요. [조건·결과·검증](docs/STANDING-HEIGHT.md).

## Windows에서 실행

Node.js 22.12 이상 또는 현재 환경에서 확인한 Node.js 24를 사용하세요. 의존성 설치 때만 인터넷이 필요합니다. [Vite 공식 실행 환경](https://vite.dev/guide/)을 참고할 수 있습니다.

PowerShell에서 프로젝트 폴더로 이동한 뒤:

```powershell
npm.cmd ci
npm.cmd run dev
```

브라우저에서 `http://127.0.0.1:5173/`을 엽니다. 이 주소에서 실제 실행을 확인했습니다. 5173 포트를 이미 사용 중이면 먼저 기존 서버를 종료하거나 `npm.cmd run dev -- --port 5174`로 다른 포트를 지정하세요. 서버 종료는 터미널에서 `Ctrl+C`입니다.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`preview`의 기본 주소는 `http://127.0.0.1:4173/`입니다. `dist/`를 정적 웹 서버에 올릴 수도 있습니다. Web Worker와 ES 모듈 때문에 HTML 파일을 `file://`로 직접 열지는 마세요.

## 3D 시뮬레이터

상단 **3D 시뮬레이터** 버튼 또는 `http://127.0.0.1:5173/#3d`로 엽니다. 기존 2D 실험도 그대로 사용할 수 있습니다.

- **한 수 놓기**: 기본 예제에서 I 블록이 세로 샤프트에 내려가 4개 수평면을 실제로 지웁니다. **되돌리기**로 이전 보드를 복구합니다.
- **자동 재생**: Greedy·2-ply 전수 탐색·Beam을 선택해 반복 배치를 관찰합니다. 깊이·폭·가중치·샤프트 전략을 바꿀 수 있습니다.
- **드래그 / 휠 / 두 손가락**: 카메라 회전과 확대. 입체·위에서·정면 버튼으로 시점을 바꿉니다.
- **직접 배치**: 블록 종류, X/Y/Z축 회전, x·z 위치를 고른 뒤 놓습니다. 방향키로 이동, Q/W/E로 회전, Space로 배치합니다.
- **층별 단면**: 내부의 빈칸을 확인하고, 위쪽을 잘라 보거나 선택한 층을 편집합니다. 보드 JSON도 저장·불러올 수 있습니다.

4×4×10, 5×5×12, 6×6×14 보드와 8종 테트라큐브를 지원합니다. WebGL을 사용할 수 없는 환경에서도 단면과 엔진 실험은 동작합니다. 수식·좌표·원작과의 차이는 [3D-SIMULATOR.md](3D-SIMULATOR.md)에 기록했습니다.

### 2D 실험

첫 화면은 ‘구멍 하나가 선택을 바꾸는 이유’에서 일시정지합니다.

1. **재생**: 현재 상태 관찰부터 첫 결정을 설명한 뒤 멈춥니다. 가상 낙하 단계에서는 계산된 대표 후보 세 개를 차례로 보여줍니다.
2. **지표 계산** 단계에서 일시정지: 구멍 한 칸을 빗금과 ×로 확인하고 −8점의 기여를 확인합니다. 높이 막대와 이웃 높이 차도 같은 셀 좌표를 사용합니다.
3. **가중치 실험**에서 구멍 패널티를 0으로 조정: 같은 보드·블록의 선택이 바뀝니다. 패널에서 아래로 스크롤하면 모든 가중치를 볼 수 있습니다. 변경은 재생을 멈추고 새 분석을 만듭니다.
4. **다음 블록의 가능성**: Greedy와 2수 완전탐색을 바꾸면 첫 행동이 달라집니다. 즉시 평가와 마지막 보드의 경로 평가는 구분해 표시합니다.
5. **남길 가지, 버릴 가지**: 빔 너비를 변경하고 트리를 펼쳐 실제 유지·제외 수와 당시 경계 점수를 확인합니다.

후보를 누르면 착지 결과와 지표·해설이 함께 바뀝니다. **비교 고정**으로 두 후보를 나란히 보고, **이 수로 새 분기**로 동일한 미래 공급을 가진 새 실험을 시작합니다. 주요 화면은 별도 페이지 이동 없이 같은 상태와 보드 렌더러를 사용합니다.

**다음 설명 단계**는 설명 커서만 옮깁니다. **다음 블록까지**는 선택을 실제로 적용하고 다음 결정을 분석합니다. 마지막 설명 단계로 이동하면 결정이 한 번 적용됩니다. 되감기·재생으로 같은 결정을 다시 봐도 중복 적용하지 않습니다. 이미 적용한 결정에서 되감으면 적용 전의 기록을 봅니다.

Space는 재생·정지, 좌우 화살표는 단계 이동입니다. 입력·슬라이더·선택상자·버튼에 포커스가 있으면 전역 단축키가 입력을 가로채지 않습니다. 모션 감소 설정을 존중합니다. 모바일은 보드·해설·설정 탭을 사용합니다.

## 새 기능: 선수 전략 실험

왼쪽 **선수 전략** 탭에서 ‘I를 위한 한 열 남기기’, ‘쌓고, I로 네 줄 회수’, ‘기다리기보다 먼저 낮추기’를 선택하세요. 모바일에서는 먼저 **설정** 패널을 엽니다. 같은 보드에서 기존 균형 평가와 웰 평가가 선택한 수를 실제로 다시 계산해 보여줍니다.

**플레이 전략**은 균형, 오른쪽 9–0, 왼쪽 0–9, 가운데 6–3입니다. 웰 전략은 예약 열 보존·4줄 추가 보상·위험 높이를 평가에 더하며 Greedy·2수·Beam 모두에 적용됩니다. 금색 세로 표시가 예약 열이고, 6–3은 웰 위치 실험입니다. 비교 실행에는 실제 1·2·3·4줄 삭제 횟수도 표시합니다. 전략 설정은 JSON에 함께 저장하며 이전 JSON도 가져올 수 있습니다.

조사 출처, 수식, 고정 사례와 구현 범위는 [PLAYER-STRATEGIES.md](PLAYER-STRATEGIES.md)를 참고하세요. 이 추가 보상은 교육용 값이며 실제 게임 점수표·B2B·콤보 계산을 복제한 값은 아닙니다.

## 교육용 게임 규칙

- 보드 10×20, I·J·L·O·S·T·Z. x는 왼쪽, y는 위에서부터 0으로 증가합니다.
- 상공에서 회전과 x를 정하고 **수직으로만 떨어뜨립니다**. 중복 점유 모양의 회전은 제거합니다. 벽·기존 셀·바닥을 통과하지 않으며, 닫힌 구멍으로 순간 이동하지 않습니다.
- 고정 시 셀이 위 경계를 벗어나면 **줄 삭제 전에** 실패합니다. 합법적인 후보가 없거나 요청한 경로를 끝까지 놓을 수 없으면 게임 오버입니다. 실패 후보는 정상 평가값으로 표시하지 않습니다.
- 완성 행을 동시에 삭제하고 빈 행을 위에 추가합니다. 고정 직후/삭제 전 보드와 삭제 후 보드를 별도로 보관합니다.
- 탐색 함수는 **현재 블록과 공개 NEXT만** 받습니다. 공급 배열·PRNG 상태는 전달하지 않습니다. 기본 NEXT 5개, HOLD 꺼짐입니다.
- 자유 실험과 학습 시나리오는 현재 블록과 공개 NEXT를 고정합니다. 이 여섯 블록은 실험용 입력이며 7-bag 묶음이라고 주장하지 않습니다. 이후 공급은 시드 기반 7-bag입니다. 비교 모드에서는 처음부터 같은 시드의 7-bag 배열을 세 실행에 공급합니다. 각 bag에는 7종이 한 번씩 있으며, 이것이 모든 실제 테트리스의 규칙이라는 뜻은 아닙니다.
- 실제 게임의 시간 제약·벽차기·슬라이드·T-spin·대전 공격 규칙은 지원하지 않습니다. 실제 온라인 게임 접속이나 자동 키 입력 기능도 없습니다.

## 평가 수식

아래는 **균형 / 생존** 전략의 기본 수식입니다. 웰 전략에서는 준비 상태·예약 열 보존·위험 높이를 F에 더하고, 4줄 추가 보상을 R에 더합니다. 추가 수식은 [PLAYER-STRATEGIES.md](PLAYER-STRATEGIES.md)와 앱의 상세 수식에 표시합니다.

| 지표 | 정의 | 초기 가중치 | 기여 |
| --- | --- | ---: | ---: |
| L | 이번 배치로 삭제한 행 수 | 10 | +10L |
| H | 열별 높이의 합. 빈 열은 0 | 0.5 | −0.5H |
| O | 같은 열 위쪽에 채워진 셀이 있는 빈칸 수 | 8 | −8O |
| B | `Σ |h[x] − h[x+1]|` | 0.7 | −0.7B |

```
R = 줄 삭제 보상 = 10L
F = 보드 평가 = −0.5H −8O −0.7B
Q = 한 수 평가 = R + F
경로 평가 = 경로의 R 합계 + 마지막 보드의 F
```

보드 특징은 **줄 삭제 후** 측정합니다. H는 최대 높이가 아니라 합계이며, 위로 열린 홈은 O에 들어가지 않습니다. 할인율은 1입니다. 중간 보드 F를 반복해서 더하지 않습니다. 표와 총점은 엔진의 동일한 기여 데이터에서 생성하며, 표시는 소수 첫 자리로 반올림합니다.

교육용 초기값과 프리셋은 전략 성향을 설명하기 위한 값이며 성능 보장이 아닙니다. 음수 점수도 정상입니다. Q와 경로 평가는 실제 게임 점수·성공 확률·생존 확률이 아닙니다.

## 세 알고리즘

- **한 수 선택(Greedy)**: 현재 블록의 모든 합법적인 착지를 평가합니다. 미래 단계를 생략하는 이유를 표시합니다.
- **2수 완전탐색**: 현재 블록과 NEXT 첫 블록의 모든 합법적인 두 행동 경로를 검사합니다. 첫 행동을 반환하며, 후속 행동·마지막 지표·누적 보상도 저장합니다.
- **가지 남기기(Beam Search)**: 기본 깊이 3, 너비 K=10. 깊이는 앞으로 놓을 블록 수로, 깊이 3은 현재 블록 + NEXT 두 개입니다. 깊이 1~5, UI의 K는 1·5·10·20·50입니다. 매 깊이 살아남은 부모들의 **전체 자식을 함께 정렬**해 K개를 남깁니다. 부모마다 K개씩 유지하는 방식이 아닙니다. 중간 순위에도 누적 R + 끝 보드 F를 사용합니다.

동점은 평가값 → 마지막 보드 구멍 수 → 마지막 보드 최대 높이 → 경로 순서의 회전 번호·x로 처리합니다. 같은 입력의 선택은 항상 같습니다. 시뮬레이션 시간을 제외한 결과·노드도 재현됩니다.

빔 탐색은 더 좋은 경로를 놓칠 수 있으며, 깊이·너비가 클수록 게임 성적이 항상 좋아지는 것은 아닙니다. 표시 트리는 계산된 실제 노드의 제한된 표본입니다. 생성·유지·제외·실패 수는 전체 계산값으로 별도 표시합니다. 상태 중복 병합은 하지 않습니다. 방어용 60,000후보 예산으로 중단할 경우 요청 깊이·완료 깊이·중단 이유를 표시합니다. 현재 UI 범위는 이 예산보다 작습니다.

## 검증된 학습 시나리오

각 시나리오는 초기 보드·현재/NEXT·가중치·탐색 설정·검증 조건을 함께 저장합니다. 승자와 점수·설명 숫자는 실행 엔진에서 계산합니다.

| 시나리오 | 검증 조건 |
| --- | --- |
| 가능한 위치 찾기 | 빈 보드의 T는 4회전, 34개의 합법적인 착지 |
| 구멍 하나의 대가 | 초기 구멍 0. 기본 선택은 0구멍, 패널티 0에서 다른 후보를 골라 1구멍 |
| 울퉁불퉁함 재기 | 수작업 열 높이 합 17, B=25, 구멍 0 |
| 줄 삭제와 평가 | 수직 I를 x=9에 놓아 4줄 삭제. 삭제 전 H=40, 삭제 후 H=O=B=0 |
| 다음 블록의 가능성 | Greedy는 r3/x7, 2수는 r2/x4. 2수 선택의 즉시 평가는 더 낮음 |
| 남길 가지, 버릴 가지 | K=1과 K=10의 생성·유지 수 차이, 매 깊이 생성=유지+제외 |
| I를 위한 한 열 남기기 | 같은 S에서 균형 r1/x8은 예약 열 높이 2, 웰 r0/x5는 열린 x9 유지. 둘 다 구멍 0 |
| 쌓고, I로 네 줄 회수 | O/x0으로 준비 4줄, NEXT I/x9로 4줄 삭제. 경로 기본 줄 보상 40 + 추가 보상 40 |
| 기다리기보다 먼저 낮추기 | 최대 높이 16에서 L/r3/x8로 3줄 삭제, 최대 높이 13 |

실제 선택 변화 사례는 개발용 결정적 탐색 `tests/find-fixtures.test.ts`로 찾았으며 `tests/fixtures-found.json`에 저장했습니다. 앱은 좋은 사례를 런타임에 검색하지 않습니다.

## 자유 실험과 저장

일시정지한 상태에서 **설정/자유 실험 → 보드 편집**을 켜세요. 클릭·드래그로 채우고 지웁니다. 드래그의 첫 셀에서 정한 동작을 이어갑니다. 키보드로는 보드 아래 x/y 입력과 셀 토글 버튼을 사용할 수 있습니다. 편집은 편집 모드에서만 작동합니다.

보드는 사용자 정의 상태라고 표시합니다. 완성 행을 입력해도 몰래 지우지 않으며, 다음 블록 고정 때 함께 삭제하는 정책을 안내합니다. 빈 보드, 시나리오 복원, 기본 가중치 복원은 각각 다릅니다.

JSON 내보내기는 현재 **실제 게임 진행 상태**의 보드·시드·가중치·설정·현재/NEXT·환경 공급 배열과 소비 위치를 저장합니다. 가상 후보나 되감기 화면은 실제 진행 상태를 바꾸지 않으므로 해당 미리보기로 내보내려면 먼저 새 분기를 만드세요. 공급을 포함한 파일은 후속 블록도 같은 순서로 이어갑니다. 공급 필드가 없는 형식도 받아 현재/NEXT 후 시드 7-bag을 새로 만듭니다. 크기 100 KB, 보드 크기·셀 값, 숫자 범위, 블록 종류, 공개 NEXT 5개, 공급과 소비 위치의 일치 여부를 검사합니다. JSON의 비공개 공급 배열은 검색 함수에 넘기지 않습니다.

가중치는 localStorage에 보관합니다. 저장을 차단한 브라우저에서도 앱은 작동합니다. 설정 변경은 150ms debounce, Worker 교체와 요청 ID 검사로 낡은 결과를 버립니다.

## 알고리즘 비교

비교를 시작할 때의 실제 보드를 공통 초기 보드로 사용합니다. 환경이 공급 배열을 만들고 각 실행은 독립적인 상태를 가집니다. 세 실행은 n번째 블록 배치에 맞춰 함께 진행합니다. 기본 상한 200블록이며 10·25·50·100·200으로 바꿀 수 있습니다.

그래프는 배치한 블록 수에 따른 실제 누적 제거 줄과 현재 구멍입니다. 화면에는 배치 수·제거 줄·구멍·최대 높이·실제 탐색 후보 수·측정 계산 시간을 표시합니다. 휴리스틱 점수는 게임 점수처럼 누적하지 않습니다.

종료 이유는 게임 오버·상한 도달·사용자 중지입니다. 죽은 실행은 마지막 보드를 유지하고 다른 실행은 계속합니다. 중지는 Worker를 종료해 실제 반응합니다. 처음 같은 상태에서 다른 첫 행동을 고른 순간의 보드와 세 행동도 볼 수 있습니다. 한 시드의 결과로 일반적인 우열을 단정하지 않습니다.

## 구조와 재생 기록

```
src/engine/       보드·평가·공급·탐색·시나리오·해설·JSON·Worker
src/hooks/        게임 상태/재생 커서/분기, 비교 동기화
src/components/   공유 SVG 보드, 설정, 후보, 해설, 재생기, 트리, 비교
tests/            엔진·고정 사례 조건·브라우저 테스트
screenshots/      실제 실행 화면
```

분석 결과와 설명 이벤트는 불변 스냅샷입니다. 재생에서 탐색을 재실행하거나 새 난수를 뽑지 않습니다. 게임 진행 상태와 설명 커서는 분리하며 같은 결정의 실제 적용은 한 번만 허용합니다. 보드 연산과 평가 함수는 DOM에 의존하지 않고 원본 보드를 수정하지 않습니다.

최근 설명 기록은 40결정까지 유지합니다. 비교 기록은 설정 상한 200블록으로 제한합니다. 트리에는 전체 계산 수와 표시 수를 따로 표시합니다. 공급 배열은 필요할 때 동일 시드의 다음 구간을 추가하며, 재생/되감기는 공급을 추가 소비하지 않습니다.

## 테스트

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:browser
```

브라우저 테스트는 현재 환경의 Microsoft Edge를 사용합니다. 다른 환경에서 Chromium을 사용할 때:

```powershell
npx.cmd playwright install chromium
$env:PLAYWRIGHT_BROWSER_CHANNEL = 'chromium'
npm.cmd run test:browser
```

검증 내역과 결과는 `VERIFICATION.md`에 기록합니다. 반응형 화면과 실제 브라우저 조작을 검증하며, 재생·되감기·초기화·동점·비공개 NEXT 경계·2수 완전열거 대조·빔의 전역 K·시나리오 조건·줄 삭제 전후·빠른 설정 변경·동일 공급 비교·JSON 검증을 포함합니다.

## 구현 범위와 한계

필수 범위는 실행 가능한 엔진, 기본 네 지표와 웰 전략 기여 시각화, 여덟 단계 재생, Greedy·2수·Beam Search, 가중치/프리셋, 여섯 기초 시나리오와 세 선수 전략 시나리오, 실제 비교 그래프, 편집과 JSON 입출력입니다.

HOLD, 공개 NEXT 밖 확률 탐색, 자동 가중치 학습, 신경망 강화학습, T-spin·벽차기·대전 공격은 구현하지 않았으며 작동하는 확장 버튼으로 표시하지 않습니다. 알고리즘 비교의 시간은 이 브라우저에서 측정한 값이라 하드웨어·브라우저 상태에 따라 달라집니다. Chrome/Edge 기반 환경을 직접 검증했으며 Safari/Firefox는 별도로 검증하지 않았습니다.
