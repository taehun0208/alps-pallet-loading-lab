# 다음 회의와 작업

아래는 이어갈 작업의 제안이다. 아직 팀의 확정 결정이나 기업과 합의한 실증 계획은 아니다.

## 팀이 먼저 정할 한 문장

“우리는 **[대상 셀의 담당자]**가 **[구체적인 상황]**에서 겪는 **[한 가지 손실]**을 줄이는 판단 기능을 만들고, **[같은 조건의 기존 방식]**과 비교해 **[대표 지표]**로 확인한다.”

현재 자료로 채울 수 있는 후보는 다음과 같다.

“우리는 순서를 보장하기 어려운 출하 적재 셀의 운영자가 관측 규격 변경에 대응할 때, 기존 적재 상태를 유지하며 다음 행동을 판단할 수 있도록 돕는다. 같은 관측값을 받은 온라인 Greedy와 비교해 정상 물량 완료, 팔레트 수, 판단시간을 확인한다.”

이 후보에서 ‘작업자 대응시간이 줄어든다’는 효과까지 주장하려면 사람을 포함한 별도 비교가 필요하다. 아직 발표의 최종 슬로건으로 확정하지 않는다.

## 회의에서 선택할 항목

| 항목 | 현재 정보 | 결정할 내용 |
| --- | --- | --- |
| 대상 | 포장 후 혼합 출하 셀이 유력한 후보 | 제조업 출하인지 물류센터인지, 담당자는 누구인지 |
| 곤란한 순간 | 순서 불확정, 규격 변경, 파손·확인된 누락 | 이번에 보여줄 사건 하나 |
| 가장 큰 손실 | 현장 자료 없음 | 정상 물량 별도 처리, 팔레트 교체, 계산 대기, 작업자 판단 중 우선순위 |
| 대표 KPI | 세 효과 가설 유지 | 한 개의 대표 지표와 함께 공개할 완료·안정성·시간 조건 |
| 비교 기준 | Greedy·기존 미래 탐색·추가 점수 실험 존재 | 같은 관측 정보와 같은 조건의 기준 정책 |
| 도입 제안 | 실제 고객과 연동 없음 | 어떤 로그를 받아 어느 범위의 비교부터 할 것인지 |

## 주최측·멘토와 접촉할 기회가 생기면 확인할 것

1. 실제로 순서가 불확정해지는 지점과 최근 막혔던 사례 하나는 무엇인가?
2. 그때 사람이 하는 일과 자동 시스템이 하는 일은 각각 무엇인가?
3. 버퍼, 동시 팔레트, 순서 변경, 이미 적재한 박스의 재배치 중 허용되는 것은 무엇인가?
4. 가장 줄이고 싶은 손실은 무엇이며, 사건 빈도와 대응시간의 대략적인 범위라도 있는가?
5. 어떤 로그와 결과가 있으면 실제 셀에서 비교할 가치가 있다고 보는가?

제공 자료 외의 답이 아직 없으므로 특정 현장이나 비용을 확정 사실처럼 쓰지 않는다. 연락이나 메시지 발송은 이번 작업에서 하지 않았다.

## 최소한의 다음 검증 순서

### 1. 같은 정상 물량의 기본 성능부터 비교

카탈로그와 수량이 같은 주문을 여러 숨겨진 입고 순서로 처리한다. 온라인 Greedy와 개선 후보에 같은 관측 정보·후보·회전·물리·로봇 제약을 적용한다. 실제 미래 순서는 환경만 소유한다.

먼저 전량 완료, 정상 물량 별도 처리, 배치 제약 준수를 확인한다. 전량 처리 정책 사이에서 팔레트 수·판단시간·모델상 작업시간을 비교한다. 시연하기 쉬운 예외 하나가 기본 미션 검증을 대신하지 않게 한다.

### 2. 한 실행에 관측 변경 사건 하나를 추가

현재 제안은 규격 변경이다. 이미 쌓인 박스는 유지하고 현재 박스 관측만 갱신한다. 계속 가능한 경우와 유효 후보를 못 찾는 경우를 구분한다. ‘계산을 못 마침’과 ‘검사한 범위에서 위치를 못 찾음’을 섞지 않는다.

정보를 갱신하지 않은 과거 계획과 비교하면 관측 갱신의 필요성을 보여줄 수 있다. 알고리즘 개선을 주장하려면 같은 갱신 정보를 받은 Greedy와도 비교해야 한다.

### 3. 사람의 불편을 줄인다는 주장을 별도 시험

작업자 지원을 핵심 가치로 선택한다면 같은 사건에서 기존 안내와 개선 안내를 보고 올바른 조치를 고르는 시간·정확도를 측정한다. 실제 현장 작업자를 확보하지 못하면 참여자의 배경과 모의 시험임을 표시한다. 알고리즘 응답시간만으로 사람의 복구시간을 대신하지 않는다.

### 4. 새 시험은 새 결과로 보존

이번에 분석한 입력과 기존 실패 사례는 개발·진단 자료로 쓸 수 있다. 다음 평가 자료는 별도로 고정하고, 결과를 본 뒤 입력·기준을 바꾸지 않는다. 기존 `results/three-directions`나 `results/v8`에 결과를 덮어쓰지 않는다.

## 효과별로 남아 있는 실험 아이디어

| 효과 | 다음 가설 | 아직 하지 않은 것 |
| --- | --- | --- |
| 팔레트 절감 | 미래 공간을 보는 점수나 후보가 실제 교체를 줄이는가 | 충분한 계산에서 선택 기준의 효과와 제한 시간에서 효과를 분리해 비교 |
| 판단 대기 감소 | 쉬운 상황은 Greedy, 필요한 상황만 추가 탐색하면 완료율을 유지하는가 | 조건부 정책 구현과 공정 주기·계산 중첩 조건 검증 |
| 변동 대응 | 특정 사건에서 적절한 조치 안내가 현행 대응보다 유용한가 | 실제 현행 절차와 사건 빈도, 작업자 비교 |

50ms 일괄 축소와 현재 미래 공간 추가 점수는 채택 근거가 없다. 이 결과를 유지하면서 새로운 가설을 시험한다.

## 발표를 구성할 때의 증거 순서

1. 실명 유사 현장의 어떤 작업이 어려웠는지 보여준다.
2. 그중 우리가 다룰 한 셀·한 상황·한 손실을 설명한다.
3. 기존 방식과 기존 상용 제품이 이미 할 수 있는 일을 인정하고, 우리의 검증 범위를 명시한다.
4. 같은 조건 비교의 결과와 실패 사례를 보여준다.
5. 시뮬레이션으로 판단 과정과 예외 처리를 시연한다.
6. 실제 입고 로그 재생 → 제어 명령 없는 병행 판단 → 제한된 실물 시험의 실증 제안을 제시한다.

현재 확보한 결과만으로는 ‘팔레트 절감 성공’이나 ‘현장 정지시간 감소’라고 발표할 수 없다. 발표 전에 확보할 증거와 지금 보여줄 수 있는 기능을 구분하는 것이 다음 작업의 핵심이다.
