# 단일 로봇팔 우선 검증 방향

작성: 2026년 10월 9일. 사용자 제안과 같은 날 코드·시뮬레이션 분석을 정리한 문서다. 팀 합의 전의 작업 방향이며, 아래 수치는 합성 입력과 공개 데이터 파생 입력의 시뮬레이션 결과다.

## 1. 정리한 방향

미션 1의 과제는 다음 한 문장이다.

> 팔레트 크기와 적재 대상 박스의 종류, 크기, 무게 및 수량은 알고 있으나 실제 투입 순서는 사전에 알 수 없는 환경에서, 박스의 안정성·적재율·작업시간을 종합적으로 고려하여 실시간 적재 패턴을 생성하는 AI 기반 Mixed Palletizing 기술을 개발함.

이에 따라 작업 순서를 다음과 같이 둔다.

1. **로봇팔 1대 + 팔레트 1개의 적재 알고리즘을 먼저 비교·검증한다.** 다음 박스가 무엇인지는 모르지만, 남은 종류별 수량은 셀 수 있다는 미션 조건을 그대로 사용한다.
2. 여러 관점에서 어떤 알고리즘이 나은지 결과를 먼저 받는다.
3. 그 뒤에 **로봇팔 4대가 하나의 컨베이어에서 병렬로 일하는 상황(우리 가정)**으로 확장한다. 여기서 중앙 오케스트레이터는 각 로봇의 작업 배정을 계산해 돕는 역할이다.
4. 로봇 대수를 바꾸는 실험은 단일 로봇 알고리즘의 최적화와 검증이 끝난 뒤에 한다.

## 2. 이 순서가 맞다고 보는 근거

**미션 문서가 단일 적재 판단을 중심으로 쓰여 있다.** 개발 목표와 기술 요구사항은 다음과 같다.

- 박스가 순차적으로 투입될 때마다 적재 위치와 자세를 결정한다.
- 미입고 박스 정보를 고려해 잔여 공간을 활용한다.
- 적재율, 작업 예상시간, 무게중심과 하중 분포, 지지면적과 붕괴 가능성, 실행 가능성으로 패턴을 점수화한다.

미션 문서에는 여러 로봇의 협업이나 배정 요구가 없다. 다중 로봇 오케스트레이터는 우리가 추가하는 확장 가정이다. [미션 원문](snapshot/research/pac2026-organizer-reference/mission-1.pdf)

**현재 중앙 오케스트레이터 결과도 단일 알고리즘의 품질에 좌우된다.** `pallet-loading-lab`의 중앙 배정 동작은 다음과 같다.

- 각 로봇이 기존 단일 셀 Greedy 점수로 뽑은 상위 2개 위치를 받는다.
- 그중 어느 로봇에 박스를 줄지를 정한다.

중앙이 위치 자체를 더 좋게 만들지는 않는다. 2026-10-09 분석에서 확인된 적재 문제는 모두 단일 셀 위치 선택에서 생긴다.

- 모든 팔레트가 (0,0) 모서리에서 시작한다.
- 팔레트 전체 무게중심이 반폭 대비 10~32% 치우친다.

배정을 정교하게 해도 이 문제는 남는다.

**R4 유휴는 배정 계산의 오류가 아니라 공급량의 한계였다.** 시드 42, 48박스를 계측했다.

| 항목 | 값 |
| --- | --- |
| R4가 쉰 시간 중 픽업 구간에 박스가 없었던 시간 | 327초 중 273초 |
| 평균 입고 간격 | 약 5초 |
| 로봇 1회 작업시간 | 약 12초 |
| 필요한 로봇 수 | 약 2.4대 |

따라서 지금 단계에서 로봇 대수와 배정을 다듬는 것은 효과를 측정하기 어렵다. 오히려 실제 손실은 R4가 박스 1개만 받고 팔레트 한 장을 출고하는 부분 팔레트였다.

## 3. 보완할 점

**① "최적"은 비교 결과로 표현한다.** 순서를 모르는 온라인 적재에서 최적해를 보장하는 방법은 없다. "정한 지표에서 비교한 후보 중 가장 나은 알고리즘"으로 결론을 낸다. 개발에 쓴 입력과 최종 평가에 쓰는 입력을 분리한다.

**② 다중 로봇으로 갈 때 '남은 수량'의 의미가 바뀐다.** 단일 로봇에서는 남은 박스 전체가 내 팔레트에 올 수 있다. 4대가 하나의 흐름을 나누면, 특정 팔레트에 어떤 박스가 올지는 오케스트레이터의 배정에 달려 있다. 단일 알고리즘의 미래 고려(잔여 수량 기반 예약·가상 순서)는 전체 잔량을 그대로 쓰면 맞지 않는다.

그래서 단일 알고리즘을 다음 형태로 만들어 두면 이후 확장에서 그대로 재사용할 수 있다.

- 입력: 현재 박스, 팔레트 상태, 이 팔레트에 올 것으로 기대하는 잔량
- 출력: 유효 후보 상위 K개와 항목별 점수

**③ 기존 비교 결과는 조건이 달라 서로 비교할 수 없다.** 같은 기준으로 다시 측정해야 한다.

| 기존 결과 | 조건 | 한계 |
| --- | --- | --- |
| `snapshot/pallet-lab/docs/62` (Python) | 24박스 × 6입력, Greedy·미래 탐색 비교 | 모두 34팔레트로 차이 없음. 다른 시뮬레이터 |
| `pallet-loading-lab/docs/packing-strategies.md` (6개 전략) | 18박스, 시드 3개 | 첫 배치 실패에서 실행을 중단해 Greedy가 4/18만 적재. 팔레트 교체 없이 적재 개수만 비교됨 |
| `pallet-loading-lab/docs/adaptive-packing.md` (A/B/C) | 12박스, 1000×1000 팔레트 | 변형·관측 오차 실험 목적. 표본이 작음 |
| `pallet-loading-lab` 중앙 배정 셀의 compact 계획기 | 4대 셀 | 단일 로봇 조건에서 따로 측정된 적 없음 |

## 4. 단일 로봇 비교 실험 설계 (제안)

### 비교 대상

| 알고리즘 | 미래 정보 사용 |
| --- | --- |
| Greedy | 사용 안 함. 기준선 |
| Greedy + 잔여 수량 평가 | 남은 종류별 수량 |
| MACS (빈 직육면체 보존) | 사용 안 함 |
| Tetris Reserved Slot | 남은 종류별 수량 |
| Dynamic Reservation | 남은 종류별 수량 |
| Lookahead (가상 순서 rollout) | 남은 수량으로 만든 가상 순서 |
| Future-Aware Hybrid | 남은 종류별 수량 |
| 4대 셀의 compact 계획기 | 현재 박스만 |

모든 알고리즘은 실제 미래 순서를 받지 않는다.

### 공통 조건

- 같은 입력, 같은 하드 제약 검사기, 같은 후보 예산과 시간 예산을 적용한다.
- 하드 제약: 관통·돌출, 지지율, 누적 하중, 무거운 박스 하부 규칙, 가반하중, 그리퍼 경로.
- 유효 후보가 없으면 실행을 중단하지 않는다. 팔레트를 교체하고 계속 적재해 **전량 처리 기준**으로 비교한다.
- 입력은 두 종류다. 합성 입력과 BED-BPP 공개 데이터 주문이며, 각각 여러 투입 순서(시드)로 실행한다.
- 개발용 시드와 평가용 시드를 나눈다. 평가 시드를 본 뒤 가중치를 바꾸지 않는다.
- 결과는 새 폴더에 저장하고 기존 결과를 덮어쓰지 않는다.

### 지표 (미션 ③과 대응)

| 미션 평가 항목 | 측정 지표 |
| --- | --- |
| 적재율·공간 활용도 | 사용 팔레트 수(마지막 부분 팔레트 포함), 정격 용적 대비 적재율, 부분 팔레트 수 |
| 무게중심·하중 분포 | 팔레트 전체 무게중심의 중심 대비 치우침(mm, 반폭 대비 %), 무게중심 높이, 4분면 질량 비율, 최대 하중 사용률 |
| 지지면적·붕괴 가능성 | 최소 지지율, 최소 국부 무게중심 여유(mm), 강체 검증 결과(선택) |
| 작업 예상시간 | 로봇 경로 시간 합계(모델값) |
| 패턴 생성 시간 | 판단 시간 p50/p95/p99 |
| 실행 가능성 | 경로 간섭·도달 거절 수, 전량 처리 여부 |

### 관점별 결과

어떤 알고리즘이 나은지는 무엇을 우선하느냐에 따라 달라진다. 하나의 합산 점수로만 순위를 매기지 않는다. 다음 관점별로 순위를 함께 낸다.

- **적재율 우선:** 팔레트 수 → 적재율 → 안정성
- **안정성 우선:** 무게중심 치우침·국부 여유 → 팔레트 수. 이 관점에서 적재율은 후순위다
- **작업시간 우선:** 경로 시간·판단 시간 → 팔레트 수
- **균형:** 서로 이기고 지는 관계를 표시한 비교

어느 관점에서도 다른 알고리즘보다 뒤지지 않는 알고리즘이 있으면 그것을 기본값으로 정한다. 그렇지 않으면 팀이 발표에서 내세울 우선순위를 정한 뒤 선택한다.

## 5. 함께 반영할 계산 보완

2026-10-09 분석에서 확인되어 단일 로봇 비교 전에 넣어야 하는 항목이다.

1. **팔레트 전체 무게중심을 판단에 반영한다.** 현재 전체 무게중심은 화면 표시용이다. 점수의 4분면 불균형 항은 최대 3점이라 사실상 영향이 없다. 운반 시 가감속을 고려한 전도 여유와 박스 간 미끄럼은 계산하지 않는다.
2. **첫 박스와 층 시작 위치의 모서리 고정을 없앤다.** 빈 팔레트의 후보 위치가 네 모서리뿐이고, 점수가 같으면 (0,0)이 선택된다. 이후 기존 박스와의 접촉 보상과 외곽 빈 공간 벌점 때문에 한쪽으로 자란다.
3. **소형 박스 바닥 금지 규칙을 다시 검토한다.** 35L 미만 박스는 바닥 배치에 −100점을 받는다. 이 때문에 기존 덩어리 위로 쌓여 한쪽이 높아진다.

1번의 허용 기준(무게중심 허용 편차, 운반 가감속)은 실제 지게차·AMR 사양에서 와야 한다. 현재 자료에 없으므로, 정하기 전까지는 가정값임을 표시하고 민감도 범위로 실험한다.

## 6. 다중 로봇 단계로 넘어가는 조건

- 단일 로봇 비교에서 기본 알고리즘과 그 근거(관점별 결과)가 정해졌다.
- 단일 알고리즘이 "상위 K개 후보 + 항목별 점수"를 반환한다.
- 셀별 기대 잔량을 어떻게 나눌지 정했다.
- 다중 로봇 실험의 비교 지표를 로봇 가동률이 아니라 팔레트 수, 부분 팔레트 수, 처리 시간으로 정했다. 입고 속도가 로봇 처리량보다 낮으면 일부 로봇이 쉬는 것은 정상이다.

## 7. 결정이 필요한 항목

| 항목 | 현재 상태 |
| --- | --- |
| 팀 합의 | 이 문서의 방향은 사용자 제안이며 팀 확정 전이다 |
| 기준 팔레트 규격 | 합성 1800×1500×1600 mm와 BED-BPP 1200×800 mm가 공존한다 |
| 무게중심·운반 허용 기준 | 자료 없음. 가정값으로 진행할지 결정 필요 |
| 판단 시간 예산 | 250ms는 우리 설정이며 주최측 요구가 아니다 |
| 발표에서 우선할 관점 | 적재율, 안정성, 작업시간 중 비교 결과를 보고 결정 |
