# 현재 증거와 미확인점

## 주최측 자료로 확인한 요구

미션 1은 박스 종류·치수·무게·수량 등은 알지만 실제 투입 순서는 모르는 상태에서 적재 위치와 방향을 결정하는 문제다. 안정성·공간 활용·실행 가능성과 재계획을 함께 다룬다. 파손·누락·규격 오인식, 로봇 도달·파지·충돌·순서와 시뮬레이션도 범위에 들어간다. [미션 PDF](snapshot/research/pac2026-organizer-reference/mission-1.pdf)

2단계 심사표는 문제의 정합성, 기술 성숙도, 현장 적용 가능성, 사업화·실증 연계, 기업 도입 의향을 각각 20점으로 제시한다. 발표는 7분, 질의응답은 3분이다. 3단계에는 같은 축과 성장 가능성을 포함한 심층 평가·합의제 순위 결정이 있으며 각 20점은 다시 적혀 있지 않다. [심사 절차 이미지](snapshot/research/pac2026-organizer-reference/judging-procedure.png)

과제별 착안점은 불확정 순서에서의 실시간 계획 논리, 안정성과 공간 효율의 균형, 재계획 속도와 시뮬레이션 검증이다. 동점 기준은 현장 적용 가능성 → 기술 성숙도 → 기업 도입 의향이다. 기업 가치 스토리는 기술 검증과 연결해야 한다. 기술 성숙도 외 80점을 모두 사업성 점수로 해석하지 않는다. [심사 착안점 이미지](snapshot/research/pac2026-organizer-reference/mission-judging.png)

250ms나 50ms는 우리 실험의 설정이다. 제공 자료가 정한 제어 응답 기한이 아니다.

## CMES의 SKU와 버퍼 설명

**있다.** CMES는 2026년 2월 공식 소개에서 7 SKU 혼합 팔레타이저를 설명하며, 컨베이어로 들어오는 박스를 비전으로 인식하고 자체 버퍼 시스템을 통해 적재 패턴을 생성한다고 밝혔다. 작업자가 사전에 박스를 분류하거나 패턴을 설정하지 않아도 된다는 설명이다. [CMES 공식 블로그, 2026-02-26](https://blog.cmesrobotics.ai/aw2026-cmes-solution)

한편 CMES 제품 페이지의 현재 검색 색인 문구는 “시퀀스 제어 시스템 없이” 최대 7개 박스 크기를 처리한다고 설명한다. 이 두 표현은 꼭 모순은 아니다. 제품 셀 내부의 버퍼로 일부 순서를 조정하면서도, 상류의 별도 시퀀서나 WMS 기반 사전 정렬은 요구하지 않을 수 있다. CMES 관계자가 올린 자료는 버퍼를 물품을 잠시 보관해 분류·순서 변경을 돕는 물리적 공간 또는 개념으로 설명한다. [CMES 제품 페이지](https://cmesrobotics.ai/en/products/palletizer), [CMES 관계자 공개 설명](https://www.linkedin.com/posts/david-callen-a8081611_application-mixed-case-palletizer-with-activity-7119402546925883392-fFUe)

공개 자료만으로는 버퍼 칸 수·용량·선택 정책·지연·실제 SKU 정의(상품 SKU와 박스 외형 규격의 관계)를 확인할 수 없다. 따라서 발표에서는 “버퍼 없이 즉시 적재”라고 하지 말고 **“최대 7종 박스 대응을 표방하며, 자체 버퍼가 있는 랜덤 혼합 팔레타이저”**라고 설명하는 편이 정확하다. 이는 우리에게 고객 문제를 다시 좁힐 근거다. 경쟁 제품도 내부 순서 조정으로 랜덤 입고에 대응한다면, 단순히 “순서를 몰라도 적재한다”는 기능은 차별점이 아니다. 우리 개선 주장은 특정 자원 조건(버퍼 용량·팔레트 수·현장 제약)에서의 비교 결과로 세워야 한다.

세부 사례 비교와 증거 한계는 [대형마트·소매 혼합 팔레타이징 조사](snapshot/research/pac2026-retail-mixed-palletizing-2026-10-09.md)를 참고한다.

**출제 의도에 대한 추론:** 이미 가능한 정적 패턴 생성에 더해, 순서와 관측 상태가 바뀌는 흐름에서 실행 가능한 다음 행동을 정하는 능력을 보려는 과제로 해석할 수 있다. 출제자에게 확인받은 설명은 아니다.

## 세 방향 최소 실험

새 합성 입력은 3개 물량 구성 × 2개 입고 순서 = 6개이며 각 24박스다. 각 정책을 2회 반복했으므로 아래 정책별 12회, 288박스다. 반복 2회를 독립 산업 사례 2개로 세지 않는다. 별도 기존 실패 진단군 2개까지 포함한 주 비교는 총 64회다.

| 정책 | 전량 완료 실행 | 정상 적재 | 팔레트 합계 | 판단·확정 검사시간 합계 | 박스별 판단시간 p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Greedy 250ms | 12/12 | 288/288 | 34 | 7.69초 | 112.2ms |
| 기존 미래 탐색 250ms | 12/12 | 288/288 | 34 | 54.21초 | 250.5ms |
| 미래 공간 추가 평가 250ms | 12/12 | 288/288 | 34 | 64.22초 | 250.6ms |
| 기존 미래 탐색 50ms | 0/12 | 240/288 | 절감 비교 불가 | 14.17초 | 50.6ms |

- 추가 평가는 팔레트를 줄이지 못했고, 기존 미래 탐색 대비 계산시간 합계가 약 18.5% 늘었다. 이번 최소 구현의 결과이며 미래 고려 전체가 무의미하다는 뜻은 아니다.
- 50ms에서는 정상 48박스가 `computation_incomplete`로 별도 처리됐다. 원시 팔레트 수 24개와 더 짧은 총시간은 전량 처리 정책의 절감 성과와 비교할 수 없다.
- 별도 기존 실패 진단군에서는 같은 정상 52개를 Greedy가 6팔레트, 기존 미래 탐색과 추가 평가가 각각 8팔레트로 처리했다. 추가 점수로 약점을 해결했다고 말할 근거가 없다.
- 기존 미래 탐색의 계산시간은 직렬 공정 추정시간의 약 1.09%였다. 로봇·입고·교체 지연 가정에 따른 모델 수치이며 실제 공장의 병목 비중은 아니다.
- 시간 측정은 계획 함수 진입부터 확정 상태·독립 기하 검사까지다. 화면 통신과 전체 제어 루프를 포함한 응답 보장값이 아니다.

상세 조건과 해석: [최소 검증 보고서](snapshot/pallet-lab/docs/62-three-direction-screening.md). 원자료: [summary.json](snapshot/pallet-lab/results/three-directions/summary.json), [runs.jsonl](snapshot/pallet-lab/results/three-directions/runs.jsonl).

## 변동 대응 기능 검증

박스 3개가 이미 놓인 상태에서 5개 조건 × 2개 정책 × 2회 = 20회를 확인했다.

| 조건 | 관측된 결과 | 아직 주장할 수 없는 것 |
| --- | --- | --- |
| 정상 대조 | 남은 정상 5개 처리 | 실제 처리량 우위 |
| 현재 박스 파손 입력 | 파손 1개 제외, 정상 4개 처리 | 카메라 파손 자동 인식 |
| 현재 박스 규격 변경 | 갱신된 규격을 반영해 정상 5개 처리 | 새 부분 재계획 최적화의 성능 우위 |
| 누락이 확인됐다는 입력 | 잔량 갱신 후 정상 4개 처리 | 누락 자동 감지 |
| 기존 배치가 팔레트 밖에 있음 | 새 배치를 실행하지 않고 중단 | 중단 이후 물리적 복구 완료 |

기존 적재 좌표·방향·제원을 유지했다. 정상·규격 변경·누락 조건의 첫 유효 배치 승인까지 시간은 Greedy 약 2.0~2.1ms, 기존 미래 탐색 약 9.7~17.5ms였다. **로봇이 배치를 끝낸 시간이나 실제 작업자 복구시간은 아니다.** 파손 조건의 약 4초는 대부분 가정한 격리·다음 입고 시간이다.

원자료 검사 기록은 주 비교 64회, 변동 검증 20회, 반출 팔레트 168개, 상태 사건 6,206개의 수량·ID 보존과 범위 내 배치 검사를 통과했다. 당시 기존 공정 테스트 20개도 통과했다. 실물 안전 인증이나 전체 시스템 검증을 의미하지 않는다. [검증 기록](snapshot/pallet-lab/results/three-directions/verification.json)

## 그 이전 v8 검증과 구분

v8 자료는 구현 효율화 전후의 일부 입력군에서 평균 계산시간 약 6% 감소와 같은 적재 결과를 기록한다. 39개 조건을 정책·전후·반복으로 실행한 468회 기록이다. 이를 Greedy 대비 일반적인 적재 성능 우위나 현장 처리량 6% 향상으로 발표하지 않는다. [v8 결과 문서](snapshot/pallet-lab/docs/56-award-evidence-results.md)

## 다음에 필요한 증거

1. 어느 고객의 어느 셀인지, 실제 순서 불확정 원인과 제약을 확인해야 한다.
2. 팔레트 교체·판단 대기·예외 대응 중 실제로 큰 손실이 무엇인지 확인해야 한다.
3. 같은 관측값을 받은 온라인 Greedy보다 개선안이 나은지 새 입력으로 비교해야 한다.
4. 작업자 부담을 주장하려면 사람의 조치 정확도·판단시간 등을 따로 측정해야 한다.
5. 경제성을 계산하려면 사건 빈도·현행 대응시간·설비 비용·작업주기가 필요하다.

현재는 현장 인터뷰·실제 입고 로그·실물 로봇·센서·제어기 연동·구매 의향 검증이 없다. 자료가 없는 항목을 발표용 가상 성과로 채우지 않는다.
