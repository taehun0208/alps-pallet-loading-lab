# 대화 흐름과 결정 상태

이 문서는 현재 대화와 보존된 문서에 근거한 요약이다. 과거 모든 대화의 원문이나 정확한 발언 시각을 복원한 것은 아니다.

## 최신 사용자 결정 — 중량 순서 제약 (2026-10-09)

- **가벼운 물체 위에 무거운 물체를 놓는다는 이유만으로 배치를 금지하지 않는다.** ‘무거운 물체는 반드시 아래’라는 일률적인 규칙은 솔루션의 기본 제약으로 삼지 않는다.
- 물체 자체 중량과 그 물체가 견딜 수 있는 허용하중은 다르다. 지지·접촉 상태, 상부에서 전달되는 하중, 알려진 압축강도·허용하중, 제품별 취급 조건으로 판단한다. 이 결정은 모든 하중·안정성 검사를 없애라는 의미가 아니다.
- 강도·허용하중 자료가 없으면 해당 검증은 미검증으로 표시한다. 상대 중량만으로 안전 또는 위험을 단정하지 않는다.
- 후속 구현에서는 `heavyRule: 'each'` / `'share'` 등의 중량 순서 규칙과 실제 지지·허용하중 검사를 구분한다. 범용 조건의 기본값 변경과 회귀 검증은 후속 작업이며, 이번 메모리 업데이트에서는 코드·진행 중 실험을 변경하지 않았다.
- 과거 문서나 실험의 ‘무거운 물체 아래’ 가정보다 이 사용자 결정을 우선한다. 기존 결과는 당시 제약 조건의 결과로 보존한다.

## 사용자가 일관되게 강조한 목표

알고리즘 종류나 시뮬레이션의 정교함보다 먼저, 기업이 선택할 가치가 있는 문제와 지표를 정해야 한다. Greedy와 휴리스틱은 이미 널리 쓰이므로 어떤 알고리즘을 사용했다는 설명만으로 충분하지 않다. 현장에서 발생하는 불편을 특정하고, 이를 개선하려는 가설과 실험을 연결한 뒤 시뮬레이션으로 보여주는 스토리가 필요하다.

팀원의 의견을 반영해 방향을 정해야 하며, 해커톤에서 모든 문제를 해결하려고 범위를 넓히지 않는다. 사용자는 시뮬레이션과 실제 동작의 고도화보다 고객 문제·기업 가치·어필 지표의 정리를 먼저 하자는 우선순위를 제시했다.

## 논의가 진행된 순서

| 단계 | 사용자 요청 또는 문제 제기 | 현재 남은 내용 |
| --- | --- | --- |
| 1 | 알고리즘 개선에 앞서 기업 가치와 어필 지표를 정하자 | 기술 구현 → 고객 가치라는 단순 추정을 피하고, 문제에서 시작하기로 함 |
| 2 | 팔레트를 줄이거나 미래 박스를 빨리 고려하는 등 세 방향을 비교하자 | 팔레트 절감·판단 대기 감소·변동 대응이라는 효과 가설 |
| 3 | 세 방향을 모두 열어두고 최소한 검증하자 | 별도 실험 폴더에서 주 비교 64회와 변동 기능 검증 20회 수행 |
| 4 | 지금은 누구를 위한 솔루션인지 불분명하며 시뮬레이션에 치우쳐 있다 | 사용자·문제·기존 대응·개선 증거·시연의 순서로 다시 설명할 필요 |
| 5 | 주최측 자료와 심사표를 바탕으로 실제 공장 문제와 출제 배경을 조사하자 | 공식 제품·운영기업·구축 사례·기술 매뉴얼·논문을 조사해 저장 |
| 6 | 제공한 자료 외에 특정 현장 사례를 들은 것은 없다 | 특정 HD현대로보틱스 고객의 불편이나 출제자의 실제 의도는 미확인 |
| 7 | 전체 내역을 이어갈 수 있게 폴더를 만들자 | 이 인수인계 폴더 생성. 새 기능 개발이나 방향 확정은 수행하지 않음 |

## 혼동하면 안 되는 두 종류의 ‘세 방향’

초기 세 방향은 **개선 효과**를 비교한 것이다.

1. 같은 정상 물량을 더 적은 팔레트로 처리한다.
2. 판단 계산 때문에 생기는 대기를 줄인다.
3. 파손·규격 변경·확인된 누락 같은 변동 후 작업을 이어간다.

현장 조사 후 정리한 세 후보는 **누구의 어떤 작업을 해결할지**를 비교한 것이다.

| 고객 문제 후보 | 연결될 수 있는 효과 | 현재 상태 |
| --- | --- | --- |
| A. 순서를 보장하기 어려운 출하 적재 | 팔레트 수, 정상 물량 처리, 판단시간 | 미션과 실사례 연결이 가장 직접적이라는 조사상 제안 |
| B. 작업 중 관측 규격이 달라질 때 재판단 | 재판단 시간, 잘못된 실행 방지, 작업자 조치 | A 안의 구체적인 시연 사건으로 제안 |
| C. 도입 전 현장 조건 검증 | 통합 엔지니어의 비교·검토 부담 | 직접 고객 불편 증거가 약함. 실증 방법으로 활용 제안 |

고객 문제 후보 A/B/C가 초기 세 효과 가설을 대체하거나 세 개 제품으로 확정된 것은 아니다. 최신 제안은 A의 한 셀을 대상으로 B의 사건 하나를 보여주고, 그 안에서 어떤 효과가 확인되는지 측정하자는 것이다.

## 확정·제안·미확정

| 구분 | 내용 |
| --- | --- |
| 사용자 의도 확인 | 기업에 필요한 문제를 좁히고, 팀 의견을 반영해 최종 방향을 정한다. 세 효과 가설을 열어둔다. |
| 작업으로 완료 | 기존 시뮬레이터·문서 보존, 최소 실험, 산업 사례 조사, 주최측 자료 보존, 이번 인수인계 정리 |
| 연구 결과에 따른 제안 | 한 출하 셀 + 규격 변경 사건 하나. 기본 온라인 적재 비교 후 예외를 추가하는 시연 |
| 최종 결정 전 | 대상 고객, 가장 비싼 손실, 대표 KPI, 선택할 개선 정책, 발표의 핵심 약속 |
| 아직 증명하지 못함 | Greedy 대비 일반적인 적재 우위, 현장 정지시간·작업자 개입 감소, 실제 ROI, 기업의 구매 의향 |

## 앞으로 유지할 판단 원칙

- 기능이 동작했다는 결과와 고객 비용이 줄었다는 결과를 구분한다.
- 일부 정상 물량을 처리하지 않고 팔레트 수나 시간이 줄어든 것을 개선으로 계산하지 않는다.
- 계획기에는 실제 미래 입고 순서를 주지 않는다. 알고 있는 종류·수량으로 만든 가상 순서와 실제 관측을 구분한다.
- 비교 정책에는 같은 관측 정보, 제약, 물량과 시간 조건을 준다.
- 복잡한 방식이 Greedy보다 항상 낫다고 전제하지 않는다. 단순 기준도 유지한다.
- 공개 자료에서 추론한 출제 배경을 출제자의 발언처럼 적지 않는다.
- 시연을 위해 만든 입력과 실제 현장 로그를 구분한다. 이미 분석한 실패 사례는 새 평가 자료가 아니다.
- 팀의 최종 결정 전까지 조사자의 추천을 확정된 제품 방향으로 표현하지 않는다.
