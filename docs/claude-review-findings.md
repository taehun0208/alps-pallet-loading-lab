# Claude API 검토와 반영

개발 중 Anthropic Messages API의 `claude-opus-5-5`를 사용했습니다. 비밀키는 저장소 밖 로컬 `.env`에서 읽었으며, 프런트엔드와 실행 제어 루프에서는 외부 LLM을 호출하지 않습니다.

초기 설계 검토는 출력 한도에 도달했지만 최종 텍스트 일부를 받았습니다. 첫 전체 코드 검토는 한도까지 내부 계산만 반환하여 최종 검토로 인정하지 않았습니다. 이후 집중 검토는 `end_turn`으로 완료했고, 사용자 요청에 따라 출력 예산을 128,000으로 올린 스트리밍 전체 검토도 `end_turn`으로 완료했습니다. [호출 결과 메타데이터](benchmarks/claude-review-log.json)는 모델·사용량·완료 상태만 담습니다.

검토 의견은 그대로 채택하지 않고 코드와 회귀 테스트로 확인했습니다.

- 의도적 보류와 제한된 탐색의 후보 없음 판정을 분리했습니다. 보류는 팔레트 교체 근거에 누적하지 않습니다.
- 다른 셀에 배정되더라도 현재 셀의 후보 없음 기록을 유지하고, 예약 전에 기록합니다.
- 최상위 위치의 집기 검증 실패 시 검사한 두 번째 위치를 시도합니다.
- 집기 시간·경로 예약 등 실행 시점 실패는 팔레트 적재 불가로 기록하지 않고 짧은 간격으로 재검토합니다.
- 집기 시점 좌표와 재검증 접근시간을 확인하고 실제 조립한 TCP 경로의 이동거리를 다시 계산합니다.
- 전체 팔레트 버전·상태가 바뀌면 계획을 폐기하는 보수적인 검사는 유지했습니다. 이 때문에 병렬 동작 중 불필요한 재계산이 생길 수 있습니다.

집중 검토는 `defer`에 후보가 들어오면 실행될 수 있다는 경계 조건을 지적했습니다. 기존 생성 경로는 보류에 빈 후보를 주므로 관측된 실행 버그로 주장하지 않았으며, 실행 경계에서 명시적으로 보류를 차단하는 방어 검사를 추가했습니다.

별도 에이전트 리뷰에서는 박스별 탐욕 배정이 전체 작업 수를 줄이는 반례와 하류 임시 배정이 현재 로봇 슬롯을 점유하는 문제를 발견했습니다. 16개 로봇 비트마스크 DP와 예약을 사용하지 않는 하류 의도로 수정했습니다.

로봇 활용 편중에 대한 추가 검토도 `end_turn`으로 완료했습니다. 낮은 투입 부하에서 R4가 적게 일하는 현상을 처리량 오류와 구분하라는 의견을 채택했습니다. 작업 분산은 선택형 목표로 두고 기본 처리 효율 정책은 유지합니다. 두 재현에서 분산 목표는 R4의 작업을 늘렸지만 완료시간과 사용 팔레트 수도 늘었습니다.

남은 모델 한계: 하류 배정은 예약이 아닌 임시 의도이므로 여러 박스가 같은 하류 로봇을 기대할 수 있고 도착 시 재계산합니다. 후속 수용 비율은 해당 로봇에 현재 들어가는 관측 표본의 보존율이며 전체 공장의 수용률이 아닙니다. 바쁜 로봇의 미래 가용 시각을 예측하는 일정계획은 아직 구현하지 않았습니다.
