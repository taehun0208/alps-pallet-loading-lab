# Packaging-aware Mixed Palletizing

이 문서는 `src/pallet/packaging`의 실행 코드와 공통 적재 제약 검사를 설명한다. 기존 4대 공장, 전달대 순환, AMR 반출, 적재 기록 및 기존 실험 화면을 유지한다.

## 1. 문제 정의

현재 입고 한 박스를 고정된 팔레트에 배치한다. 미입고 박스의 종류별 총수량·규격·포장 조건을 알고 있으나 실제 다음 순서는 알지 못한다. 이미 확정한 박스는 이동하지 않는다. 단일 팔레트에 들어가지 못한 박스는 미적재 기록으로 남기고 다음 입고를 처리한다. 4대 공장 모드는 별도로 도착한 전체 재고를 셀별로 나누고 기존 전달 규칙을 사용한다.

## 2. 3D Bin Packing과 차이

부피 최소화 외에 포장 방향, 상부 허용하중, 접촉면적, 무게중심, 공구 접근, 가반하중과 미입고 재고의 공간 기회를 제약 또는 평가 항목으로 사용한다. 크기는 mm 단위 연속 치수이며 맞물리는 격자를 가정하지 않는다. 학습 모델, 외부 AI 호출, 서버 추론 없이 TypeScript/Web Worker에서 계산한다.

## 3. Packaging-aware constraint

`spec.ts`의 `BoxSpec`은 요청한 포장 종류·회전·적층·하중·지지·파손 민감도·CoG·파지 면·출처와 실험 수량을 가진다. 기존 `BoxType`, `Observation`, `Placement`에 선택적인 `packaging`을 붙여 이전 JSON을 그대로 지원한다. 공통 `candidateSet`, `inspectConstraints`, 입고 환경, 가상 관측, 재질 평가도 이 정보를 전달한다.

회전은 XYZ=0, YXZ=90, XZY=whd, ZXY=hwd, ZYX=hdw, YZX=dhw로 대응한다. keepUpright는 XYZ/YXZ만 허용한다. 금지 자세는 후보 생성 전에 제외하며, 외부에서 주입된 금지 자세도 하드 검사에서 거부한다. 치수가 같은 자세라도 비대칭 CoG와 파지 면이 다를 수 있어 포장 계획기는 임의로 병합하지 않는다. `maxStackLayers=1`은 해당 박스 자체를 포함한 최대 수직 경로가 한 층이라는 뜻이다.

## 4. Extreme Point Candidate Generation

기존 `frontierOrigins`를 재사용한다. 팔레트 모서리, 기존 박스의 앞뒤 변, 서로 다른 박스에서 투영한 x/y 교차점을 생성하고 해당 위치의 가장 높은 충돌면에 내려놓는다. 논문의 완전한 EP 구현이나 모든 연속 위치의 전수 탐색은 아니다. 공중에 떠 있는 임의 z는 만들지 않는다.

높이·자세·사분면별로 순환 표집하여 기본 최대 96개를 자세히 검사한다. 생성 수와 검사 수를 구분한다. ‘회전 사전 제외 4/6 자세’는 후보 4개를 뜻하지 않는다. 경계·충돌·하중·지지·로봇 탈락은 중복 집계다. 하드 검사에서 탈락한 후보의 `score=null`, `terms={}`를 유지한다.

## 5. Load Propagation

포장 박스에서 `share = contact.area / sum(contact.area)`로 다시 계산한다. 높은 박스부터 `(자중 + 누적 상부 하중) × share`를 각 받침에 더한다. `calculateLoads`와 확정 프레임의 `loadAbove`가 이 면적 모델을 사용한다. 위 적재 금지, 최대 누적 하중, 최대 적층 수 모두 실제 후보를 탈락시킨다. `maxTopLoad`는 입력된 허용값 그대로이며 기존 재질 데모의 안전계수를 이중으로 나누지 않는다. 80%는 경고, 100% 초과는 거부한다.

면적 비례 하중은 균일 접촉압을 가정한 근사다. 기존 정적 반력 솔버는 별도로 회전된 실제 CoG에서 비음수 반력과 모멘트 평형이 가능한지 검사한다. 비대칭 CoG에서 면적 분배와 실제 반력 분배가 동일하다는 뜻은 아니다. 포장 변형, 국부 압력, 압축 강도 시험, 마찰 변화는 이 모델로 검증되지 않는다. 포장 속성이 없는 이전 박스는 기존 반력 비율에 의한 하중 경로를 유지한다.

## 6. Support Ratio / CoG

바닥 접촉면적 합 / 박스 바닥면적을 해당 박스의 `minSupportRatio`와 비교한다. 접촉 박스가 겹치지 않는 유효 상태에서는 접촉면적도 중복되지 않는다. 전역 비율보다 BoxSpec 값이 우선한다. Carton .75, fragile .85, wooden case .70은 조정 가능한 실험용 기본값이다.

CoG는 원래 박스의 최소 모서리에서 잰 mm 좌표다. 회전은 기하학적 중심 기준 offset을 실제 자세 변환한 뒤 새 최소 모서리에 더한다. 전체 무게중심은 질량 가중 평균이며 기존 3D 금색 마커와 중심 편차 평가에 연결된다. 받침 다각형 내 CoG, 누적 모멘트 평형과 설정한 측방 여유도 검사한다.

## 7. Future-aware Monte Carlo

계획 입력은 `{pallet, types, constraints, placements, current, remaining}`으로 투영한다. 실제 입고 시드, 큐와 이벤트는 계획기에 전달하지 않는다. 계획 시드와 단계로 만든 별도 RNG가 남은 개수에 비례하여 중복 제거 추첨한다. 20 / 50 / 100개 가상 순서, 깊이 3 / 5 / 10을 선택할 수 있다. 모든 루트 후보에 같은 가상 순서를 사용한다.

비용을 제한하기 위해 즉시 점수 상위 기본 3개 루트만 미래 탐색한다. 가상 순서를 평균내기 전에 실제 지원·하중·방향·파지·도달 제약으로 후속 후보를 검사한다. 미탐색 꼬리는 성공으로 가정하지 않고 실패 위험에 포함한다.

## 8. Beam Search

각 가상 순서에서 각 깊이의 상태를 기본 상위 10개로 제한한다. 가상 후속은 박스 변과 팔레트 모서리의 O(n)개 위치에서 높이를 계산하는 축약 EP를 사용한다. 루트의 모든 교차 투영을 후속마다 다시 만들지 않는다. 후속 상태당 최대 8개의 위치를 검사하여 최대 3개 자식 상태를 확장한다. 사용자는 beam 1~30, 루트 후보 1~8, 깊이와 샘플 수를 바꿀 수 있다. 기본 전체 미래 검사 예산 12,000회를 루트/샘플/남은 깊이에 배분한다. 접두 상태 캐시로 같은 가상 상태의 계산을 재사용한다. 시간 기반 중단으로 결과가 바뀌지 않도록 결정적 검사 개수 예산을 사용한다.

실제 샘플 수, 도달 깊이 최소·최대, 후보 검사 수, 캐시 횟수, 예산 적용 여부를 표시한다. 요청한 깊이를 모두 탐색하지 못했다면 그대로 표시한다. 전역 최적해를 보장하지 않는다.

## 9. Robust Optimization / 점수

미래 성공 수 + 추가 용적 보상 − 실패 수를 요청한 깊이로 정규화한다. 하위 10% 표본 평균을 `worst`로 정의한다. Robust는 `0.7 mean + 0.3 worst`, 일반 Future는 mean이다. 이 값에 미래 가중치를 곱하고 별도 실패 위험 비용을 차감한다. 100점은 백분위나 성공 확률이 아니라 정규화 점수 표시다.

조정 가능한 항목은 현재 공간 효율, 지지, 하중 여유, CoG, 평탄도, 미래 큰 공간, 접근 여유, 높이, 파손 위험, 로봇 시간, 미래 실패, 미래 점수다. 음수 기여도까지 더한 값이 TOTAL과 일치한다. HIGH 포장에는 상부 하중 위험과 후속 박스에 묻힐 가능성 비용을 부과하고, 충격 민감 박스는 이동/회전 시간을 1.35배로 가정한다. 높이 비용에는 무게/가반하중도 반영하여 중량물을 낮게 선호한다.

큰 공간 보존은 바닥 장애물로 최대 빈 직사각형을 분할하고 남은 종류 중 큰 3종의 필요 수량을 고려한다. 튼튼하고 노출된 상면도 한 개의 미래 기회로 인정한다. 이것은 저렴한 기하학적 탐색 지표이며 그 자체가 미래 배치의 물리적 증명은 아니다. 실제 미래 탐색에서는 공통 하드 검사를 다시 수행한다. 즉시 용적 점수와 미래 공간 점수를 별도 표시한다.

## 10. Robot Constraint

`packaging/robot.ts`의 `reachability`는 교체 가능한 3D 구형 작업공간 모델이다. 로봇 base xyz, minReach/maxReach, 접근 거리를 사용한다. TCP 경로의 최대 반경은 끝점, 최소 반경은 각 선분에서 base에 가장 가까운 점으로 검사한다.

파지 면은 박스 회전에 따라 변환한다. 아래를 향한 면은 사용할 수 없다. 허용 TOP/FRONT/BACK/LEFT/RIGHT 면 중 접근 corridor가 빈 면을 고르고, 공구 두께·폭과 운반 박스의 sweep를 기존 박스와 검사한다. 회전 이동 구간은 보수적인 박스 외접구를 사용한다. 이동·파지·회전·복귀 시간이 결과에 들어간다. 전체 로봇 링크 연속 충돌이나 제조사 6축 IK 검증은 아니다.

새 단일 팔레트 실험의 기본 가반 100 kg, 최대 도달 3.5 m는 A–H 비교를 위한 **Simulation Assumption**이다. 기존 공장으로 보내면 선택한 공장 문맥의 35 kg / 협동로봇 15 kg 제한을 그대로 적용하므로 40/70 kg 박스는 적재되지 않을 수 있다. 공장의 장식 시설물은 충돌 장애물 데이터가 아니다.

## 11. Replanning

파손·누락·잘못된 치수·잘못된 무게·종류 변경은 현재 입고 관측을 바꾸며 확정 팔레트를 초기화하지 않는다. 치수 변경 시 CoG의 상대 위치를 보존하여 새로운 mm 위치로 환산한다. 알 수 없는 미래 관측을 임의로 바꾸지 않는다. 미입고 잔량은 실제 수정된 관측 목록에서 다시 산출한다.

`REPLANNING…` 후 변경 전후 후보 위치·자세·점수를 표시한다. Worker 응답은 request ID로 구분하고 이전 Worker를 종료한다. 확정 직전 관측·팔레트·제약 signature와 하드 제약을 다시 확인하여 오래된 계획을 적용하지 않는다.

## 12. 사용법

1. 상단 **포장 제약 실험** 또는 `/?palletView=packaging#pallet`을 연다.
2. A–H 예제와 기본 Robust 계획을 사용하거나 BoxSpec JSON을 편집해 새 실험에 적용한다.
3. ‘한 박스 확정’ 또는 ‘자동 적재’로 단계를 진행한다. ‘배치 기록’ 슬라이더로 과거 프레임을 확인한다.
4. ‘후보 Debug’와 후보 목록을 통해 통과/탈락 위치를 선택한다. 3D에는 앞 24개 및 선택 후보를 표시한다.
5. 적재된 박스를 클릭하면 오른쪽에 그 박스의 포장 정보와 누적 하중을 표시한다.
6. 현재 입고 이벤트로 재계획하거나 같은 시드로 재실행한다. 결과 JSON에는 관측, 결정, 후보 이유, 프레임과 설정이 들어간다.
7. ‘4대 공장에 재고 적용’은 기존 공장 재고를 새 입력으로 시작한다. 포장 속성은 공통 후보·제약 검사에서 계속 사용된다. 4대의 순환·반출 정책은 기존 height-fill 정책을 사용한다.

## 13. 비교 / 검증

First Fit(유효 후보 순서), Greedy EP(현재 평가), Tetris heuristic(평탄도·낮은 높이 강조), Future(mean), Robust Future(mean+하위 꼬리)를 같은 실제 순서와 제약으로 실행한다. 표에서 용적, 적재·실패, 평균 지지, 최대 하중 사용률, CoG 편차, 평균 계산 시간, 추정 로봇 시간과 재계획 횟수를 비교한다. 정책 버튼은 해당 결과의 3D 프레임을 연다.

`tests/pallet-packaging.test.ts`는 최소 요구 10종을 포함한다. `tests/pallet-packaging-benchmark.test.ts`는 A–H 22개 동일 입력을 5정책으로 실행하여 `docs/packaging-benchmark.json`에 실측을 저장한다. 낮은 장벽에서 XL가 들어갈 직사각형을 파괴하는 별도 입력에서 Future가 Greedy보다 공간을 보존하는지도 검증한다. 특정 예제 개선을 모든 입력에서의 우월성으로 해석하지 않는다.

Greedy 50 ms/box, Future 1초/box는 목표다. 브라우저 첫 실행, 기기 성능, 박스 수, 샘플 수에 따라 초과할 수 있다. UI는 현재 기기의 측정값과 실제 탐색 범위를 보여준다. Worker는 렌더링을 막지 않지만 계산 총량을 없애지는 않는다.

## 14. Reference Case / Simulation Assumption

A의 400×300×200 mm, 총중량 1 kg, CARTON BOX는 [HD Hyundai Marine Solution 관련 Packing List 공개 재게시본](https://www.scribd.com/document/1023542427/CIPL-MK-24-K-123-IMKBS007891K02)의 개별 출하 사례를 참고했다. 제3자 재게시본이며 제조사 공식 규격 페이지나 일반 제품 표준이 아니다. 문서의 내용물 36EA는 한 carton 안의 링 수량이다. 실험 수량 4박스 및 강도·지지·회전·CoG·파지 가정은 해당 문서에서 확인된 값이 아니다.

B–H의 제품군 명칭, 치수, 질량, 수량, 포장재와 모든 취급/강도 조건은 사용자 제공 **Simulation Assumption**이다. 전장품·선박 예비품의 실제 포장 규격이라고 표시하지 않는다. 모든 preset 값은 편집할 수 있다.
