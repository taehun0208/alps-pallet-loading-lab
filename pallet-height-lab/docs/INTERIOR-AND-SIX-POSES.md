# 내부 빈 공간과 6자세 혼합 적재 · 2026-10-05

## 변경 목적

서로 다른 박스를 가장자리에 붙여 놓다가 중앙에 좁고 긴 빈 공간을 남기던 문제를 보완했다. 입력 박스 치수를 맞춰 깎거나 가상의 지지판을 추가하지 않는다. 전체 재고를 꺼낼 수 있는 연구 모드에서는 박스 ID·자세·위치를 함께 선택한다. 순차 투입 모드에서는 현재 도착 박스의 자세와 위치만 선택하며 실제 미래 순서를 읽지 않는다.

[바로 실행](http://127.0.0.1:5173/?palletDemo=spatial#pallet). 기존 `?palletDemo=compact`와 `high-stack` 주소도 같은 새 예제로 연결한다. `legacy-high-stack`은 과거 중앙 기둥 검증용이다.

## 실제 변경한 알고리즘

1. **서로 다른 최대 6자세**: `(w,d,h)`, `(d,w,h)`, `(w,h,d)`, `(h,w,d)`, `(h,d,w)`, `(d,h,w)`를 박스별 허용 목록 안에서 검사한다. 밑 박스와 같은 방향이어야 한다는 제한은 없다. 바닥 90° 교차 배치와 옆면 세우기 모두 가능하다. `upright`는 원래 높이축을 유지하고, `no-top-load`는 자세에 관계없이 위 적재를 금지한다.
2. **내부 빈 부피**: 모든 박스 바닥/윗면 높이로 구간을 나눈다. 각 높이 구간에서 실제 박스들의 외곽 사각형 부피를 더하고 점유 부피를 뺀다. 좁은 틈도 누락하지 않는 연속 치수 계산이다. 열린 홈도 포함하므로 밀폐된 공동만의 부피나 안전성 확률은 아니다.
3. **후보 생성과 평가를 함께 수정**: 유한 후보 예산을 배분할 때 같은 높이에서 외곽 폭이 작아지는 위치를 앞에 둔다. 팔레트 외벽에 붙이는 보너스는 없애고 실제 이웃 박스 접촉은 유지한다. 조밀성 점수에 `-250 × 내부 빈 부피 증가 / 팔레트 허용 부피`를 추가한다. 낮은 실현 가능한 위치, 넓은 받침, 유효 부피, 묻히는 틈, 잔량 기회를 함께 평가한다.
4. **남은 박스 재검사**: 최종 후보들에 대해 배치 전후 잔량의 실제 제약 통과 위치를 비교한다. 6자세는 현재 후보와 잔량·후속 탐색에 공통 적용한다. 옆면으로 세울 때 바뀐 높이도 후속 공간 평가에 반영한다. 무한 탐색이나 최적해 보장은 아니다.
5. **자세별 안전 검사**: 변환된 실치수로 경계·관통·높이·지지율·균등 질량 중심·정적 반력·모든 아랫단의 누적 하중·전도 여유를 재계산한다. 방향별 강도 입력이 있으면 세운 원래 축의 강도를 사용한다. 같은 치수라도 축별 강도가 다르면 해당 자세들을 합치지 않는다.

빈 공간의 벌점은 배치 선호도다. 옆면 접촉을 접착이나 지지면으로 간주하지 않는다. 모든 방향에서 동일한 안전 검사를 통과해야 확정한다.

## 로봇 근사와 3D 표현

이상적 적재 모드는 그리퍼 치수·경로 제약을 사용하지 않는다. 그리퍼 모드는 원래 윗면 파지를 고정한 채 안전 높이에서 회전한다. 따라서 세운 박스의 TCP는 옆면에 있고, 놓은 뒤 해당 면의 바깥으로 이탈한다. 회전 구간은 TCP 기준 외접 구의 상자로, 직선 이동은 회전된 공구/박스의 스윕으로 작업공간과 장애물을 보수적으로 검사한다. 회전 시간도 최대 180° 기준의 보수적 근사다.

3D 이동 박스와 공구는 같은 자세 변환으로 회전한다. 확정 상자는 이미 변환된 치수로 표시하며 이중 회전하지 않는다. 저장 JSON, 과거 프레임, 패턴 재검사와 강체 복제에도 동일한 배치를 사용한다. 실제 흡착 유지력, 재파지, 관절 IK, 전체 링크, 종이 압축 변형은 검증하지 않는다.

`maxLoadByAxis: {w, d, h}`는 **해당 원래 축이 수직일 때의 상부 하중 기준 kg**다. 비어 있는 축은 공통 `maxLoadKg` 또는 기존 재질 예제값을 사용한다. 즉 미입력 방향도 같은 강도라는 가정이며, 세우기만으로 박스가 더 튼튼해지도록 보정하지 않는다. 강도 보정과 여유 계수는 기존처럼 적용한다.

## 같은 입력으로 먼저 실행한 결과

비교 원본은 기존 `pallet-compact-measurements.json`을 그대로 보존했다. 박스 치수·수량·무게·재질·하중·팔레트·로봇 및 강체 검사 설정은 같고, 새 실행은 허용 자세와 공간 평가만 확장했다. 원자료는 프로젝트의 `docs/pallet-interior-measurements.json`이다.

|---|---:|---:|---:|---:|---:|---|
| 20261004 · 30개 | 17 → 16 | 1459 → 1325 | 0.427 → 0.277 | 66.4 → 72.1% | 4 | 통과 |
| 7919 · 24개 | 12 → 15 | 641 → 709 | 0.227 → 0.143 | 63.6 → 75.5% | 4 | 통과 |
| 20261005 · 30개 | 16 → 19 | 1202 → 896 | 0.268 → 0.191 | 67.4 → 75.4% | 9 | 통과 |

기본 입력은 내부 빈 부피가 약 **35.1% 감소**했으나 적재 수는 한 개, 적재 부피는 **0.845→0.716m³**로 줄었다. 이 개선을 모든 입력의 적재량 증가로 해석하지 않는다. 6자세를 끄고 공간 평가만 바꾼 중간 실험은 16개·1115mm·내부 빈 부피 0.314m³·채움 64.7%였다. 좁은 곳에 세워 넣는 자세가 추가된 최종 결과의 채움은 72.1%다.

세 번째 입력의 직전 강체 검사는 이동 초과였지만 새 결과는 통과했다. 강체 검사 설정은 3초, dt 1/120초, 솔버 12회, 접촉 120Hz, 이동 허용 5mm, 회전 허용 3°로 유지했다. 이것은 해당 수치 모델에서의 결과다.

반복 8종 48개 브라우저 예제도 새 6자세로 실행했다. 26개·1005mm이며 선택한 자세에 따라 받침 관계가 달라진다. 이 예제가 매번 여러 받침에 걸치도록 강제하지 않는다. 다중 받침의 유효성은 별도 엔진 회귀에서 검사한다.

## 사용법

- **옆면 세우기 허용 · 새 실행**: 기존 재고와 제약을 유지하고, 위아래 유지 박스를 제외한 자세를 확장해 새 실행을 시작한다. 과거 실행은 보관한다.
- **현재 재고 모아서 실행**: 이미 허용된 자세를 존중해 같은 재고를 다시 계획한다.
- **랜덤 혼합 재고 실행**: 치수·재질 등이 다른 새 재고를 생성한다. 현재 실험에서 세우기를 허용했다면 새 재고에도 적용한다.
- **팔레트 · 박스 편집**: 박스마다 허용 자세 6개와 위아래 유지·상부 적재 금지, 방향별 허용 하중을 편집한다.
- **내부 공간과 박스 자세**: 현재 프레임의 내부 빈 부피, 채움 비율, 세운 박스와 실제 치수를 확인한다.

## 검증 사례

- 중앙의 100×200mm 틈에 눕혀서는 들어가지 않는 400×190×90mm 상자를 세워 넣는 사례: 기본 배치·Greedy·Rollout 모두 바닥 틈 선택.
- 수평 받침 위 교차·세움 자세, 높이 초과, 방향별 강도 초과, 위아래 유지 제한, 그리퍼 옆면 이탈 충돌 검출.
- 6자세 치수와 역변환, Three.js 회전과 기하학 변환의 일치, 정육면체의 방향별 강도 보존.
- 브라우저에서 세워야 들어가는 상자의 실제 회전·변환 치수·JSON·프레임 복원 일치. 위아래 유지로 바꾸면 배치 거부.
- 같은 기본 랜덤 결과의 엔진·브라우저 수량/높이 일치, 강체 복제 최대 이동 약 0.709mm. 320/1440px 화면 가로 넘침 검사.
