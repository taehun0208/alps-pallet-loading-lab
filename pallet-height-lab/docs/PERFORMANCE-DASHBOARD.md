# 성능 대시보드 · 2026-10-09

실행: `/?palletView=adaptive#pallet`. 기존 **변형·관측 실험** 화면을 확장했다. 4대 컨베이어 화면, 알고리즘 A/B/C, 충돌·하중 검사기와 실행 판단은 유지한다. 로봇 수/종류 변경 및 GLA/GLAS 구현은 이번 작업에 포함하지 않는다.

## 조작

1. 박스 수·시드·조건을 설정하고 **조건 적용 · 새 실행 준비** → **실행** 또는 **한 단계 실행**.
2. 상단 6개 지표를 누르면 상세 분석으로 이동한다. 중앙 3D는 기존 회전·확대·선택을 유지한다.
3. **위험 및 성능 진단**, 그래프의 막대, 박스 행을 선택하면 실행이 일시정지되고 저장된 단계·박스로 이동한다. 비교 중 선택하면 비교 작업을 취소한다.
4. **기록 재생**은 650ms마다 저장된 판단을 재생한다. **실시간 보기**는 가장 최근 상태로 돌아간다. 이는 측정된 로봇 시간에 맞춘 애니메이션이 아니다.
5. **A/B/C · 3개 시드 비교** 후 알고리즘 비교/강건성 탭에서 다른 결과를 불러와 같은 방식으로 재생한다.
6. 아래 **원자료 · 비교표 · JSON / CSV 내보내기**에서 비교 JSON/CSV, 단계 평가 CSV, 현재 실행 JSON을 저장한다. 현재 실행 JSON과 비교 JSON에는 실제 상태·관측 상태와 단계별 평가 기록이 들어간다. 단계 CSV의 completion/utilization은 0~1 비율이다.

## 구현 파일

- `src/pallet/adaptive/performance.ts`: 읽기 전용 평가, 지지 외곽·방향별 전도 근사, 분위수, 동일 조건 비교, 진단.
- `PerformancePanel.tsx`, `performance.css`: 6 KPI, 5개 분석 영역 + 적합성 + 비교, 재생과 선택.
- `worker.ts`: 기존 Session 호출 후 기록을 만들고 전달한다. 비교도 단계 기록을 보관한다.
- `AdaptiveLab.tsx`: 기록/커서/현재 실행 분리, 진단과 3D 선택 연결, 내보내기.
- `AdaptiveScene.tsx`: 전체 무게중심과 수직 투영, 하중 사용률 표시. 기존 형상·접촉·경로 유지.
- `tests/pallet-performance.test.ts`: 8개 핵심 검증.

## 지표 정의와 가정

길이 mm, 질량 및 반력 kg 상당, 시간 s/ms, 전도한계 g. 물리 검사의 허용오차와 기본 설정은 기존 Config를 그대로 사용한다.

- 적재 적합성: 빈 상태는 미검증. 기하·정적 검사에 위반이 있으면 독립적으로 실패. 위반이 없어도 전체 링크 충돌·IK·실물 흡착을 검사하지 않았으므로 종합 적합성은 미검증. 높은 완료율이 실패를 상쇄하지 않는다.
- 적재 성과: 배치 수/입력 수. 상태 위반이 있으면 상단 완료율은 미판정. 정격 공간 활용률은 실제 복합 외형의 합집합 체적/허용 팔레트 체적. 정상 규격 부피도 별도 표시한다.
- 전체 무게중심: 각 박스의 명시된 실제 질량중심을 현재 자세로 변환해 질량 가중 평균. 외형 변형만으로 질량중심을 바꾸지 않는다.
- 전도 근사: 바닥 접촉의 볼록 외곽과 전체 질량중심을 사용한다. 최저값은 지지 경계 거리 d/무게중심 높이 h. 8개 방향은 관성력 방향의 광선과 지지 외곽의 교차거리/h. 상단은 현재 재생 시점까지 기록된 최솟값이다. 적재물이 일체인 강체라는 가정이며, 일반적인 독립 박스 더미의 동적 안정성·미끄럼·유연 골판지 파손을 보장하지 않는다. 지게차와 포크의 안정성도 포함하지 않는다.
- 국부 안정성: 기존 검사기가 구한 실제 접촉, 누적 반력/합력 작용점, 강도 한도를 재사용한다. 지지면적은 합집합. 강도 미입력은 사용률을 비워 둔다. 합성 강도 입력은 출처를 표시한다. 청록 80% 이하/황토 80% 초과/적색 100% 초과는 표시용 구간이며 안전계수가 아니다.
- 무거운 박스를 가벼운 받침에 올리지 않는 별도 규칙은 이 변형 실험에는 추가하지 않았다. 누적 허용하중 검사와 같은 것으로 표시하지 않는다.
- 로봇 작업: 기존 수직 운반체의 가정 속도와 지연으로 구한 모델 시간. 경로 길이는 상자 기준점의 위치 궤적이며 실제 TCP·관절 회전 거리가 아니다. 실물 작업시간과 동작별 시간 분해는 미검증.
- 계산 성능: 계획기 호출의 누적 시간 차이를 기록한다. 기록/평가/렌더 비용은 제외된다. P50/P95/P99는 최근접 순위이며 작은 n의 P99는 최대값에 가깝다. 기한 내 유효 후보 반환은 시간 이내이면서 반환 후보 중 제약 통과 후보가 있어야 한다. 빠른 실패는 성공으로 세지 않는다. 전체 실시간 시스템의 지연 검증과 구별한다.
- 강건성: 현재 모드에서 완료된 합성 시험 중 전량 적재 + 모델 제약 무위반 비율. 현재 3개 시드 시험은 박스 세트/관측도 바뀌므로 고정 박스의 순서 변화 시험이나 누락·오인식 주입 시험이 아니다. 예외 복구율은 미검증.
- 비교: 박스 목록/순서/물성/시드/환경/설정이 일치하는 A 결과만 짝으로 삼는다. 모드 외 설정이 다르면 비교에서 제외한다. 같은 브라우저 실행에서 얻은 시간만 표시하며 CPU/GPU 기종 및 전력 설정은 미확인으로 둔다.

## 기록과 성능

매 판단마다 실제·관측 위치/회전/형상, 무게중심, 지지 상태, 합력 여유, 하중, 계획시간, 모델 시간, 선택 경로, 후보 개수를 복사한다. 성공뿐 아니라 실패/대기도 기록한다. 과거 전체 후보 목록은 메모리를 줄이기 위해 제외하고 선택 후보와 개수만 보존한다. 최신 실행의 전체 후보 검토 기능은 유지한다. 기록은 브라우저 메모리에만 남으며 새 실행/새로고침 전 JSON을 내려받아야 한다.

UI 스레드에서 최적화하지 않는다. 기존 Worker 안에서 평가/기록하며 취소 시 Worker를 종료한다. 평가 비용은 추가되지만 알고리즘의 배치 선택에 입력되지 않는다. 최대 96개 박스와 기존 유한 재시도 한도를 유지한다.

## 검증

`node node_modules/typescript/bin/tsc -b` 통과.

다음 Vitest 5개 파일 **34개 테스트 통과**: pallet-performance, pallet-adaptive, pallet-adaptive-ablation, pallet-equilibrium, pallet-com-assessment. 검사 항목은 빈 상태/실패의 독립 판정, 실제 CoM·방향별 전도 계산, 강도 미입력, P99 꼬리·기한 판정, 불변 기록과 기존 선택 일치, 비교 입력 불일치 제외, 강건성 집계다. 기존 물리/변형 검사도 함께 통과했다.

실제 브라우저: 8개 입력 실행, 진단→판단 6/B007 이동, 이전 기록·자동 재생·실시간 복귀, A/B/C 9개 비교, C/43 저장 결과 로드와 재생, 비교 JSON 및 단계 CSV 다운로드를 확인했다. 실제 검사 화면은 1280×720. 뷰포트 설정 API가 실제 크기에 반영되지 않아 1920×1080/휴대폰 크기의 육안 검증은 완료했다고 주장하지 않는다. CSS의 작은 화면 분할/표 내부 스크롤은 구현되어 있다.
