# PAC 2026 알고리즘 평가 / Benchmark

기존 React 19 + TypeScript + Vite + Three.js 화면과 모든 계획기를 보존했다. Rapier는 별도 수동 강체 검사 기능이며 이 벤치마크의 동적 물리 검증에 사용하지 않았다. 새 시스템은 `src/pallet/benchmark/`에 독립 배치했고 기존 `PalletLab.tsx`와 `relay/dashboardView.ts`에 탭만 연결했다.

## 실행

- `npm install`, `npm run dev`; `/?palletView=benchmark#pallet` 열기.
- 기존 설정 또는 혼합 18개 전략 예제를 선택하고 알고리즘·시나리오·시드·반복 횟수를 설정한다. 기본은 100회, 10/50/100/500/1000회 선택 지원.
- 실행 → 종합표(헤더 정렬) → 상세 분포 → 실행 선택 → 3D 단계·박스 확인.
- 가중치·절대 정규화 기준을 바꾸면 원시 결과를 재사용하여 즉시 다시 계산한다. 실험 조건 변경은 다음 실행에 적용한다.
- 일시정지는 현재 trial 완료 후 적용한다. 취소·초기화·탭 이탈은 Worker를 중단한다. 취소 시 미실행 trial을 실패로 만들지 않는다. 결과는 메모리에 유지되며 새로고침 전에 JSON/CSV로 저장한다.
- JSON에는 조건·지표 정의·검증 범위·전체 단계 기록·요약, CSV에는 trial별 원시 수치·예외·실패 유형을 포함한다. 현재 로컬 공유 환경의 브라우저 정보도 함께 기록한다.

## 기존 코드 분석과 재사용

- 좌표: 바닥 x/y, 위쪽 z, 박스 최소 모서리 위치. mm / kg / s, 알고리즘 판단시간 ms.
- `ArrivalEnvironment.input`: 현재 도착 박스, 종류별 구성·잔여 수량만 공개. 내부 큐와 이벤트 계획은 평가기만 보유한다. 확정된 박스는 이동하지 않는다. 온라인에서는 첫 배치 불가 박스에서 중단하는 기존 정책을 유지한다. 새로운 버퍼·재배치 휴리스틱은 추가하지 않았다.
- 공통 `plan`: legacy BL/Greedy/Rollout, 6개 미래공간 전략, seeded random. 후보는 기존 frontier/모서리/균형 위치와 허용 회전에서 생성한다. 기존 점수와 가중치는 변경하지 않았다.
- `inspectConstraints` + `advance`: 경계·최대 높이·관통·허용 회전·접촉 지지·정적 합력/모멘트·누적 하중·중량 순서·그리퍼 스윕/도달 반경/가반 검사. 어댑터는 위치/방향만 결정하며 강도·접촉·경로를 확정하지 못한다. 관측 물성과 공통 검사 결과로 덮어쓴 뒤 확정한다.
- `metrics`, `stability`, `evaluatePattern`, `remainingSites`: 기존 질량중심·사분면 반력·누적 하중·최종 재감사·잔여 위치 검사 재사용.
- `PalletScene`: 단계별 위치·지지 영역·합력 중심·선택 경로·박스 선택을 그대로 재사용. 벤치마크 화면의 팔 애니메이션은 끄며 로봇 검증으로 오인하지 않게 한다.

## 모듈

- `model.ts`: 공통 설정, trial/단계 기록, 6개 영역, 기준값.
- `registry.ts`: 16개 온라인 어댑터 + 오프라인 재고 선택 Greedy. 기존 10개 공통 계획기, 기존 포장 5개(First Fit/Greedy/Tetris/Beam/Robust Beam), 명시적 z-y-x BLB. 사용자 알고리즘은 같은 파일에서 `registerAlgorithm({id,name,scope,family,description,plan})` 후 빌드하면 Worker와 UI에 함께 등록된다. 외부 임의 코드 업로드·실행 기능은 없다.
- 변형·관측 실험의 별도 형상/실행 상태는 직육면체 공통 프로토콜과 달라 자동 합치지 않았다. 기존 탭은 유지하며 동일 형상 판정 어댑터가 준비되기 전까지 공정한 순위에 넣지 않는다.
- `runner.ts`: 격리된 trial, 온라인 경계, 제안 검사, 확정 재검사, 기록, 최종 감사. 후보 탈락은 알고리즘의 불법 제안과 구분하고 유형별 후보당 한 번 집계.
- `worker.ts` / `controller.ts`: 순차 Worker, 제한시간, 강제 중단, 일시정지, 취소, 뒤늦은 메시지 무시. 새 Worker 생성 비용은 알고리즘 판단시간에 넣지 않는다.
- `statistics.ts` / `scoring.ts`: 분포·Student-t CI·절대 정규화·검증 범위별 순위.
- `metrics.ts`: 단위·공식·측정/근사/미지원 출처. `export.ts`: JSON/CSV.
- `BenchmarkLab.tsx` / `benchmark.css`: 기존 엔지니어링 UI에 맞춘 조작·순위·레이더·막대·상세·3D 기록.

## 공정한 실험과 예산

모든 알고리즘에 동일한 시드별 박스 집합·도착 순서·팔레트·제약·후보 예산·예외·판정 코드를 적용한다. 설정은 실행 시작 시 복제하고 각 trial은 독립된 상태로 시작한다. `fingerprint`는 알고리즘명을 제외한 조건 식별용이며 암호학적 보증은 아니다. 실제 미래 순서와 감사용 도착 ID 배열은 계획기 입력에 전달하지 않는다. 전략 상태/예약은 해당 trial에서만 이어진다.

- 기본 1,000 ms/판단, 30,000 ms/trial. 실제 함수 측정이 상한을 넘으면 그 행동은 확정하지 않는다. 메인 스레드 감시기는 메시지 지연 여유 500 ms/2,000 ms 뒤 Worker를 종료한다. 이 여유는 행동 채택 예산이 아니다.
- 강제 종료로 확보하지 못한 지표는 null로 기록한다. 늦게 반환된 행동은 거부한다. 알고리즘에 따라 기록된 prefix 유무가 다르므로 지표별 측정 n을 함께 확인한다.
- 최대 10,000 trial 또는 예상 250,000 박스 시도/실행. 정상 적재 수가 0인 실행은 종합점수를 부여하지 않는다. 후보 예산은 입력 설정을 공유한다. 잔량 검사는 기본 종류별 8개 위치 표본, 0이면 끈다. 전수 탐색·최대 적재 가능량 보증이 아니다.
- Node 실험과 브라우저 Worker의 시간은 별도 측정이다. 브라우저는 CPU 모델·정확한 메모리·전력 설정을 제공하지 않아 미제공으로 기록한다. 실제 로봇 시간은 계산 지연과 별도다.

## 예외 정의

일반 시나리오는 입력의 기존 이벤트를 지우고 선택한 합성 이벤트만 공통 적용한다. 3번째(3개 미만이면 마지막) 박스에 이벤트를 넣는다.

- 누락: 해당 박스를 누락으로 제외하고 재고를 갱신하면 통과.
- 파손: 해당 박스를 격리하면 통과. 변형 재료 물성의 성공률이 아니다.
- 규격 오인식: 사전에 정한 첫 타입 기반 w×1.12, d×0.93, 동일 h로 현재 관측을 수정하고 실제 그 치수로 적재하면 통과. 연산은 수정된 현재 관측부터 시작하므로 센서 오류 감지·접촉 실패 복구 성공률은 아니다.
- 팔레트 변경: 1/3 처리 후 폭 15% 감소. 확정 배치를 재감사한 후 다음 박스 적재 시 통과. 기존 배치가 새 경계 밖이면 안전 중단하고 복구 실패로 기록한다. 이미 놓은 박스 이동은 하지 않는다. 이 환경 변경 실패를 이전 알고리즘의 불법 제안으로 집계하지 않는다.
- 만나기 전에 중단한 예외는 미평가. 예외 유지율은 같은 알고리즘·시드의 `다양한 크기` 무예외 실행을 함께 선택한 경우에만 계산한다.

## 점수와 미검증

기본 가중치 25/25/15/20/10/5. 단위가 다른 수치는 직접 더하지 않는다. 기준값은 `DEFAULT_THRESHOLDS`이며 UI에서 수정하고 JSON에 저장한다. 80% 부피율, P95 10 ms 만점/1,000 ms 0점, 5~40초/박스, 정적 전도 0.3g는 **조절 가능한 비교 가정**이며 PAC 공식 기준이나 현장 안전 한계가 아니다.

- 효율: 완료율 60% + clamp(부피율/0.8) 40%.
- 정적 안정성: 최소 지지율 40% + clamp(최저 정적 전도한계/0.3g) 40% + (1−사분면 반력 불균형) 20%.
- 작업·계산: P95 지연 60% + 모델 초/박스 40%. 이상 환경은 계산만 평가하며 다른 검증 범위로 분리.
- 순서 대응: 무작위/혼합 반복 완료율 평균 50% + P05 완료율 50%. 2 trial 이상에서만 표시. 결정론적 작은/큰/무거운 우선 조건을 무작위 강건성 표본으로 섞지 않는다.
- 로봇: 기하 접근 제안 통과율/전체 실행 완료율 평균. 실제 IK·파지 성공률은 항상 null.
- 예외: 실제 만난 이벤트의 정의된 대응 성공 비율.

미지원 영역을 0점 처리하지 않고 남은 가중치로 부분 종합을 계산한다. 영역 가용성, 로봇 평가 방식, 강도 입력 범위, 시나리오·시드·조건 집합이 같을 때만 같은 순위 그룹에 들어간다. 가중치 변경 시 검증된 영역 가중치 비율도 바뀐다. 물리·실기 미검증 표시는 항상 남긴다.

안전 제안 거부, 시간 초과, 실행 오류, 적재 0개, 환경 변경 안전 중단 중 하나라도 있으면 전체 실험 묶음의 종합점수·순위는 null. 정상 부분 적재는 완료율로 평가한다. 오프라인 전체 재고 선택 Greedy는 알고리즘별 Online Regret 참고값만 제공하며 순위 제외. 최적성 증명은 없다. 예외 오프라인 어댑터는 지원하지 않는다.

각 지표는 trial별 평균/중앙값/표본 표준편차/최솟값/최댓값/P05/P95/평균 95% CI와 유효 표본 n을 제공한다. n=1일 때 표준편차·CI는 null. CI는 독립 trial 근사, df≤30 t 표값, 이후 근사식이다. trial별 P95의 평균을 모든 판단의 pooled P95라고 표시하지 않는다.

## 한계와 다음 확장

- 단일 팔레트, 직육면체 입력에 대한 공통 평가. 다중 로봇의 동시 작업 스케줄·다중 팔레트 효율은 별도 확장이다.
- 변형 메시·실제 흡착·관절 IK·동적 충돌·소성변형/압축강도·실기 작업시간은 이 점수의 검증 대상이 아니다.
- 허용하중을 명시하지 않은 물성의 기존 재질 예제값은 `assumed` 또는 `missing`으로 분리. 실측 강도라고 표시하지 않는다.
- 잔여 수용성은 종류별 독립 표본 검사. 미래 순서를 전수/몬테카를로로 공동 적재하는 새 평가기는 추가하지 않았다.
- 동일 미래 구성에 대한 자료구조가 다른 변형 실험의 공통 프로토콜, 실제 로봇 검증기, 대용량 결과 영구 저장·paired CI가 후속 과제다.


## v25 / 평가 엔진 2.0 보완

기존 배치 계획기와 입력 경계는 수정하지 않았다. 평가 모듈의 근거와 비교 조건을 강화했다.

- `hardConstraints.ts`: 10개 제약을 PASS / FAIL / NOT VERIFIED로 분리. 정적 기하·지지 PASS는 모델 범위의 통과이고 실제 동적 안정성 인증이 아니다. 미측정 trial은 PASS가 아니다. 재질 기본값·자동 생성 강도, 해당 방향의 강도 정보 누락은 하중 미검증. 전체 링크 충돌/IK/실제 파지는 항상 미검증으로 남긴다.
- 공식 / 잠정 / 오프라인 참고 / 실패 순위를 별도 구획한다. 전체 10개 PASS만 공식 순위 대상이며 현재 구현의 실제 시험은 모두 잠정이다. 잠정에서도 같은 검증 범위·워밍업 조건·입력에서만 순위를 비교한다.
- 입력 가중치는 각각 0~100, 합계 100% (부동소수점 오차 1e-6 이내). 틀리면 점수·순위만 보류하고 원시 지표와 재생을 보존한다. 기본 가중치 복원 버튼 추가.
- `controller.ts`: 알고리즘별 같은 Worker에서 기본 1회 워밍업(0~5회), 새 trial 상태 사용, 측정 통계에서 제외. 실패 시 자동 반복하지 않고 실제 완료 수와 같은 Worker 여부를 기록한다. 이후 Worker 교체 시 다음 trial의 새 워밍업도 상한 내에서 수행한다. 실행 횟수 진행률은 측정 trial만 센다.
- `motionMetrics.ts`: 선택적 TCP 가속도(mm/s²), 기본 미입력. 미입력은 기존 등속 가정. 입력하면 각 선분 정지→출발→정지 사다리꼴/삼각형 속도로 예상시간을 계산하고 회전·집기·놓기 시간을 유지한다. 궤적 블렌딩·관절 가속도·토크·실제 사이클 검증이 아니다. 경로나 배치 결정은 변경하지 않는다.
- 잔여 외곽 공간 mm³, 무작위 순서 완료율, 파손·누락·규격 재관측 개별 대응 지표 추가. 무작위 통계에는 mixed/random만 사용한다. 오프라인 격차 및 예외 유지율 설명을 실제 계산인 **부피 적재율**로 바로잡았다.
- 가벼운 박스 우선 시나리오는 기존 heavy-late(질량 오름차순)의 명시적 별칭이다. 두 시나리오는 동일 순서이며 별개의 확률 실험으로 해석하지 않는다.
- JSON `PAC-Benchmark/2`: 알고리즘 버전/평가 버전/제약 근거/워밍업 기록 추가. 기존 결과 파일은 덮어쓰지 않았다. 사용자 어댑터에는 `version`을 지정하며 누락하면 미지정으로 남긴다. 현재 bundled 어댑터는 `adapter-1.0 / planners-f6ec11d4259a`.

### v25 실제 검증

새 23개 + 기존 평가 26개 + 기존 무작위 배치 12개 = **61개 회귀 테스트 통과**. 별도 재현 실험 1개도 통과. TypeScript 및 Vite 빌드 통과(208 모듈). 브라우저에서 10개 시드 × 2개 알고리즘, 워밍업 제외 진행률, 가중치 101% 거부·기본값 복원·원시 기록 유지, JSON 실제 다운로드 및 스키마/워밍업/미검증 기록, 3D 재생 기록과 콘솔 오류 없음 확인.

`PAC_BENCH_V2_REPORT=1 npx vitest run tests/pallet-evaluation-v2-report.test.ts`로 재현한다. Windows PowerShell은 `$env:PAC_BENCH_V2_REPORT='1'`을 먼저 지정한다. 결과: [JSON](benchmark-v2-measured.json), [CSV](benchmark-v2-measured.csv).

18개 혼합 박스, 팔레트 1000×800×1400 mm, 시드42~51, 후보64개, 판단1000ms, 이상적 로봇. 알고리즘별 한 번 워밍업 후 동일 Node 프로세스에서 각각 10회 측정(워밍업2회는 통계 제외). 장비·시드·설정은 JSON에 포함한다. 시간은 공유 PC 측정치이며 브라우저 실행과 직접 동등하지 않다.

|---|---:|---:|---:|---:|---:|---|
| Greedy | 8.4 | 46.67% | 13.53% | 58.54 | 61.56 | 잠정 |
| 무작위 | 8.1 | 45.00% | 12.70% | 4.74 | 64.17 | 잠정 |

선택 제안 및 확정 상태의 정적 위반 0건. 기하·하중 입력·정적 지지 6항목 PASS, 로봇 관련 4항목 NOT VERIFIED. Greedy의 적재량이 더 많으나 무작위의 계산비용이 낮아 기본 부분 종합 순위는 무작위가 높다. 이를 일반적인 알고리즘 우열이나 실물 로봇 성능으로 해석하지 않는다. v24와 적재 수·부피 결과가 같아 기존 계획 동작 보존을 확인했다.

전체 링크/IK/흡착 물리, 동적 붕괴, 복수 팔레트 벤치마크, 실제 센서 예외, 결합된 미래 수용량 최적화는 여전히 미지원이다. 잔량 검사는 표본 기반 정적 근사다. Claude 읽기 전용 점검은 최종 분석을 반환하지 않아 완료된 코드 리뷰로 산정하지 않았다.
