## 이번에 추가한 동작

### 파지 자세·회전과 도달 검사

입고 상자의 파지 방향은 0°로 시작합니다. 목표가 90°이면 안전 높이에서 상자와 그리퍼를 회전하고, 내려놓은 뒤 빈 그리퍼의 방향을 복원합니다. 0°/90° 양 끝점뿐 아니라 회전 중 최대 외곽도 검사합니다.

`회전 외곽 폭 = w|cos θ| + d|sin θ|`

`회전 외곽 깊이 = d|cos θ| + w|sin θ|`

각 구간의 끝 각도와 극값 각도를 포함해 최대 외곽을 구하고 작업공간·기존 박스 간섭을 보수적인 스윕으로 검사합니다. 운반 박스에는 현재 관측 치수를 사용합니다. 그리퍼 자체도 같은 방향으로 회전합니다.

`구간 시간 = max(이동 거리 / 이동 속도, 회전 각도 / 회전 속도) + 집기·놓기 정지 시간`

기본 회전 속도 180°/s는 편집 가능한 예제값입니다. 회전 시간은 3D 재생과 실제 계산 시간과 독립인 논리 작업 시간에 포함됩니다.

TCP 도달 반경은 기준 x/y와 최소·최대 반경으로 설정합니다. 모든 직선 구간의 기준점까지의 최소 거리와 최대 거리를 검사합니다. 따라서 끝점 두 개가 모두 가능해도 중간에 최소 반경을 침범하면 탈락합니다. 높이와 그리퍼/박스 외곽은 기존 작업공간 검사에서 확인합니다.

기본 기준점 `(−700,500) mm`, 최소 0mm, 최대 2400mm는 실물 로봇 모델의 인증값이 아닌 예제입니다. 파지 방향은 상면 접근과 yaw 0/90°만 지원합니다. 연속 yaw 경로를 표시해도 실제 관절 자세·역기구학 해·링크 충돌이 검증되었다는 뜻이 아닙니다.

### 실행 중 부분 재계획

- **확정 적재 유지 · 조건 재계획:** 왼쪽 편집에서 팔레트·제약을 바꾼 뒤 실행합니다. 확정 상자의 실제 좌표와 속성으로 새 기하·하중·지지 조건을 재검사합니다. 기존에 실행된 로봇 경로는 당시 조건으로 보존하고 앞으로의 경로는 새 로봇 조건으로 검사합니다.
- **현재 관측 수정 · 부분 재계획:** 현재 박스의 실제 가로/깊이/높이, 손상, 누락을 입력합니다. 실제 ID·수량·투입 순서를 바꾸지 않습니다. 수정 규격은 현재 박스에만 적용하고 나머지 동일 타입 박스를 몰래 바꾸지 않습니다.
- 미확정 애니메이션·분석을 취소하고 새 실행 ID로 현재 단계부터 계산합니다. 늦게 도착한 이전 Worker 결과와 이전 동작의 확정을 적용하지 않습니다.
- 실패한 미확정 결정은 새 재계획에서 제외하지만 변경 전 실행은 보관합니다. 확정 배치와 정상 처리 기록은 유지합니다.
- 이미 처리한 관측을 수정하거나 박스 세트·수량·입고 시드를 바꾸는 부분 재계획은 거절합니다. 이들은 **새 실행**으로 패턴을 재생성합니다. 새 조건에서 확정 적재가 불안정하면 기존 좌표를 자동 이동해 성공으로 바꾸지 않습니다.

모든 새 확정 기록에 당시 팔레트·제약을 저장합니다. 팔레트 폭을 200→600mm로 바꾼 실행에서도 과거 1단계 프레임은 200mm 조건을 보여주고 현재는 600mm를 보여줍니다. 입고가 모두 끝난 뒤 조건을 다시 바꾸더라도 보관 실행은 최종 저장 조건을 사용하고, 그 안의 개별 과거 단계는 당시 조건을 사용합니다. 보관 화면의 활성 검사와 내보내기도 저장 조건을 따릅니다. 프레임 재생과 강체 물리 검증은 계획을 수정하지 않습니다.

### 공통 패턴 점수와 조건별 비교

모든 정책에 같은 평가를 적용합니다. 먼저 기록된 단계별 배치를 당시 조건으로 재검사하고, 현재 확정 적재를 현재 팔레트·정적 조건으로 다시 검사합니다. 강도가 미검증이거나 제약 위반이 있으면 종합 점수를 `미검증`으로 표시합니다.

각 차원은 0~100점입니다. clamp는 0~1 범위 제한입니다.

| 차원 | 정의 | 품질 가중치 |
| --- | --- | ---: |
| 공간 활용·조밀성 | 50 × (고정 용적 이용률 + 사용 높이 효율) | 0.25 |
| 하중 균형 | 100 × clamp(1 − 바닥 사분면 불균형) | 0.20 |
| 전도·하중 여유 | 100 × min(각 접촉의 clamp(전도 여유 / 경계 여유), clamp(1 − 최대 하중 사용)) | 0.35 |
| 로봇 작업 시간 | 100 / (1 + 평균 박스 작업 초 / 10) | 0.15 |
| 결정 계산 시간 | 100 / (1 + 결정 계산 중앙값 ms / 1000) | 0.05 |

`종합 점수 = 실제 적재 수 / 초기 전체 수량 × 품질 가중 평균`

이상적 연구 모드에서는 로봇 시간 점수를 미평가로 두고 나머지 가중치를 합 0.85로 나눕니다. 적재가 없으면 0점이며 확정 배치가 없다고 표시합니다. 격리·누락을 전체 적재 성공으로 바꾸지 않습니다. 전도 경계/하중/시간 기준과 가중치는 프로젝트의 비교용 정의이며 실물 안전 확률이 아닙니다. 계산 시간은 장비·동시 작업에 영향을 받으므로 작은 점수 차이를 통계적 우열로 주장하지 않습니다.

**조건별 비교 기록**에는 완료된 세 정책 비교의 원래 박스 구성·팔레트·제약·탐색 설정·실제 결과를 함께 저장합니다. 조건을 바꿔 다시 비교해도 이전 조건을 덮어쓰지 않습니다. 같은 조건 안에서 정책을 비교하고, 서로 다른 조건의 결과는 조건 차이와 함께 봅니다. 현재 실행 JSON, 비교 JSON/CSV, 조건별 비교 JSON에 평가와 재현 정보를 저장합니다.

## 먼저 확인한 고정 입력

1. `200×300` 상자/그리퍼가 90° 회전: 시작과 끝은 작업공간 안이어도 중간 대각 외곽이 밖으로 나가는 배치를 거절했습니다.
2. TCP의 양 끝점은 도달 반경 안이지만 직선 중간이 최소 반경 안으로 들어가는 경로를 거절했습니다.
3. `200×400×100` 팔레트에서 첫 상자를 확정한 뒤 다음 300mm 상자가 막힘: 폭 600mm로 조건을 바꿔 첫 상자의 좌표·ID를 유지하고 두 번째부터 다시 계획해 2/2개를 적재했습니다.
4. 새 높이 50mm가 이미 확정한 높이 100mm 상자를 위반: 부분 재계획을 거절하고 기존 실행을 보존했습니다.
5. 이동 중 두 번째 상자의 관측을 `185×147×131`로 수정: 이전 동작을 취소하고 첫 상자를 보존했습니다. 이후 손상·누락 처리까지 2 적재 + 1 격리 + 1 누락 = 4개를 보존했습니다.
6. 팔레트 폭 600/700mm의 비교를 각각 완료: 2조건 × 3정책의 입력과 결과를 보존해 JSON에서 원래 팔레트 폭을 확인했습니다.
7. 현재 확정 좌표가 잘못되거나 기록 배치가 제약을 위반하면 점수를 제공하지 않고, 강도 미검증·이상적 로봇 시간도 분리했습니다.

## 같은 혼합 입력의 최종 측정

세트/입고 시드 `20261004/42`, `7919/834`, `15401/902`를 그대로 사용합니다. 상자 치수·중량·재질을 바꾸지 않았습니다. 온라인/무게 순서/누적 반력/강도/그리퍼 자세·경로/도달 반경을 적용했습니다. [측정 JSON](pallet-online-measurements.json)에 입력·결과·개별 경로 yaw·단계 조건·평가가 있습니다.

| 세트 / 물량 | BL 적재 / 점수 | Greedy 적재 / 점수 | Rollout 적재 / 점수 |
| --- | ---: | ---: | ---: |
| 20261004 / 30 | 7 / 14.5 | 8 / 16.1 | 7 / 13.6 |
| 7919 / 24 | 10 / 16.4 | 8 / 17.1 | 8 / 16.7 |
| 15401 / 24 | 6 / 13.4 | 6 / 14.3 | 6 / 14.2 |

계산 중앙값은 각각 BL 80.0/66.4/33.7ms, Greedy 246.2/198.8/120.2ms, Rollout 419.5/276.4/252.8ms였습니다. 로컬 Node의 1회 측정이고 빌드가 동시에 실행되었으므로 고정 실시간 상한이 아닙니다. 점수는 적재 수뿐 아니라 위의 품질 차원을 함께 반영합니다. 제한된 희소 후보·후속 탐색이며 전체 최적해를 주장하지 않습니다.

추가 검사 후 적재 개수는 이전 실행과 같았습니다. 기본 혼합 30개는 Greedy 8개 후 중단합니다. **이번 기능이 적재 수를 일반적으로 개선했다거나 실제 로봇의 모든 요구조건을 검증했다고 주장하지 않습니다.** [이전 측정](pallet-online-before-requirements.json)도 보존했습니다.

검증 명령과 최종 결과는 [VERIFICATION.md](../VERIFICATION.md)와 [검증 메타데이터](pallet-requirements-verification.json), 기존 온라인 알고리즘 수식/입력은 [앞선 재설계 보고서](ONLINE-MIXED-PALLETIZING.md)에 있습니다.
