# ALPS 로봇 적재 시연 · 8초 병렬 판정 · 발표 자료

## 현재 발표 전용 페이지

**[http://127.0.0.1:4191/alps](http://127.0.0.1:4191/alps)**

기존 연구실 메뉴와 분리해 새로 만든 화면이다. 적재율·계산, 로봇 시연, 매장 진열 효율, 발표 자료 네 화면만 노출한다. 72박스 용량 자료는 새 Claude 도구 실행의 40행, 24박스 주문 자료는 차트 06과 같은 v2 원본의 100개 평가행을 사용한다. 과거 실험·1043 기본 조건 자료는 이 페이지에 섞지 않는다.

`python3 scripts/focused-alps-data.py`가 원본 해시를 포함한 `public/alps-current.json`을 생성한다. 초기 화면에서는 작은 집계 JSON만 읽고 로봇 시연을 열 때 재생 자료를 추가로 읽는다. [현재 발표 자료 ZIP](http://127.0.0.1:4191/presentation-charts/ALPS-current-presentation.zip)은 차트 06·07의 PNG/SVG/CSV/캡션·출처만 포함한다.

72박스, 높이 1,200mm, 로봇 제약 적용, 호출당 8초 한도에서 40/40실험 완료, 제약 위반 0건. 선택 3시드에서 고른 Compact의 별도 평가 5시드 평균 적재율은 65.17%, Hybrid는 61.46%. 평균 호출 시간은 각각 5.59ms/69.52ms, 전체 관측 최대 호출은 980.10ms다. Compact−Hybrid의 대응 차이는 +3.70%p, 95% 구간 -4.51~11.92%p로 일반 우월성을 입증하지 않는다. 단일 호출과 전체 센싱·판단·제어 주기를 구분한다.

## 최신 요청 반영

로봇 적재 애니메이션은 유지한다. **마트 내부의 이동·진열 애니메이션만 제외**하고, 적재 방법에 따른 부서별 인출·방해 상자 재취급·예상 매장 작업시간은 비교표와 설명으로 유지한다. 매장 효율을 삭제하거나 현장 검증 완료로 주장하지 않는다.

로봇은 박스당 8초 동작 중 다음 박스를 인식하고 계산한다고 가정한다. 계산이 8초 안에 끝나면 매번 계산시간을 동작시간에 더하지 않는다. 첫 준비 계산과 다음 행동 전에 끝나지 않은 노출 대기만 더한다. 팔레트 교체 20초 동안 빈 팔레트에 대한 재계획도 병행한다.

## 서로 다른 실험 구분

1. 기존 72박스/단일 팔레트/250ms 자료: `../capacity/` 및 차트 01~05. 높이별 용량과 계산시간의 내부 관측. 일부 물량만 적재하므로 알고리즘별 총시간을 전체 주문 처리량으로 비교하지 않는다. 1043 차트는 **저장된 기본 조건**이며 사용자가 설정을 바꾼 새 1043 실행은 아니다.
2. 현재 24박스 전체 주문/8초 병렬 모델: `results.json`, `results.csv`, 차트 06. 팔레트를 교체하며 모든 물건을 적재하고 매장 작업을 수치로 추정한다. 24박스 전체 부피는 1200×1000×1200mm 팔레트의 43.08%이므로 가득 채우는 용량 검증과 다르다.
3. Claude 호출 결과와 추가 72박스/8초 판단 한도 비교는 `claude/`에 별도 저장한다. Claude가 로컬 실행 도구를 호출한 원본과 모델의 해석을 구분한다. HRPal의 실제 프로그램을 실행하지 못하면 `not_evaluated`, 수치 `null`로 남긴다.

## 8초 모델의 비교 기준과 실제 기록

입고 순서를 계획기에 미리 전달하지 않는다. 센서가 다음 박스를 운반 중 인식한다고 가정하고 확정될 배치 상태로 다음 박스의 계획을 미리 준비한다. 8초는 다음 집기 준비까지 포함한 사용자 가정이며 실제 기종에서 보장되는 사이클 측정은 아니다. 인식 추가 지연을 0으로 두고 계획 호출 외 통신·후속 검사·제어 지연은 별도다.

계산기는 한 번에 하나의 계획을 수행한다. 이전 운반 또는 교체의 시간창은 한 번만 소비한다. 정상 완료에서:

`적재 경과시간 = 8초 × 적재 수 + 교체시간 + 초기 준비·노출 계산 대기`

`계획 호출 경과시간 합 = 동작 중 숨겨진 계산 + 노출 계산 대기`

계획 호출 60초는 실행 보호 상한이고 8초 사이클 목표와 구분한다. 8초를 넘는 계산은 노출 대기로 반영한다. 기존 250ms 초과 Hybrid도 다시 실행했다. 계산시간은 호출의 wall-clock 경과시간이며 CPU 전용시간이나 센서 입력부터 로봇 승인까지의 지연 보장은 아니다.

선택 시드 310~314에서 5알고리즘 × 구역 선호 ON/OFF를 평가했다. 선택용 예상 전체 작업시간 기준은 Compact+구역 선호, 관측 최하는 Greedy였다. 별도 평가 시드 2210~2229에서 기준, 선택 ALPS, 동일 Greedy+구역, Hybrid OFF/ON을 비교했다. 총 150회 모두 완료, 배치 위반 0건. 첫 평가 시드 2210을 시연으로 사용한다.

선택 ALPS와 기준의 대응 차이(기준 − ALPS): **평균 53.23초, 95% t 신뢰구간 -11.07~117.54초**, 15개선/5악화. 신뢰구간이 0을 포함하므로 일반적인 시간 단축이 입증됐다고 주장하지 않는다. 구간은 이 입력의 랜덤 순서 변동만 다루며 가정된 매장 동작시간의 오차를 포함하지 않는다.

Hybrid의 평가 적재율이 더 높다. Compact를 **최대 적재율 최적 알고리즘**이라고 부르면 안 된다. 선택용 지표와 별도 평가 관측치를 구분하며 평가를 보고 사전 선택 결과를 바꾸지 않았다.

## 매장 진열 효율을 설명하는 방법

구역별로 접근 가능하게 배치하면 방해 박스를 임시로 옮기는 작업을 줄일 수 있다. 다만 공간 이용이 나빠져 팔레트를 더 쓰면 이동과 교체가 늘 수 있다. 이 관계를 적재 형태·재취급 개수·팔레트 수·예상 시간으로 설명한다. 매장 애니메이션을 실제 효과의 증거로 사용하지 않는다.

양쪽 모두 입고장 분류 후 카트 이동 / 팔레트 직접 순회와 구역 방문순서 6개 중 가능한 빠른 방법을 사용한다. 기준선에 강제 대기나 잘못된 경로를 넣지 않는다. 최적 혼합 정책 전체를 탐색한 것은 아니다.

카트 6박스/80kg, 이동 0.9m/s, 층간 45초, 인출 4초, 분류 2초, 구역 전환 2초, 개봉 6초, 낱개 진열 2초, 포장재 정리 3초, 팔레트 교체 20초 가정. 주문 전체의 개봉·진열·정리 600초는 공통이다. 입고장 공간은 주문 전체를 수용하고 직원 1명과 팔레트·임시 카트가 구역에 접근 가능하다고 가정한다. 통로·승강기·인체 부담·실제 판지·진동·흡착·전체 로봇 관절 충돌은 현장 검증 밖이다.
