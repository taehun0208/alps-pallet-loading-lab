## 발표 가능 범위

품질 지표는 **조건을 명시한 내부 시뮬레이션 결과**로 제시할 수 있다. 현장 성능 검증, 최적해 증명, 운송 진동 저항성 검증 자료는 아니다. 적재율·판단 계산시간·근사 로봇 경로시간·정적 질량중심을 구분한다. 임의의 종합 100점은 만들지 않았다.

기존 단일 팔레트 자료는 72박스 입고 중 실제로 담은 일부 물량을 비교한 것이다. 알고리즘마다 완료 물량이 달라 후단 전체 주문 처리시간 비교에 사용할 수 없다. [기존 차트 설명](charts/CAPTIONS.md)과 [근거 감사](EVIDENCE-REVIEW.md)를 함께 읽는다.

## 새 전체 주문 실험 결과

- 6품목 × 4박스 = 24박스의 같은 전체 주문, 1200×1000×1200 mm 팔레트, 로봇 1대, 입고 버퍼 0.
- 한 팔레트에 현재 박스를 못 놓으면 마감·교체 후 재시도. 사용 팔레트 수와 교체시간을 모두 센다.
- 후보 5개 × 구역 선호 ON/OFF × 선택 시드 5개(210~214) = 50회.
- 전 실행 완주·배치 제약·250 ms 판단 기한을 지킨 후보 중 전체 모델 작업시간 평균으로 선택한다. 7개 시간초과 실행은 순위에서 제외했다. 기한 검사는 동기 호출 반환 후 검사이며 강제 중단 실시간 제어기가 아니다.
- 기준 Greedy, 선택 ALPS `Bottom-Left-Back + 구역 선호`, 같은 기반의 효과 분리용 `Greedy + 구역 선호`를 평가 시드 20개(1210~1229)로 비교했다. 60회 모두 24박스 완주, 배치 위반 0건.
- 전체 기록 110회. 첫 평가 시드 1210을 미리 시연 대상으로 고정했다. 이 시드에서는 ALPS가 더 느리다. 불리한 결과를 바꾸거나 감추지 않았다.

| 별도 평가 지표 | 값 |
|---|---:|
| 기준 전체 작업 평균 | 1268.85 s |
| 선택 ALPS 전체 작업 평균 | 1250.04 s |
| 대응 차이 평균, 기준 − ALPS | +18.80 s |
| 평균 차이의 95% t 신뢰구간 | −37.97 ~ +75.57 s |
| ALPS 개선 / 악화 / 동률 | 16 / 4 / 0 |
| 동일 Greedy 기반 구역 선호 차이 | −54.97 s |

**현재 결과로 시간 단축이 검증됐다고 발표하지 않는다.** 신뢰구간이 0을 포함한다. 평균값만 떼어 개선율로 강조하면 불확실성을 숨기게 된다. 동일 Greedy 기반에서는 구역 선호로 평균 전체 작업시간이 오히려 약 55초 늘었다. 구역 선호로 재취급이 줄어도 공간 손실·팔레트 추가가 이득을 상쇄할 수 있다.

신뢰구간은 이 품목·치수·동작 가정에서 랜덤 입고 순서의 변동을 나타낸다. 실제 로봇/직원의 수행시간이나 입력 가정 오차를 포함하지 않는다. 카트 3/6/12개로 같은 배치의 후단을 재계산한 평균 차이는 각각 +59.92/+18.80/+17.50초였고 모두 신뢰구간이 0을 포함했다.

## 공통 후단 정책과 시간 가정

양쪽 모두 입고장 분류 후 카트 이동, 팔레트 직접 순회 중 가능한 빠른 방법을 사용한다. 구역 3곳의 방문순서 6개를 비교하며 직접 순회는 각 팔레트의 순서도 별도로 최적화한다. 기준선에만 강제 대기·잘못된 경로를 넣지 않는다. 이는 이 두 정책 계열 내 비교이며 모든 혼합 정책의 최적화는 아니다.

기본 카트 6박스/80 kg, 이동 0.9 m/s, 층간 이동 45초, 상자 인출 4초, 분류 2초, 구역 전환 2초, 개봉 6초, 낱개 진열 2초, 포장재 정리 3초, 팔레트 교체 20초. 같은 전체 주문의 개봉·진열·포장재 정리 600초는 모든 완료 정책에 공통이다. 코드에서 사용한 `redistributionSeconds`에는 이동·인출·분류·임시 이동을 넣고 이 공통 600초는 분리한다.

입고장 공간은 전체 주문을 수용하며, 직원 1명이 팔레트·임시 카트와 함께 필요한 구역에 접근한다고 가정한다. 카트는 박스 수·중량만 제한한다. 실제 통로/승강기 규격, 인체 부담, 카트 기하, 가속도, 센서·PLC 대기, 박스 사이 로봇 연결 이동, 도로 운송·센터와 매장 병렬 처리·래핑은 미검증 또는 모델 밖이다. 이 값을 현장 시간으로 인용하지 않는다.

## 재현·파일

```sh
npm ci
npm run benchmark:presentation
npm test -- tests/pallet-presentation.test.ts tests/pallet-capacity.test.ts
npm run build
```

- `results.json`: 설정·선택 순위·전체 110회 요약·최종 배치·통계·민감도·소스 SHA.
- `results.csv`: 실행별 비교 지표.
- `../../public/presentation-example.json`: 첫 평가 시드의 상세 적재·후단 재생 기록까지 포함.
- `results-quick.*`: 본 실행 전 선택/평가 각 1개로 수행한 개발 점검. 발표 통계에는 사용하지 않는다.
- `charts/`: 기존 180회 용량 실험으로 만든 그래프. 새 24박스 전체 주문 실험과 구분한다.

측정: Apple M5 / Node v24.14.1 / macOS arm64, 공유 개발 컴퓨터. 독립 6박스 입력으로 후보별 준비 계산 1회, 집계에서 제외. 실행 순서는 고정되어 OS/JIT 부하 영향을 제거한 엄밀한 마이크로벤치마크는 아니다.

## 구현 검사

새 테스트 9개: 전체 수량·한 번씩 진열·합산 시간 보존, 팔레트 교체 재시도, 시간초과 부분 결과 제외, 불가능 가반 미완료 보존, 시드/구역 검증, 상부 방해 박스 우선 인출·카트 한도, 실험 식별값 일치, 평가 시드의 선택 누출 방지, 저장 재생의 인출 순서·재고 검사.

연관 7개 테스트 파일 총 81개 통과. TypeScript와 Vite 빌드 통과(기존 대형 청크 경고). 브라우저에서 세 탭·랜덤 입고 재생·재분배 전환·초기 0/24·완료 24/24·동기 비교·그림 갤러리를 확인했다. 정적 무게중심은 운송 진동 시험을 대신하지 않는다.
