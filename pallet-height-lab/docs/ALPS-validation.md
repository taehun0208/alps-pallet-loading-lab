# ALPS — 중앙 대분류와 적재·재분배 검증

기존 React/TypeScript/Vite/Three.js 시뮬레이터에 추가한 독립 실험입니다. 기존 적재 알고리즘, Rapier 검증, 로봇 구성, 스캐너, 컨베이어, 중앙 배차를 교체하지 않았습니다. `?palletView=alps#pallet`로 접근합니다.

## 구현과 사용

- `src/pallet/alps/experiment.ts`: 기존 알고리즘 등록부와 확정 검사기를 재사용하는 중앙 팔레트 선택, 배송 대분류, 입고 및 출고 재적재, 통계와 대응 비교.
- `src/pallet/alps/worker.ts`: 브라우저 계산 격리. 실행별 별도 Worker; 취소·시간 상한·진행 표시.
- `src/pallet/alps/AlpsLab.tsx`, `alps.css`: 적용 전/후와 동일 시드의 낮은/높은 성과, 입고·출고 P1/P2 단계 재생, 설정, JSON/CSV 저장.
- `PalletLab.tsx`, `relay/dashboardView.ts`, `index.html`: ALPS 명칭 및 기존 탭을 유지하는 신규 검증 탭.
- `tests/pallet-alps.test.ts`: 인과 정보 경계, 동일 용적, 편중, 물리 제약, 버퍼·수량 보존, 고정 시드, 별도 확인 및 시간 초과 검증.
- `tests/pallet-alps-benchmark.test.ts`: 60개 실제 비교 실험과 보고서 생성.

기본 화면은 저장된 실제 Node 측정 결과를 불러옵니다. 측정 환경과 시각을 표시하며 브라우저의 실측으로 표시하지 않습니다. 실험 조건을 펼쳐 수정하고 ‘동일 조건 비교 실행’을 누르면 현재 브라우저에서 재측정합니다. 현재 시뮬레이터의 입력을 가져올 수도 있습니다. 수정한 설정은 다음 실행에 적용되고 이미 측정한 결과 조건은 따로 표시됩니다. 취소된 부분 실행에서는 전체 선정 조건이 충족되기 전 추천하지 않습니다.

## 공정한 실험 조건

입고 팔레트 2개와 재분배 목적 팔레트 2개는 모든 정책에 동일합니다. 분류 적용 후 용적을 늘리지 않았습니다. 기본은 유통 가정 합성 박스 36개, 각 팔레트 1000×800×700 mm입니다. 박스는 기존 혼합 크기 예제이며 지지·누적 하중·허용 방향 검사와 균등 내부 질량 가정을 그대로 사용합니다. 별도의 무거운 박스 우선 규칙은 끄고 입력 허용 상부하중 검사는 유지합니다. 강도는 합성 가정이며 실측이 아닙니다.

배송 분류는 물건별 의류/기타이며 입력 분류 비율만큼 ID를 시드로 추첨합니다. 동일한 규격과 물성의 물건도 서로 다른 분류일 수 있습니다. 분류 때문에 크기·질량·재질·강도·질량중심을 바꾸지 않습니다. 분류는 배송 속성이지 소재를 자동 추론하는 모델이 아닙니다. 실제 상품 데이터 연결 시 ID별 분류 매핑 인터페이스를 확장해야 합니다.

정책은 다음 세 개입니다.

1. 공용: 현재 박스를 두 입고 팔레트에서 평가.
2. 전용: 의류→P1, 기타→P2. 해당 팔레트가 막히면 미적재 기록.
3. 용량 부족 시 혼합 허용: 전용 팔레트 실패 시 다른 팔레트도 검사. `mixed`는 이 예외 배치 횟수이며 JSON/CSV로 확인 가능.

중앙은 각 팔레트의 기존 알고리즘 제안을 같은 확정 검사로 다시 검사합니다. 서로 다른 알고리즘의 원시 점수를 비교하지 않고 결과 높이→지지율→팔레트 번호로 목적 팔레트를 선택합니다. 각 팔레트의 예약 상태는 독립적입니다. 실제 투입 순서는 환경에만 있으며 계획 입력에는 현재 관측, 해당 팔레트 배치, 종류별 잔여 수량, 물리 설정만 전달합니다. 미래 순서·분류 매핑·환경 객체를 넘기지 않습니다. 실패한 박스는 미적재로 기록하고 다음 도착을 처리하는 공통 실험 정책입니다. 기존 공장 화면의 순환 컨베이어를 변경한 것이 아닙니다.

측정 보고서의 후보 상한은 **팔레트당 16개**입니다. 공용 정책은 두 팔레트를 평가하고 전용 정책은 한 팔레트만 평가하므로 실제 검사 횟수가 달라집니다. 모든 알고리즘에 같은 상한과 제약을 제공합니다. 미래 평가 깊이 1, 샘플 2, 미래 후보 4는 수정 가능한 기존 설정입니다. 단일 실험은 30초이며 Worker에는 추가 10초의 응답 상한이 있습니다. 탐색 실패/예산 초과는 불가능의 증명이 아닙니다.

## 재분배 가정과 검증 범위

기본은 **의류 우선 출고**: 의류 작업 완료 전 기타 목적지는 열지 않습니다. ‘동시 출고’에서는 두 목적지가 처음부터 열립니다. 정적 배치에서 상부 박스/그리퍼 여유가 수직 인출을 막으면 접근 가능한 차단 박스를 제한된 임시 버퍼로 먼저 옮깁니다. 다른 분류의 실제 차단 관계가 있을 때만 그 이동이 발생합니다. 목적지에 현재 박스를 못 넣으면 다른 접근 가능한 박스를 검토하고 목적지 상태가 바뀐 뒤만 재시도합니다. 버퍼 6개 기본값은 현장 실측이 아닌 가정입니다.

임시 이동 1회는 실제 임시 인출 한 번입니다. 이후 목적 팔레트 이동은 별도 1회입니다. `moves = redistributed + rehandles`이며 아직 버퍼에 남은 물건도 수량에서 제외하지 않습니다. 모든 이동 단계는 원본·목적 팔레트·버퍼 스냅샷으로 저장합니다. 출고 완료율 분모는 전체 정상 입고 박스 수, 입고 대비 출고 실패 수는 `placed - redistributed`입니다. 재분배를 정밀 동역학·실제 로봇 사이클 타임으로 해석해서는 안 됩니다.

검증한 것은 직육면체 충돌, 허용 자세, 실제 설정 지지 조건, 정적 반력, 입력 누적 하중, 수직 인출의 보수적 수평 간섭입니다. 목적지 재적재는 기존 `inspectConstraints`로 재검증합니다. 이상적 로봇 입력에서는 로봇 검사를 했다고 표시하지 않습니다. 실제 IK/링크 충돌, 진공 밀봉, 동적 파손, 상자를 빼낼 때의 측면 마찰, 두 팔레트 사이 전체 운반 경로와 작업시간은 미검증입니다. 재생 속도는 설명을 위한 상대 진행률이고 시간 측정값이 아닙니다. 실제 컨베이어 실험과 단순 운반 동작을 혼동하지 않습니다.

## 실제 측정 결과와 해석

`docs/alps-results/measured.json` 및 `.csv`, `public/alps-results.json`을 참조합니다. Node v24.19.0 / Windows / AMD64 환경, 4알고리즘×3정책×5시드 = **60회**입니다. 20261010~20261012는 선정, 20261013~20261014는 별도 확인입니다. 알고리즘 실행 순서를 시드마다 회전했습니다. 계산시간은 계획 호출+공통 감사의 wall time이며 모듈의 JIT 워밍업·OS 경쟁을 완전히 통제한 마이크로벤치마크가 아닙니다. 운반시간·클라우드 네트워크 지연은 포함하지 않습니다.

별도 확인 시드 평균, ‘용량 부족 시 혼합 허용’ 정책:

| 알고리즘 | 입고 완료율 | 출고 완료율 | 임시 이동 | 계획+감사 합계 |
|---|---:|---:|---:|---:|
| Greedy · 현재 박스만 | 83.3% | 55.6% | 2.0회 | 415 ms |
| Future-Aware Hybrid | 86.1% | 34.7% | 1.5회 | 5693 ms |
| Bottom-Left-Back | 87.5% | 33.3% | 1.0회 | 292 ms |
| 무작위 배치 | 77.8% | 25.0% | 3.5회 | 286 ms |

선정 시드에서 뽑힌 두 후보는 Hybrid와 무작위 배치였습니다. 그러나 확인 시드에서는 Greedy가 더 높은 출고 완료율을 보였습니다. 따라서 **최종 최고 알고리즘을 확정하지 않습니다.** 낮은 임시 이동 수가 출고 성공을 보장하는 것도 아닙니다. 이 결과를 숨기거나 ‘ALPS가 모든 항목에서 개선’이라고 주장하지 않습니다. Hybrid는 입고 완료율/후속 공간에 집중하는 기존 결합 휴리스틱이고 Greedy는 저비용 기준입니다. 이 두 축을 더 큰 실제 입력에서 재검증하는 것이 다음 단계이며, 단 두 확인 시드로 이마트 최적해를 주장할 수 없습니다.

제약 위반 제안 및 확정 제약 위반은 이번 실험에서 0건입니다. 실제 물리/로봇 검증 완료를 뜻하지 않습니다. 모든 조합이 시간 상한 안에 종료했지만 일부 박스는 미적재되거나 재분배가 중단되었습니다. 실패 원인은 보고서의 `failures`와 단계 기록에 보존했습니다. 95% 구간은 대응 차이의 Student-t 구간이며 n=2에서는 매우 불확실합니다. 공식 안전 인증/통계적 우월성 판정으로 표시하지 않습니다.

## 재현

```sh
node node_modules/vitest/vitest.mjs run tests/pallet-alps.test.ts
node node_modules/vitest/vitest.mjs run tests/pallet-alps-benchmark.test.ts
node node_modules/typescript/bin/tsc -b
node node_modules/vite/bin/vite.js build
```

재실행하면 현재 머신 계산시간은 다시 측정됩니다. 시드에 따른 도착과 배치 좌표는 재현되며, 예산 초과 여부는 머신 부하에 따라 달라질 수 있습니다. 박스·단위·알고리즘 버전·설정·입고 순서·지문·환경을 함께 저장합니다. 상세 단계 스냅샷은 배포 용량을 위해 첫 선정 시드의 12조합에 저장하며, 나머지 조합은 원시 지표와 도착 순서를 보존합니다. 브라우저에서 재실행하면 모든 조합의 단계를 생성합니다.

추가 연구 구현이나 새 결합 알고리즘을 이번 결과의 승자로 만들어 넣지 않았습니다. 후속 단계는 실측 입출고/분류 비율/배송 우선순위, 더 많은 선정·확인 시드, 재분배 차단 비용을 배치 평가에 넣는 선택적 휴리스틱의 ablation, 실제 로봇 운반 검증입니다.
