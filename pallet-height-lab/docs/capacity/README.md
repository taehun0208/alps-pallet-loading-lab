# 단일 로봇팔 · 높이 제한과 계산 기한 비교

실행 화면: `http://127.0.0.1:4191/?palletView=capacity#pallet`

GitHub `main`의 `b582caa52e2245f40f2c9fba0f770887c3a9e8c2`를 기반으로 추가했다. 기존 `single`, `relay`, `alps`, `benchmark` 화면은 보존했다. 원격 저장소에 푸시하거나 공개 배포하지 않았다.

## 무엇을 선택하는가

한 팔레트에 가능한 많은 부피를 적재하되, 배치 판단의 계산 기한을 지키는 기반 알고리즘을 찾는다. 로봇 제약 적용 조건의 선택용 시드에서 다음 순서로 비교한다.

1. 필요한 반복이 모두 종료되고 확정 배치 위반·계산 기한 초과가 없는가.
2. 평균 허용 높이 기준 부피 적재율이 높은가.
3. 같은 적재율이면 적재 개수가 많은가.
4. 여기까지 같으면 평균 계산시간이 짧은가.

선택용 시드 42·43으로 선택하고, 1042·1043에서 그 선택의 결과를 따로 보고한다. 검증 결과를 다시 이용해 선택을 바꾸지 않는다. 두 개 시드의 결과는 일반적인 우월성이나 통계적 안정성을 입증하지 않는다.

## 같은 입력의 세 조건

| 조건 | 공통 검사 | 추가 조건 |
|---|---|---|
| 로봇 제약 미적용 | 높이·경계·겹침·허용 회전·지지·하중·정적 평형 | 로봇 실행 가능성은 사후 감사만 수행 |
| 로봇 제약 적용 | 위와 동일 | 유효 가반·TCP 수평 반경·작업공간·공구/운반 상자 경로 근사 |
| 로봇 + 매장 구역 고려 | 위와 동일한 로봇 조건 | 기존 후보에 구역 선호 추가 |

같은 상품·입고 순서·팔레트 1개·후보 상한·보류 용량을 사용한다. 미입고 종류별 잔량은 알려주지만 실제 미래 입고 순서는 계획기에 전달하지 않는다. 무거운 상자를 반드시 아래에 놓는 규칙은 사용하지 않는다.

박스 배치 실패 시 보류 공간에 넣고, 성공적인 배치 뒤에 관측된 보류 박스만 다시 검사한다. 보류 공간이 가득 차면 그 박스를 미적재로 보존하고 다음 입고를 처리한다. 주문 종료 때 남은 보류 박스도 한정된 반복으로 검사한다. 팔레트 교체·출하·래핑은 수행하지 않는다.

입고 수 = 적재 + 미적재 + 미처리 수량을 항상 확인한다. 시간 초과 때 늦게 계산된 좌표는 확정하지 않는다. 완료된 일부 시드만 남은 후보는 선택에서 제외한다. 동일 입력의 로봇 효과는 같은 알고리즘과 같은 검증 시드끼리 차이를 계산한다.

## 팀 자료와 기존 결과의 활용

`ALPS_작업정리_2026-10-10.md`가 참조한 `alps-control-room/engine/core.js`에서 생수·과자·세제·생활용품·헤어케어·스킨케어의 치수, 중량, 가정 상부하중, 매장 구역을 가져왔다. m를 mm로 변환했다. 문서의 24박스가 모두 들어가는 사례에서 확장해 기본은 품목당 12개, 총 72개를 투입한다.

최신 저장소의 `docs/BENCHMARK.md`, `benchmark-measured.json`, `benchmark-v2-measured.json`과 기존 로컬 `singleRobot` 시험 구조를 검토했다. 기존의 다른 제약·입력에서 얻은 종합점수나 알고리즘 순위를 새 조건의 승자로 옮기지 않았다. 현재 실험은 최신 저장소의 실제 공통 계획기와 검사기를 호출한다.

| 후보 | 이번 비교의 역할 |
|---|---|
| Bottom-Left-Back | 낮은 z → y → x 순서의 빠른 기준선 |
| Compact | 기존 Compact 기하 점수를 사용하는 현재 입고 전용 변형. 잔량 예측을 제외하고 낮은 면·접촉·묻히는 틈을 평가 |
| Greedy | 저장소의 `strategy-greedy` |
| Lookahead | 저장소의 가상 잔량 탐색 |
| Future-Aware Hybrid | 저장소의 미래 공간 예약 및 결합 평가 |

Compact는 기존 잔량 평가를 제거한 별도 정책이므로 원래 정책과 같은 좌표를 보장하는 최적화라고 주장하지 않는다. 기존 파일의 점수식은 변경하지 않았다. 팀 문서의 별도 엔진에 있는 Beam/MCTS와 이번 Lookahead/Hybrid를 같은 알고리즘으로 표시하지 않았다.

구역 선호는 원래 후보의 순위, 같은 부서의 가로 구역, 다른 부서 아래 박스를 가리는지를 비교한다. 원래 선택보다 최대 100 mm 높은 후보를 허용한다. 원래 선택과 달라지면 이전 선택에 맞춰 계산된 예약 상태를 버린다. 구역 고려가 항상 적재율·차단 수를 개선한다고 가정하지 않는다.

## 지표와 시간 해석

- 부피 적재율 = 적재 부피 / (팔레트 면적 × 설정한 최고 높이).
- 실제 높이 내부 채움 = 적재 부피 / (팔레트 면적 × 실제 최고 높이).
- 공급 부피 상한 = min(1, 전체 주문 부피 / 허용 부피). 물리 제약을 무시한 느슨한 상한이다.
- 시간 기한은 계획기 호출과 구역 선호를 합친 **한 번의 배치 판단**에 적용한다. 보류 재검사는 별도 판단이다.
- 평균·P95·최대 계산시간, 판단 수·총 계산시간, 기한 초과를 기록한다. 표의 P95 평균은 각 실행의 P95 평균이며 모든 판단을 합친 P95가 아니다.
- JSON에는 계획 수치, 전체 최종 좌표, 실패 원인, 미적재 ID, 조건 식별값을 보존한다.
- 공통 확정 재검사, 최종 독립 감사, 넓힌 잔여 후보 검사의 시간은 계획기 계산시간에 합산하지 않는다. 전체 제어 시스템의 실시간 지연 보장은 아니다.
- 로봇 시간은 선택된 적재 경로의 추정 합계다. 별도 보류대 이동·회수, 래핑·이송·매장 직원 작업시간은 포함하지 않는다.

## 최대 적재와 검증 범위

마지막 상태에서 미적재 품목별 최대 4배 후보(상한 512개)를 검사한다. 추가 자리가 발견되면 버퍼·탐색 개선 여지로 표시한다. 발견되지 않아도 전역 최적성이나 물리적인 적재 불가능을 증명한 것은 아니다. 과거에 별도 처리한 박스를 무제한 버퍼에서 다시 꺼낸 것처럼 적재량에 더하지 않는다.

최종 배치는 독립 겹침·경계 검사와 적재 순서대로 공통 제약 재검사를 수행한다. 로봇을 무시한 배치도 원래 적재 순서에서 로봇 제약으로 다시 감사해 실행 불가능한 박스 수와 사유를 표시한다.

그리퍼 포함 유효 가반 38 kg는 상품 30 kg + 도구 8 kg의 비교 가정이다. TCP 반경은 수평 근사, 높이는 작업공간으로 제한한다. 표시하는 관절 팔은 설명용이며 제조사 운동학·관절 제한·연속 전체 링크 충돌·실제 흡착·판지 압축·동적 물리는 검증하지 않았다. 강도와 마찰은 실측값이 아니다.

```sh

npx vitest run tests/pallet-capacity.test.ts tests/pallet-alps.test.ts tests/pallet-evaluation.test.ts tests/pallet-evaluation-v2.test.ts tests/pallet-robot-arm.test.ts tests/pallet-hyundai-view.test.ts
npm run build
```

기본 보고서는 3높이 × 4시드 × 5알고리즘 × 3조건 = 180개다. Node와 브라우저 모두 알고리즘마다 독립 소량 입력으로 한 번 준비 계산하며 측정에서 제외한다. 화면에서 높이·물량·계산 기한·후보 수·보류 용량·그리퍼 폭·TCP 반경·작업공간 높이를 바꿀 수 있다.

`results.csv`는 원시 비교 수치, `results.json`은 조건·통계·최종 좌표, `public/capacity-example.json`은 화면의 저장 예시다. 파일 크기를 줄이기 위해 저장 예시는 선택된 1200 mm / 첫 검증 시드의 세 조건만 전체 재생 이력을 포함한다. 나머지도 최종 좌표는 보존하며 브라우저에서 다시 계산하면 전체 이력을 얻는다.

화면의 새 계산은 기존 저장 기록을 자동으로 덮어쓰지 않는다. 탭 이탈·중단은 Worker를 종료하고, 실행 중 조건 변경은 잠근다. 새로고침 전에 JSON 저장으로 결과를 보관할 수 있다.
