# 입고 스캐너와 실전 배치 조건 (2026-10-09)

기존 React 19 / TypeScript / Three.js, 중앙 Worker 배정 및 기하·정적 지지·누적 하중 검사를 확장했다. 기존 알고리즘을 삭제하지 않았다. 브라우저 실행: `npm run dev`, 빌드: `npm run build`. 길이 mm, 질량/허용 상부하중 kg, 시간 s, 각도 °. 3D 표시만 m로 변환한다.

## 조작

- 첫 탭 **적재 알고리즘 · 1대**: 일자형 벨트, 한 방향 통과. 집기하지 않은 박스는 끝단 대기로 배출하며 돌아오지 않는다.
- **확장성**: 기존 순환 벨트, 1–8대 및 바닥형·천장형·혼합형. 초기값 4대. 중앙에서 관측된 박스와 팔레트 상태를 바탕으로 동시 명령을 배정한다.
- 실험 조건에서 박스 수·시드·최대 높이·불량률·회전·도구·정렬 조건을 바꾸고 **조건 적용 · 바로 재실행**. 높이만 바꾸면 동일 박스 목록을 유지한다.
- 스캐너 판독에 최근 치수·형상 편차·정상/불량 판정을 표시한다. 장부 무게와 재질은 스캔 측정값과 구분한다.
- JSON 저장은 스캔·격리·배출 및 실제 배치 오차 기록을 포함한다. 실제 배치 좌표가 다음 중앙 계획의 적재 상태가 된다.

## 벤치마크의 6축

6축 기준선은 항상 표시한다. 미측정 축은 0점이 아니며, 점·면을 만들어 측정한 것처럼 표시하지 않는다. **6영역 측정 조건**은 무작위 순서(2회 이상 필요), 누락, 파손, 규격 수정, 팔레트 변경과 그리퍼 기하 경로 모드를 선택한다. 알고리즘과 반복 횟수는 그대로다.

6개 영역에 실제 측정이 있으면 점수 도형을 닫는다. 이는 실제 로봇 검증 완료를 뜻하지 않는다. 기존 PASS / FAIL / NOT VERIFIED, 공식/잠정/제외 순위 정책을 유지했다. 실제 로봇 IK·전체 링크 충돌·진공 밀봉은 여전히 미검증이다.

## 실제 검증

- 10개 관련 테스트 파일, **106개 통과**. 신규 입고 8개 + 실전 조건 7개: 시드 재현성, 스캔/메시 일치, 미관측 정보 차단, 격리 후 오래된 명령 차단, 수량 보존, 일자/순환 차이, 원래 회전 허용 범위, 방향별 강도, 반복 설정, 도구 외곽, 무거운 상부 박스·하중 초과 구분, 보정 한계, 실패 실제 자세 미확정.
- TypeScript 검사 및 Vite 생산 빌드 통과. 기존 큰 청크 경고 유지.
- 브라우저, 시드 42, 불량 100%, 8개: 계측 8, 격리 8, 적재 0, 수량 보존, 공급분 처리 완료.
- 브라우저, 시드 42, 정상 12개, 조 그리퍼, 일자형: 적재 5, 미집기 출구 대기 7, 최소 지지율 100%, 99.3 s. 한 번만 통과하는 벨트는 못 집은 박스를 회수하지 않아 전체 완료율이 낮아질 수 있다. 처리 완료와 적재 성공을 구분한다.
- 혼합 3대 구성 변경/재실행 및 순환 유지 확인. 1920×1080, 모바일 390×844 가로 넘침 없음.
- 브라우저 벤치마크: 무작위 배치, 시드 42–51, 5개 조건×10회=50 trial, 워밍업 1회. 6개 영역 모두 측정되며 6점 도형 생성. 45개 부분 적재, 5개 예외/제약 실패, 시간초과 0. 실패를 포함하므로 종합점수·순위 제외. 원시 기록 `intake-practical-benchmark-measured.json`.
- 장시간 기존 `pallet-benchmark.test.ts` 1개는 180 s 제한시간 초과. 원래 3개 알고리즘 및 Rapier 비교가 포함된 별도 실험이며 통과로 보고하지 않는다. 이번 작업의 106개 관련 회귀 검증과 구분한다.

## 모델 범위와 남은 과제

입고 스캐너는 합성 메시를 아는 기하 센서이며 실제 카메라 인식이 아니다. 눌림 때문에 강도·질량중심을 자동 변경하지 않는다. 불량 박스는 격리하여 변형 접촉 적재 성공으로 계산하지 않는다. 작업시간은 기존 TCP 속도/구간 모델 추정치다.

현재 대상은 직육면체 박스다. 교체형 도구 인터페이스는 확장했지만 임의 형상 물체의 정밀 파지·접촉은 미구현이다. 자유 각도 XYZ 자세, 실제 정렬 접촉력, 동적 충격·밀봉·미끄럼, 실제 로봇 역기구학은 검증 범위 밖이다. 각도 보정 불가 또는 실제 위치 제약 실패 시 출구 대기로 보내며, 자동 재취급·정밀 재시도는 후속 구현이다. 대기 트레이는 수량과 대표 박스만 표시한다.

연속 공정의 스캔/실전 배치 모델과 단일 팔레트 벤치마크는 별도 실험이다. 벤치마크 예외 이벤트 점수는 연속 공정의 실제 스캔 인식률이 아니다. 미래 팔레트/박스 계획에 감춰진 형상 정답이나 미계측 박스 메타데이터를 사용하지 않는다.
