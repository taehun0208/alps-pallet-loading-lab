# 더 높게 쌓기 · 중단 원인과 6단 검증

2026-10-05. 층 수 자체를 2~3단으로 제한하는 코드는 없습니다. 기존 기본 입력의 중단을 재현한 뒤, 같은 입력의 재고 선택 실험과 별도의 6단 검증 입력을 실행했습니다.

## 기본 입력이 2단에서 멈춘 이유

기본 Greedy는 8개, 최대 630mm에서 아홉 번째 `B28-01` 박스(716×177×146mm, 5.23kg)를 처리하지 못합니다. 설정 높이는 1,600mm이므로 위쪽 공간은 970mm 남습니다. 그러나 바닥 공간이 나뉘어 있고 기존 박스 윗면의 높이와 크기가 서로 다릅니다. 현재 박스의 지지 조건은 바닥 면적 95% 이상입니다. 팔레트 안에서 상세 검사한 상단 후보 96개의 최대 지지율은 약 63.0%였습니다. 무게 순서와 하중 중심 조건도 함께 검사합니다.

이는 검토 후보의 결과이며 모든 연속 좌표에서의 불가능성 증명이 아닙니다. 버퍼 없는 순차 공급에서는 현재 정상 박스를 보류하거나 다음 박스를 먼저 꺼낼 수 없어 중단합니다. 높이 한계 숫자를 키우는 것만으로 받침이 생기지는 않습니다.

## 같은 안전 조건의 실제 결과

Greedy, 계획기 시드 2026, 기본 탐색 설정입니다. 기본 혼합 입력은 생성 시드 20261004, 입고 시드 42를 유지했습니다.

| 입력 / 공급 | 적재 | 최대 지지 단수 | 최대 높이 |
| --- | ---: | ---: | ---: |
| 기존 혼합 30개 / 무작위 순차 투입 | 8/30 | 2단 | 630mm |
| **같은 30개 / 전체 재고 선택** | **14/30** | **5단** | **1,375mm** |
| 고층 검증 24개 / 전체 재고 선택 | **24/24** | **6단** | **1,472mm** |
| 같은 고층 24개 / 무작위 순차 투입 | 10/24 | 3단 | 739mm |
| 고층 24개 / 높이 한계만 950mm | 12/24 | 3단 | 739mm |

앞의 두 실행은 치수·무게·재질·팔레트·지지·강도·무게 순서·로봇 수치가 같습니다. 전체 재고 선택은 모든 박스를 실제로 꺼낼 수 있는 별도 공급 조건입니다. 미래 순서를 아는 온라인 알고리즘으로 포장하지 않습니다. 미입고 상자를 미리 쓸 수 있는 환경인지에 따라 결과가 달라집니다.

고층 예제는 24개의 서로 다른 치수, 세 재질, 여섯 중량 단계로 구성한 **합성 검증 입력**입니다. 팔레트에 맞춘 격자 분할이 아니며, 윗단 박스가 하부에 들어갈 수 있도록 구성했습니다. 무작위 현장 입력의 보편적인 전량 적재 성능을 뜻하지 않습니다. 크기는 1mm 단위이고 틈이 남습니다. 최고 6단은 실제 지지 부모 연결의 최대 깊이이며 서로 다른 윗면 높이의 개수를 센 값이 아닙니다.

[최종 5개 적재 실험](pallet-height-measurements.json)에는 입력·좌표·지표·진단과 매 확정 배치의 제약/수량 검사가 있습니다.

## 배치 알고리즘 보완

큰 바닥 면적 → 큰 부피 순으로 다음 박스를 고르는 재고 선택 규칙은 유지했습니다. Greedy/Rollout에서 같은 크기 박스의 위치를 비교할 때 다음 순서로 판단합니다.

1. 모든 기하·지지·누적 하중·무게 순서·로봇 제약 통과.
2. 전체 바닥이 팔레트 또는 한 받침 안에 들어가는 위치 우선. 가능하지 않으면 하드 검사를 통과한 다중 받침을 사용.
3. **아랫단 자체 무게 + 전달된 상부 하중의 중심 치우침을 먼저 최소화.**
4. 잔량 공간과 높이·하중·작업 시간 등의 기존 종합 점수 및 결정적 동점 규칙 적용.

6단 입력은 이 변경 후 모든 받침의 누적 하중 중심이 받침 중심에 정렬됐습니다. 결과가 항상 더 많은 박스를 의미하지는 않습니다. 첫 재고 실험은 15개·1,300mm였고, 최종 중심 정렬 정책은 14개·1,375mm입니다. 박스 수 하나가 줄었으며 높이와 지지 구조가 바뀌었습니다. [첫 실험](pallet-height-first-pass.json)을 보존했습니다.

또한 유효 후보가 없을 때 팔레트 밖의 음수 좌표를 먼저 진단하던 문제를 고쳤습니다. 팔레트 안의 후보를 우선 상세 검사하되 높이 초과 후보도 남깁니다. 950mm 제한 시험에서 예전의 ‘팔레트 경계 밖’ 안내가 실제 ‘최대 적재 높이 초과’로 바뀌었습니다. 가능한 후보의 안전 제약을 낮추지 않았습니다.

## 강체 검증과 수치 수렴

초기 6단 배치의 Rapier 복제에서 약 50.09mm 이동이 나와 안정으로 처리하지 않았습니다. 접촉 면과 아랫단 중심 정렬을 보완한 뒤 기본 접촉 계산에서 약 6.26mm로 감소했습니다. [접촉 설정 보완 전 배치와 물리 결과](pallet-height-before-physics-refinement.json)를 보존했습니다.

강체 계산의 기본값을 접촉 솔버 12회, 접촉 고유진동수 120Hz로 명시했습니다. 이는 **강체 접촉의 수치 계산 설정**이며 포장재 압축 강도 실측값이 아닙니다. 박스 질량·마찰·배치 좌표와 안정 판정 기준 5mm/3°는 유지했습니다. 높은 적층에서의 반복 수와 접촉 강성의 역할은 [Rapier 공식 통합 파라미터 설명](https://rapier.rs/docs/user_guides/c/integration_parameters/)을 참고했고, 사용 API는 설치된 0.21.0 타입 정의와 실제 실행으로 확인했습니다.

같은 최종 배치를 3초, 기본 시간 간격 1/120초에서 계산한 최대 이동은 **0.7561mm**, 최대 회전은 **0°**입니다. 반복 수 24회 결과와 시간 간격 1/240초 결과의 최대 위치 차이는 각각 **0.0104mm / 0.0115mm**였습니다. 같은 혼합 재고의 5단 배치도 최대 이동 **0.5733mm**로 기준을 통과했습니다. [최종 물리·수렴 데이터](pallet-height-physics.json)에 모든 이동/회전과 수치 설정을 저장합니다. 떠 있는 상자의 낙하와 무게중심이 밖인 상자의 전도도 별도 회귀 검사하여 불안정 배치를 안정으로 숨기지 않음을 확인합니다.

강체 복제는 원래 계획 좌표를 변경하지 않습니다. 이 관측 조건의 통과가 포장 압축 변형·운송 진동·흡착·실물 로봇 관절을 검증하는 것은 아닙니다.

## 웹 사용

- 상단 **현재 재고 모아서 실행**: 보고 있는 박스 세트와 물리 조건을 유지하고 전체 재고를 선택하는 새 실행을 시작합니다. 이전 실행은 보관합니다. 손상·누락 이벤트가 있는 입력은 이 바로가기로 재정렬하지 않습니다.
- **6단 적재 예제 실행**: 24개 고층 검증 입력을 불러와 자동 실행합니다. 상면을 잘라 보던 단면 옵션도 전체 높이로 복원합니다.
- [6단 예제 바로 실행](http://127.0.0.1:5173/?palletDemo=high-stack#pallet): URL로 한 번 자동 시작합니다. 일시정지·시나리오 변경 후 다시 자동 시작하지 않습니다.
- **적재 높이 분석**: 지지 연결의 최대 단수, 현재/허용 높이, 남은 높이, 현재 박스와 검사한 상단 지지율, 주요 탈락 조건을 표시합니다. 과거 프레임과 보관 실행의 조건을 따릅니다.
- **물리 검증 실행**: 별도 강체 복제에서 위치/회전 변화를 확인합니다. 실제 설정과 결과는 실행 JSON에도 들어갑니다.

최종 테스트 범위와 결과는 [VERIFICATION.md](../VERIFICATION.md)와 [검증 메타데이터](pallet-height-verification.json)에 기록했습니다. 실제 웹 캡처: [6단 장면](pallet-height-scene.png), [1366px](pallet-height-1366.png), [320px](pallet-height-320.png).
