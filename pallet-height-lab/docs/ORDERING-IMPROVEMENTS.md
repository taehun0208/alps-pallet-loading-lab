# 도착 순서 의존성·계획 재사용 개선

## 실행

기존 프로젝트의 `/?palletView=adaptive#pallet`에서 실행한다. 새 시뮬레이터를 만들지 않았다. 기존 4대 컨베이어·포장 제약·테트리스 화면은 유지한다.

1. C 모드 → **도착 순서 개선 · Wang / Hauser**에서 기능별 설정.
2. **조건 적용 · 새 실행 준비** → 실행 / 일시정지 / 한 단계 실행.
3. 화면 아래 **의존성·재사용·버퍼 비교 · 연구 옵션**에서 11개 조건을 동일 입력으로 비교한다. 진행 중 비교 취소 가능. 각 행에서 실제 단계 기록을 3D로 재생하고 JSON/CSV를 내려받는다.
4. 수정 전 C 재현: 개선 활성화 해제. 이전 JSON에 `ordering`이 없으면 해제로 처리한다. 새 실행의 기본값은 개선 활성화다. A/B 선택은 기존 의미를 유지하며 이 개선을 적용하지 않는다.

```sh
npm install
npm run dev
npx vitest run tests/pallet-ordering.test.ts tests/pallet-ordering-benchmark.test.ts
npm run build
```

## 기존 구조와 중복 구현을 피한 부분

React 19 / TypeScript 5.9 / Vite 7 / Three.js 0.186이다. 별도의 기존 Rapier 강체 실험은 있으나 이번 계획기는 복합 직육면체 기하 + 비음수 반력 정적 근사다. 바닥 x/y, 높이 z, 길이 mm, 질량·하중 kg 상당, 시간 s/ms를 사용한다.

| 기존 모듈 | 기존 기능 / 이번 판단 |
|---|---|
| `pallet/planner.ts`, `strategies/` | Greedy·Bottom Left·Rollout, 미래 공간/재고 전략, 후보별 제약 및 결정 내 캐시. 기존 경로 보존. 전체 재고를 보는 전략과 이번 온라인 실행을 같은 정보 조건이라고 주장하지 않는다. |
| `packaging/planner.ts` | 포장·접근 제약과 미래 시나리오 탐색. 유지. 논문의 CDG나 QOP 정책이 구현된 것으로 간주하지 않는다. |
| `relay/streamPlanner.ts` | 계측된 물품만 고르는 연속 컨베이어·로봇 셀 캐시. 별도 상태기계를 재작성하지 않았다. |
| `adaptive/planner.ts` | EMS 6방향 분할/포함 제거/개수 제한, 형상 경계 정렬 후보, 바닥/상면 활용. 이미 있으므로 새 공간 엔진 불필요. 후보마다 동일 접두 스택의 EMS를 다시 만드는 비용 발견. |
| `adaptive/mechanics.ts` | 변형 형상, 실제 접촉 합집합, 지지율, 합력·볼록 지지경계, 다층 하중, 강도 정보, 비음수 힘/모멘트 평형. 변경하지 않음. |
| `adaptive/grasp.ts` | 전체 흡착면 검사, 상자+그리퍼 수직 경로 Swept AABB. 기존 계산에 사용한 swept geometry를 CDG가 재사용하도록 반환만 확장. 실제 로봇 IK 아님. |
| `adaptive/runtime.ts` | 실상/관측 분리, 제한 버퍼, 대기·시도 상한, 재관측, 공통 실행 판정. 유지하고 계측·세션 내 이전 위치 메모리만 추가. |

기존 C는 높은 점수를 선택한다. 높이 3, 공간 2, 지지 2, 하중 1, 경로 1, 흡착 1, 대기 1, 재시도 0.5, 후속 받침 2의 0~1 정규화 가중 평균이다. 래스터 Heightmap 최소화 알고리즘은 아니다. 기존 높이 선호와 모든 제약을 유지했다. 관측된 형상에 0/90° 수평 회전만 허용하며 실행된 박스를 옮기지 않는다. 기존 Zhu GLA/GLAS 전체 재현 코드는 확인되지 않았고 이번에도 추가하지 않았다.

## 논문과 적용 범위

확인한 1차 자료: [저자 공개 TASE 원고](https://motion.cs.illinois.edu/papers/TASE2020-Wang-RobotPackingNondeterministic-preprint.pdf), [IEEE DOI](https://doi.org/10.1109/TASE.2020.3024291), [저자 프로젝트](https://hauserlab.web.illinois.edu/packing/index.html). 공개 구현 코드를 복사하거나 논문 성능 숫자를 이 프로젝트 측정치로 쓰지 않았다.

| 아이디어 | 실제 적용 / 원형과 차이 |
|---|---|
| VI-A Dependence Minimization | 기존 최대화 점수에서 `λ × 조상 수 / max(1, 기존 적재 수)`를 차감. 원형 HM 대신 기존 복합 점수를 보존한 프로젝트 휴리스틱. 직접 지지 박스 수가 아니라 경로·지지 그래프의 전이적 조상을 센다. |
| V-C CDG | 실제 지지 접촉의 모든 소유자를 보수적 선행 조건으로 취급. 새 박스가 이전 박스의 삽입 경로를 막으면 `이전→새 박스`. 후보 이전 물품과 그 후손을 제거한 상태의 평형을 제한 횟수 재검사한다. 단일 필수 지지 집합을 최소화하는 완전한 원형 모델은 아니다. |
| VI-B Prior Placement Matching | 도착한 대기 물품의 이전 최상위 위치를 메모리에서 먼저 검사. 물성·관측이 동일하고 현재 충돌·지지·하중·흡착·경로를 모두 통과해야 재사용. 불가하면 일반 후보 탐색. 전체 미실행 계획들 간 매칭 대신 세션의 대기 후보 캐시다. |
| VIII Buffer | 기존 버퍼 재사용. 임시 보관 k, 현재 도착 1개를 합쳐 선택 풀 k+1. 입력 배열 앞에서 실제 도착한 물품만 선택한다. |
| VII Equivalence Classes | 크기뿐 아니라 실제 형상, 질량/CoM, 회전, 마찰, 강도/출처, 손상, 흡착 조건, 관측 자세가 같아야 합친다. 대기·재시도 기여가 높은 대표를 검사. ID/배치 결과는 유지. 이전 위치가 다르면 대표로 합치지 않는 보수적 방식. |
| V-D Verify-CDG-Coverage | 작은 고정 계획 집합에 대해 루트 분기/공통 고립 노드 제거/메모화/탐색 상한으로 그래프 순서 포함 여부 또는 반례를 반환. 반례 순서로 실제 계획을 추가하는 소규모 실험을 제공. 전체 QOP 정책 합성은 하지 않는다. |

CDG는 후보 점수와 탐색 보조다. 빠진 복합 물리 조건이 있을 수 있어 **`heuristic-only`**이며, `covered-graph` 결과도 `physicalVerified:false`다. 지지율·누적 하중·접근성은 기존 전체 검사기를 별도로 통과해야 한다. 전체 도착 순서를 먼저 알고 계획들을 고르는 NDOP 그래프 포함 검사와, 같은 관측 접두부에서 같은 행동을 해야 하는 QOP 정책 검증은 다르다. 실행 계획기는 미도착 물품의 순서/정답 형상을 보지 않는다. 논문의 사전 물품 집합까지 활용하는 더 강한 모델보다 정보가 제한적이다.

## 기본값과 비용 제한

- `ordering.enabled`: 새 기본 실행 true. 생략 또는 false면 기존 C. A/B 무시.
- `dependencyWeight=0.12`: 0~1 변경 가능, 최적값 주장 없음. 조상 비용은 0~1. 지지/충돌 위반을 점수로 상쇄하지 않음.
- `cdg/prior/equivalence/spaceCache=true`: 개별 해제 및 비교 가능.
- `removalChecks=8`: 한 의사결정에서 스택과 후보에 공유하는 제거·평형 검사 최대 횟수, 0~64. 필수 최종 제약 검사를 줄이는 값이 아님. 그래프 보조 검사가 생략되면 완전 모델로 표시하지 않음.
- 후보 64개/물품, EMS 80개, 시간 예산 1500 ms는 기존 기본값 유지. 동기식 단일 기하 검사 중에는 예산을 선점하지 못하므로 soft budget이다. Worker 종료로 비교 취소 가능.
- 버퍼 기본 선택 풀 6 = 임시 보관 k=5 + 현재 1. k=0/1/2/3 비교 제공. 최대 대기 8판단, 재시도 2회 유지.
- 접촉 허용 0.5 mm와 관통 허용 0.05 mm 유지. 강도 미확인·실물 진공·동적 안정성·IK 미검증 처리 유지.

증분 EMS는 직전 스택의 동일한 공간 목록에 새 경계상자만 분할한다. 분할 순서·포함 제거·정렬·개수 절단까지 기존 전체 재계산과 같음을 테스트했다. 불가능한 후보에는 선택에 사용하지 않는 빈 공간 선호 점수 계산을 생략한다. 유효한 후보 점수/후보 순서는 보존한다.

캐시는 Session 수명에 묶이고 설정 초기화 시 폐기한다. 관측 또는 물성 변경 시 이전 위치의 키가 달라진다. 스택은 달라져도 반드시 전체 재검증한다. 캐시된 위치가 유효하다는 이유만으로 실행 시 실제 상태 검사를 생략하지 않는다.

## 실측 결과

`ordering-results/ablations.json` 및 CSV: 12개 물품 × 2종 입력군 × 시드 41/42/43 × 14조건 = **84회**. Windows의 Node/Vitest 단일 비교 테스트에서 실행. 후보 24, EMS 80, 시간 예산 30000 ms, 팔레트 800×700×1000 mm. 동일 입력군·시드 내 SHA-256 입력 해시 동일. 측정 시각/런타임과 모든 배치·미배치 원인을 JSON에 저장했다. 모든 실행에서 시간 예산 도달 0, 성공 배치의 모든 단계에 기존 물리 제약 검사 통과.

| 입력 / 3시드 평균 | 기존 C | 전체 결합 | 관찰 |
|---|---:|---:|---|
| 혼합·변형 박스 배치 수 / 12 | 4.00 | 4.00 | 증가 확인 안 됨 |
| 혼합 높이 mm | 670.67 | 670.67 | 동일 |
| 혼합 계획시간 ms | 639.2 | 523.4 | 약 18.1% 감소 |
| 혼합 후보 수 | 760 | 737 | 약 3.0% 감소 |
| 동일 2규격 반복 배치 수 / 12 | 12 | 12 | 전량 유지 |
| 반복 높이 mm | 300 | 300 | 동일 |
| 반복 계획시간 ms | 168.6 | 138.8 | 약 17.7% 감소 |
| 반복 후보 수 | 943 | 753 | 약 20.1% 감소 |

그룹화 단독은 반복 물량에서 후보 943→511(45.8% 감소), 평균 97.6 ms였다. 증분 EMS 단독은 혼합 535.4 ms / 반복 137.7 ms로, 의존성 추가보다 이번 입력에서 계산 비용 대비 효과가 명확했다. 전체 조합은 기존 위치가 서로 다른 동등 물품을 보수적으로 분리하므로 그룹화 단독보다 후보 수가 많다.

λ=0, 0.06, 0.12, 0.25는 이 6입력에서 배치 수·높이가 동일했다. 의존성 단독은 반복 물량에서 193.4 ms로 기존 168.6 ms보다 느렸다. 따라서 **의존성 비용이 적재 성공률을 개선했다고 주장하지 않는다.** 작은 입력/시드와 장비·JIT 편차가 있으며 통계적 보편 성능 보장이 아니다. 동일한 품질을 더 적은 계산으로 얻은 사례가 확인된 것이다.

버퍼 k=0/1/2/3의 혼합 평균 완료 수는 4.67/3.33/3.67/4.00, 반복 물량은 모두 12였다. 반복 높이는 320/320/320/300 mm였다. 큰 버퍼가 항상 낫지 않으며, 기존 대기 상한·선택 순서와 간섭한다. 미배치가 있으면 낮은 최종 높이를 단독 품질 개선으로 해석하지 않는다.

추가 취급 횟수는 버퍼에 둔 고유 ID당 입고/출고 2회라는 **모델 추정값**이다. 로봇의 실측 취급 수가 아니다. `replans`는 기존 실패 후 재관측/재시도 계수이며 정상 단계별 계획 호출 수와 다르다.

순서 검증 결과는 `ordering-results/coverage.json`에 별도 저장한다. 4개 상자의 지지 순서 반례를 찾아 고정 계획을 추가하고 그래프 포함을 확인했다. 이 결과도 전체 물리 보증이나 QOP 인증이 아니다. 탐색 상한은 `budget`, 미포함 순서는 `counterexample`이며 실제 적재 불가능 증명으로 표시하지 않는다.

## 남은 한계 / 후속

모든 순서에 대응하는 QOP 정책 트리, 정밀 접촉 물리의 CDG 충분조건 증명, 전체 계획 간 동등류 순서 검증, 미도착 물품의 집합 정보 활용은 범위 밖이다. 명확한 계산 이익이 있는 기존 EMS 재사용부터 적용했고, 의존성·이전 위치 선호는 입력에 따른 품질 저하 가능성이 있어 선택 해제를 남겼다. 더 많은 실물 규격·순서, 높은 적재율 스트레스 입력, 제한시간별 P95/P99 지연과 실패 원인 분포를 다음 검증 대상으로 권한다. 현재 변경은 변형·관측 C 경로에 통합했으며, 연속 4로봇 협업 스케줄러에 CDG를 직접 주입하지 않았다.

재개 후 중앙 배차도 기존 연속 컨베이어에 통합했다. [중앙 오케스트레이션 구조·별도 검증](CENTRAL-ORCHESTRATION.md)을 참고한다. 논문 C 계획기의 실측 개선과 중앙 배차 구조 변경의 결과를 구분한다.
