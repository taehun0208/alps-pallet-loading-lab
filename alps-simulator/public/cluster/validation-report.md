# ALPS 군집 적재 평가·검증 보고서

작성일: 2026-10-10. 원자료: `public/cluster/`. 현장 실험이 아닌 단일 팔레트 합성 입력 시뮬레이션이다.

## 선정 결과

- 적용 전: Compact (`capacity-compact`). 기존 6종 중 선정 점수가 가장 높았다.
- 적용 후: ALPS 군집 · 연결 우선 (`cluster-layer`, `cluster-packing/1`). Tetris와는 별개 후보다.
- 관측 하위: Bottom-Left-Back (`blb`). 이번 비교의 하위이며 모든 문제에서 가장 나쁜 알고리즘이라는 뜻은 아니다.
- 의도적 비효율 대조군: 분산 적재 (`dispersed`). 지지·하중 등 공통 제약을 유지하며 동일 상품 접촉을 덜 선호하게 만들었다. 실제 점수가 BLB보다 높았으므로 최하위 화면에 억지로 사용하지 않았다.

## 선정과 확인 분리

10개 정책을 선정 시드 21010–21013의 40회로 비교하고 순위를 고정했다. 이후 별도 시드 22010–22021의 120회로 확인했다. 총 160회, 회당 72개다. 화면 기본 시드 22010도 확인 결과를 보기 전에 지정했다. 알고리즘·선정 규칙·입력·소스 해시는 `freeze.json`에 동결했다.

점수 = 적재율×30 + 바닥 직접 접촉률×25 + 동일 SKU 접촉률×30 + 내부 빈틈 효율×10 + 중심 균형×5. 내부 빈틈 효율은 `clamp(1 - columnVoid / 적재 상자 부피)`, 중심 균형은 `clamp(1 - 수평 무게중심 편차 / 팔레트 반대각선 길이)`다. 항목들은 0–1 비율이며 총점은 100점이다. 가중치는 이번 목표에 대한 설계 선택이다.

선정 실행 모두에서 제약과 기한을 통과해야 한다. ALPS 후보는 기존 최고 평균 적재율에서 5%p 넘게 손해인 후보를 제외했다. 이번 임계값은 60.281875%다. 실제 다음 박스 순서는 제공하지 않는다. 같은 시드의 모든 정책은 같은 입고·SKU별 잔량·물리 제약·시간 기한을 사용하지만 후보 수와 탐색 방법은 서로 다르다. 같은 연산량으로 최적화한 비교는 아니다.

## Compact 대비 선정 ALPS의 대응 차이

통계 단위는 개별 상자가 아니라 같은 입고 시드의 실행 쌍이다. 12개 대응 차이에 Student t의 95% 구간을 사용했다. 여러 보조 지표를 탐색적으로 제시하며 전체 입력 분포나 현장 성능의 보장은 아니다.

| 지표 | 평균 차이 ALPS − Compact | 95% 구간 |
|---|---:|---:|
| 가중 점수 | +5.05점 | [+2.87, +7.24]점 |
| 적재율 | +2.46%p | [-1.63, +6.54]%p |
| 바닥 직접 접촉 | -0.12%p | [-2.38, +2.15]%p |
| 동일 SKU 접촉 | +14.83%p | [+10.30, +19.36]%p |
| 동일 SKU 수직 접촉 | +18.02%p | [+12.22, +23.82]%p |
| 내부 빈틈 | -4.14 L | [-6.48, -1.79] L |

**해석:** 이번 입력에서 동일 SKU 군집·수직 접촉·내부 빈틈은 개선됐다. 적재율과 바닥 사용률의 차이 구간은 0을 포함한다. 따라서 두 지표의 일반적 개선을 확인했다고 발표하면 안 된다. 바닥 사용률만 보면 ALPS Tetris의 평균 90.85%가 가장 높고, 선정한 군집 연결 정책은 87.71%다. 연결 정책은 군집을 포함한 사전 가중 점수에서 선정했다. 모든 지표의 동시 최적해가 아니다.

## 과거 테스트는 어떤 의미가 있는가

- 과거 133회·9,576개 판단의 원본 해시와 당시 소스 스냅샷을 확인했다. 기존 엔진과 초기 Tetris 개선 결과를 현재 군집 정책의 결과로 바꾸지 않았다.
- 별도 Python 검산으로 과거 133회 및 새 160회·11,520개 판단의 박스 ID·수량, 기한, 경계·비겹침, 바닥 면적, 내부 빈틈, 질량가중 무게중심, 접촉 면적, 점수, 재취급 수량·시간, 대응 입력과 신뢰구간을 확인했다. 결과는 `audit.json`에 있다.
- 과거 독립 5개 시드의 개선 구간은 0을 포함했다. 계산의 일관성과 실행 가능성을 확인한 근거로는 의미가 있지만, 적재율 우월성을 입증한 근거로는 부족하다. 과거 선정에는 현재 군집 지표가 없었다.
- 코드 테스트 14개 파일·97개는 모델·정보 경계·실행 기한·재생 수량 보존 등 오류를 찾는 검증이다. 97회의 실물 실험을 뜻하지 않는다.

## 재생·카운팅·모델의 범위

3개 화면은 저장한 실제 알고리즘 배치 좌표와 판단·로봇 완료 시각을 재생한다. 재생 중에는 그 시점까지 적재 완료한 상자로 지표를 다시 계산한다. 상자 인식 시 SKU별 입고 잔량을 감소시키며 미적재 박스도 잔량에서 제외한다. 적재량과 남은 입고량은 다른 수량이다. Tetris는 잔량 비율로 가상 미래 입고를 샘플링하고, 연결 정책은 남은 규격을 좁은 틈 판단에 사용한다. 연결 정책이 잔량에 비례한 구역 예약을 한다고 설명하면 안 된다.

72개 상자 총부피 1,860.912 L는 팔레트 허용 부피 1,440 L보다 크다. 모든 상자를 한 팔레트에 적재하는 것은 불가능하다. 미적재는 결과에 남기며 숨기지 않는다. 동일 SKU 접촉 지표는 직접 맞닿는 면적을 사용하므로 공중에 떨어져 있는 박스의 단순 투영 겹침은 접촉으로 세지 않는다.

재분배는 동일한 상부 접근·목적 구역 순서·임시 보류 규칙에 따른 추가 취급 모델이다. 100개당 시간은 적재된 SKU 구성과 개수가 다른 결과를 정규화한 값이며, 실제 매장 소요 시간의 실측이 아니다. 동작 시간·강도는 가정이다. 현재 시뮬레이션은 정적 지지·반력·허용 상부 하중과 그리퍼 경로 근사를 검사한다. Python 검산이 재료 강도·전체 로봇 관절 경로·운송 진동을 독립 인증한 것은 아니다. 자세한 근거는 `ALPS-TETRIS-알고리즘과-물리모델.md`에 정리했다.

## Claude Opus 5.5 검토 상태

요청 모델 `claude-opus-5-5`로 API 호출을 시도했으나 제한된 네트워크에서 연결되지 않았다. 외부 API 접근을 위한 권한 상승도 자동 승인 정책에서 거부됐다. 모델 답변을 받지 않았으므로 Claude 검토 완료나 승인을 주장하지 않는다. 최초 호출 프롬프트는 `docs/claude-cluster-prompt.txt`, 완료된 전체 자료에 대한 후속 검토용 프롬프트는 `docs/claude-cluster-final-prompt.txt`, 호출 상태는 `public/cluster/claude-review-status.json`에 있다.
