# ALPS Tetris 비교 실험 — 최종 조건

2026-10-10. 원래 1,000회·MCTS 포함 설계에서 사용자의 시간 제한 요청에 따라 **MCTS 제외, 조건당 100회**로 축소했다. 선정 결과를 보고 표본 수를 바꾼 것이 아니다. 이전 실험과 예비 실행은 본 평가에 합산하지 않는다.

| 항목 | 최종 조건 |
|---|---|
| 팔레트 | 1,200 × 1,000mm, 적재 높이 1,200mm |
| 박스 | 총 30개; 조건 A 6 SKU, 조건 B 8 SKU |
| 표본 | 조건별 서로 다른 난수 시드와 서로 다른 SKU 입고 순서 100개 |
| 비교 | BLB, Compact, Greedy, Lookahead, Future Hybrid, ALPS Tetris, ALPS 군집 |
| 총 실행 | 2 × 100 × 7 = 1,400회, 최대 42,000개 판단 |
| 정보 | 현재 박스·배치·규격·종류별 잔량, 실제 미래 입고 순서는 비공개 |
| 공통 조건 | 10초 주기, 1초 여유, 9초 계획 한도; 버퍼 없음; 상대 중량 순서 금지 제외 |
| 물리 검사 | 지지, 정적 평형, 허용 상재하중, 경계·겹침, 그리퍼·도달성 대리 검사 |
| 실행 | 최대 4개 프로세스, 조건·입고 인덱스별 25개 묶음, 같은 입고의 7정책 순환 |

각 조건의 규격과 수량은 고정한다. 100회는 서로 다른 100개 제품 규격 조합이 아니라 서로 다른 입고 순서다. 6 SKU는 각 5개, 8 SKU는 앞 6종 각 4개·추가 2종 각 3개다. SKU 추가와 수량 재배분으로 공급 부피도 변하므로 조건 간 절대 적재율을 직접 알고리즘 효과로 해석하지 않는다.

주 지표는 **실제 적재 부피 / 공급된 박스의 전체 부피**다. 같은 조건·시드의 ALPS Tetris와 나머지 6정책 차이를 대응 비교한다. 두 조건의 총 12개 비교에 Bonferroni 보정 신뢰구간을 적용한다. 실무 차이 기준은 +2%p로 사전 설정하며, 보정 구간 하한이 이를 넘을 때만 해당 비교에서 의미 있는 개선이라고 표현한다. 100회에서 차이가 불명확하면 그 불확실성을 그대로 보고한다.

보조 지표는 적재 수량, 팔레트 허용 부피 기준 적재율, 바닥 접촉, 동일 SKU 접촉, 수직 공극, 무게중심, 개별 판단 P50/P95/P99/최대, 기한 실패·fallback이다. 실패 실행을 주 지표에서 삭제하지 않는다. 중단·누락은 별도로 표시하고 미완료 집합을 완료 결과로 부르지 않는다.

## 점수 표시

사용자가 요청한 빠른 성과 비교를 위해 본 평가를 시작하기 전에 아래 **설계 우선순위 점수**를 고정한다. 산업 표준·최적해 인증·통계 검정 지표가 아니다. 원 지표도 나란히 제공한다.

`점수(0~100) = 60 × 공급부피 적재비율 + 15 × 바닥 접촉률 + 15 × 동일 SKU 접촉률 + 10 × 기한 준수율`

기한 준수율은 `1 − 기한 실패 판단 수 / 관측된 판단 수`다. 동일 SKU 접촉이 정의되지 않는 빈 배치·무접촉 배치의 점수 항은 0으로 둔다. 표본별 점수를 계산한 뒤 평균한다. 서로 다른 물량을 가진 두 조건은 별도로 보여준다. 이 종합점수의 사후 순위는 기술통계이며 주 지표 검정의 우월성 결론을 대신하지 않는다.

## 시간과 한계

병렬 본 실행 시간은 **다른 실험과 CPU를 공유한 조건의 wall-clock 시간**이다. CPU 경쟁은 판단 지연뿐 아니라 시간 한도에서 선택한 배치에도 영향을 줄 수 있다. 단독 성능·실제 로봇 사이클·운송 안전성으로 확대하지 않는다. 기록한 단독 예비 실행과 병렬 예비 실행을 구분한다. 실제 로봇이 10초 움직이는 동안 대기하는 것이 아니라 계산된 시간 모델을 사용한다.

30개는 공급 부피가 팔레트 허용 부피보다 적어 주 지표에 천장 효과가 있을 수 있다. 이번에는 높이 1,200mm 하나만 평가하므로 여러 높이의 최적해를 주장하지 않는다. 10 SKU·60개·MCTS와 1,000회는 이번 시간 제한 범위에서 제외했다. 현장 SKU 분포와 실제 물성·로봇 운동학은 별도 검증이 필요하다.

## 재현

`npm test`, `npm run build` 후 esbuild로 TypeScript 실행기와 Worker를 번들링한다. 최종 명령은 아래와 같다.

```sh
python3 scripts/benchmark-1000-pool.py --out docs/benchmark-1000/evaluation-v2 --n 100 --concurrency 4 --batch-size 25
python3 scripts/benchmark-1000-audit.py --root docs/benchmark-1000/evaluation-v2
```

소스·분석 코드·입력 manifest·실행 설정을 동결한 뒤 실행한다. gzip 원자료, 각 묶음의 진행 상태, 전체 진행률을 남긴다. 기존 파일이 있으면 동일 hash·identity를 확인하여 재개하며 관측된 실패를 성공 결과로 덮어쓰지 않는다.
