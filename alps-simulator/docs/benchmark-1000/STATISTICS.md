# Frozen statistical analysis

The current evaluation uses **100 unique arrival orders per condition**, two conditions (1200 mm, 30 boxes, 6 or 8 SKU) and seven policies: BLB, capacity-compact, strategy-greedy, lookahead, future-hybrid, floor-dense and cluster-layer. There are **1,400 trials**. MCTS and the historical 10-SKU/60-box pressure conditions are excluded following the user's revised time and sample-size requirements. Historical pilot-v1 is incomplete and belongs to a different frozen protocol. Pilot-v2 calibrates execution, not algorithm selection or outcome-dependent sample allocation.

Each condition has fixed geometry, SKU quantities, mass and synthetic material parameters. Seeds and full SKU arrival sequences are both unique within that condition; the same sequence and complete input are paired across all policies. These are 100 different arrival orders, not 100 different box geometries. The generator still supports and tests 1,000 unique arrival orders; the actual evaluation sample size is read from its freeze manifest. The two inventories have different supplied volumes, so outcome comparisons are made within each condition.

The primary outcome is **placed volume / supplied volume**, recomputed from raw box dimensions. Pallet fill (placed volume / allowed pallet volume), accepted box fraction and placed count are descriptive secondary outcomes. A rejected box contributes zero placed volume while remaining in the supplied-volume denominator. Auditable error, cancelled and deadline-miss trials remain in descriptive means and any available matched pair. Missing or corrupt trials are explicitly counted, never assigned an invented zero or silently treated as successes. Any missing/corrupt trial prevents a complete evaluation claim; partial summaries are preliminary and cannot support a superiority claim.

The primary family is floor-dense versus each of six other policies in each of two conditions: **12 predeclared comparisons**. For each pair, compute D = acceptance(floor-dense) − acceptance(baseline), its sample mean, sample standard deviation and SE = SD / sqrt(n). Report ordinary paired Student t 95% CIs and Bonferroni simultaneous 95% CIs using t(1 − 0.05 / (2 × 12), n − 1). Report two-sided paired t p-values and min(1, 12 × p). The ordinary and adjusted intervals use the same pairs, including failures and misses; there is no success-only primary filter.

The practical superiority threshold is **+0.02 (2 percentage points)**. Evidence for meaningful superiority against a particular baseline requires the adjusted interval's lower endpoint to exceed +0.02 and the evaluation to be complete. A positive mean or small p-value alone does not establish practical superiority. No overall winner, tuned algorithm selection, global optimum, distribution-free guarantee or real-cell safety/latency guarantee follows from these finite synthetic workloads. At n=100, intervals can be materially wider than at n=1,000. Paired t inference is an approximation over independently seeded synthetic orders; unique-order rejection sampling introduces negligible dependence in the enormous order space and is disclosed rather than represented as physical production data.

The analysis uses SciPy's Student t functions when installed. Its standard-library fallback computes t tail probabilities through the regularized incomplete beta function with a converged continued fraction. For n=100 and small pilot samples, quantiles are obtained by 80-step bisection of that t CDF. Only df ≥ 999 use a fourth-order Cornish–Fisher t-quantile expansion. Thus the actual n=100 analysis uses numerical Student t inversion, not a normal critical value. A zero-variance difference has a degenerate interval; a nonzero constant difference receives p=0, while an exactly zero difference receives p=1. Fewer than two pairs produce no inferential interval or p-value.

Decision latency P50/P95/P99/max is computed by pooling **raw decisionMs values** within each condition/policy, including first startup decisions and failed/missed decisions that have traces. Quantiles use linear interpolation at p × (N − 1), not averages of per-trial quantiles. Worker startup is excluded by the canonical supervisor. Four concurrent process workers share the machine, so measured deadlines and latency reflect contention; they are throughput results under this execution setting, not isolated CPU latency or actual robot motion measurements. Native policy search/candidate/iteration caps differ and remain disclosed in the frozen source and configuration.

Run the independent auditor after the pool finishes:

```sh
python3 scripts/benchmark-1000-audit.py --root docs/benchmark-1000/evaluation-v2
```

For a live partial snapshot, add `--allow-incomplete`. It permits an incomplete exit without hiding missing counts, but does not permit corrupted data. Exit codes are 0 for complete/explicitly allowed partial snapshots, 1 for audit errors, and 2 for incomplete evaluation. `--output` selects an alternate report directory; the default is `<root>/audit`.

The auditor reads both `<root>/trials/*.json.gz` and `<root>/shards/**/trials/*.json.gz`. It validates freeze signatures and archived source hashes; unique condition manifests, seeds and SKU sequences; raw filename/trial IDs; identical frozen scenario/config/arrival data; box conservation and dynamic quantities; accepted/rejected/unprocessed partitions; raw decision counts and residual inventories; finite dimensions/timings; placed volume, fill, accepted fractions, deadline/fallback counts; pallet bounds and box overlaps; and reconstructed engine input fingerprints plus an independent SHA-256 pairing hash. JSON drops undefined observation properties; the documented ArrivalEnvironment optional fields are restored as null solely to reproduce the engine's canonical fingerprint. Current source changes are reported separately when intact frozen snapshots exist. The audit does not independently reimplement robot reach, swept gripper clearance, support/load constraints, or transport stability.

Outputs are `audit.json`, `trials.csv`, `summary.csv`, `paired-effects.csv` and compact `summary.md`. Every summary carries expected/audited/missing sample counts, status and miss counts. The JSON includes all missing trial identities and audit errors. No table automatically crowns a winner or converts an incomplete sample into a final claim.
