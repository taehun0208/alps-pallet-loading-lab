# Claude Opus 5.5 독립 프로토콜 검토

사용자 요청에 따라 Anthropic Messages API를 실제 호출했다. 알고리즘 수치 계산은 재현 가능한 로컬 시뮬레이터가 수행하며, Claude는 실험 설계와 해석을 검토한다. API 응답에서 내부 추론과 서명을 제거하고 공개 최종 답변·모델·토큰 사용량·종료 사유만 보존했다. API 키는 저장하거나 출력하지 않는다.

## 현재 적용 범위

사용자가 실행 시간을 2시간 이내로 줄이고 MCTS를 제외하도록 변경했다. 현재 목표는 높이 1200mm·30개 박스, 6/8 SKU 두 조건, 7개 알고리즘, 조건별 100개의 고유 입고 순서, 총 1,400개 trial이다. 본 평가 시작 전 사용자가 150개 계획을 100개로 줄이도록 확정했다. 원래 1,000개 순서·4개 조건 설계는 대체되었다. 입고 seed뿐 아니라 실제 SKU 순서도 중복 제거한다. 같은 조건·순서의 모든 알고리즘은 같은 입력을 사용한다.

최종 사용자 해석 기준은 기본 적재 성능 우선이다. 먼저 배치 개수와 부피를 확인하고, 실제 사용 높이의 3차원 밀도와 column void를 함께 읽는다. 동일 SKU 군집은 기본 적재가 충분할 때만 추가 가치다. 기존 보조 점수는 채택 순위의 근거로 사용하지 않는다. 이 해석은 사후의 기술적 판단이며, 사전 지정한 부피 수용률 1차 검정을 밀도 검정으로 바꾸지 않는다.

4개 병렬 작업은 공유 머신 부하 상태의 실험이다. 벽시계 마감이 있는 탐색은 경합에 따라 지연뿐 아니라 탐색량·최종 품질도 달라질 수 있다. 결과는 해당 병렬 실행 조건에 한정하며, 소규모 순차 파일럿과 동질적인 지연 표본으로 합치지 않는다.

## API 검토 이력

1. `claude-protocol-prompt.txt` → `claude-protocol-review.json`: 원래 32,000-trial 설계의 소스 발췌 검토. `claude-opus-5-5`, `end_turn`, 입력 6,024 / 출력 7,283 토큰. 출력 중 thinking 3,001 토큰은 공개 파일에서 제거했다. 이 검토는 아래 새 범위의 완료 증거가 아니다.
2. `claude-reduced-prompt.txt` → `claude-reduced-review.json`: 실행 전 중간 계획이던 조건별 150개·총 2,100-trial·4작업 설계의 요약 검토. 이후 최종 사용자 요청은 조건별 100개로 변경되었으며, 이 API 검토가 최종 100개 구현이나 원자료를 감사했다는 뜻은 아니다. `claude-opus-5-5`, `end_turn`, 입력 1,583 / 출력 4,904 토큰. 출력 중 thinking 1,504 토큰은 공개 파일에서 제거했다. 요약 검토이며 변경된 전체 구현을 감사했다는 뜻은 아니다.

## 첫 검토의 핵심과 확인 상태

Claude는 원래 짝비교 설계가 합성 입력에 대한 비교로 유효할 수 있다고 판정했고, 제출된 발췌 코드에서 확정적인 치명적 버그를 찾지 못했다. 다만 제한된 발췌만 보았으므로 일부 항목을 추가 검증 요구로 분류했다.

- 병렬 실행의 출력 충돌을 막으려면 단일 freeze 준비와 서로 다른 shard 출력이 필요하다. 변경된 러너는 이 구조와 실행 동시성 기록을 도입했다.
- 분석 방법·실패 처리·입력·소스·실행 예산은 평가 전에 동결하고 번들은 현재 소스에서 다시 빌드해야 한다.
- 모든 trial과 실패를 보존하고, 실행이 중단되면 목표 표본 수를 완료했다고 보고하지 않는다.
- 높이·수량·SKU 구성의 명시적 확인이 권장된다. 원래 검토가 의심한 `quantityPerSku` 덮어쓰기는 `core.ts`의 사용자 시나리오 경로에서는 발생하지 않는다. 기존 workload 테스트도 수량과 입력 제한을 검증한다.
- 원래 검토에서 요구한 algorithm·seed 필드는 이미 `evaluateTrial`의 반환값에 포함된다. 추가 `orderIndex`는 추적 편의 사항이다.

## 고정할 해석

1차 지표는 공급 부피 중 배치한 부피의 비율이다. `floor-dense` 대 다른 6개 알고리즘 × 두 조건의 12개 비교에 대해 짝차이와 일반 95% 구간, Bonferroni 동시 95% 구간을 제시한다. 실질 기준은 사전 지정한 2%p다. 신뢰구간이 충분히 좁지 않으면 표본 수가 100개여도 우월성은 미결정이다. 100% 수용률의 동률은 우월성으로 바꾸지 않는다.

재고 형상은 조건 안에서 고정되어 있다. 이 실험은 100가지 형상이 아니라 100가지 입고 순서다. 조건 간 SKU 조합은 부피도 바꾸므로 SKU 수 자체의 인과 효과를 입증하지 않는다. 결과는 시험한 구현·제약·예산·부하 상태의 성능이며, 논문 알고리즘의 정확한 재현, 전역 최적성, 실제 로봇 10초 사이클을 입증하지 않는다.

## 실행 전 150개 중간 계획에 대한 API 판정

Claude는 n=150, 12개 비교 family, 4작업 부하 조건의 설계를 **조건부로 의미 있는 비교가 가능**하다고 판정했다. 판정은 실행 완료나 실제 우월성을 뜻하지 않는다.

가장 강하게 제기한 점은 실행 시간이다. 4작업 × 7,200초 ÷ 2,100 trial = 약 13.7 작업·초/trial이다. 오버헤드와 예비 시간을 고려하면 파일럿으로 이보다 빠른 처리량을 확인해야 한다. ETA는 조건×알고리즘의 실측 trial 시간과 병렬 효율로 산정하고 실행 초반 처리량으로 갱신한다. 결과의 효과나 p값을 보고 n을 바꾸지 않는다.

150개 계획 검토의 권고는 최종 100개 계획에도 다음과 같이 적용·해석한다.

- 순서 하나의 7개 알고리즘은 같은 shard에서 사전 지정 순서로 실행한다. 4개 shard 전체를 하나의 seed를 끝낼 때까지 막는 전역 장벽은 필요하지 않지만, 중단 시 완전한 짝과 미완료 짝을 명시한다.
- 오류·마감 초과 trial은 확보된 배치 부피/전체 공급 부피로 기록하고 미처리 화물을 공급 분모에서 빼지 않는다. 취소 시도도 별도로 보존한다. 목표 n 미완료 분석은 불완전·탐색적으로 표시한다.
- 9초는 **박스 한 개의 결정 탐색** 마감이다. 10초는 인지·여유·경로를 포함한 목표 cycle이며 실제 로봇 검증 결과가 아니다.
- 모든 짝차이가 0인 경우 차이 0과 동률 사실을 보고하고 우월성을 주장하지 않는다. 실제 n의 자유도로 t 분위수를 계산하며 API 답변의 근사 상수를 그대로 하드코딩하지 않는다.
- API의 BLAS/OpenMP 제어 권고는 일반적인 병렬 연산 점검 사항이다. 본 러너는 Node worker 기반이며 해당 라이브러리를 사용한다는 근거는 없다. 공유 머신의 다른 작업을 완전히 금지하거나 CPU 격리를 완료했다고 주장하지 않는다.
- API 답변의 "조건 간 비교 금지"는 SKU 수의 인과 효과나 사전 지정하지 않은 1차 검정을 피하라는 취지로 해석한다. 조건별 수치를 나란히 기술하는 것 자체가 금지되는 것은 아니다.

검토 원문은 JSON의 `content` 텍스트에 보존되어 있다. 표본 수 변경만을 이유로 설계 검토를 다시 호출하지 않는다. 전체 결과가 완성되고 독립 감사가 통과한 뒤에는 실제 요약치를 제공하여 별도의 경험적 결론 검토를 한 번 수행할 수 있다. 낮은 effort를 지정한 별도 호출 도구는 네트워크 연결 단계에서 즉시 실패하여 응답이나 토큰 사용 증거가 없으며, 최종 성공 응답은 기존의 검증된 호출 도구로 확보했다.


## 최종 사용자 변경 반영

실행 전 API 설계 검토는 조건당150개 계획을 대상으로 했다. 이후 사용자가 본 평가 시작 전 조건당100개로 확정했다. 실제 평가는2조건×100개×7정책=1,400회다. 비교군12개는 동일하지만 표본 감소로 신뢰구간이 넓어진다. 이 설계 검토가 최종100개 원자료를 검산했다는 뜻은 아니다. 본 평가는 독립 Python 감사로 확인하며, 완료 후의 별도 API 결과 검토는 아래에 구분해 기록한다.


사전 지정한 보조 기술 점수는 공급부피 수용률 60점, 바닥 접촉 점유율 15점, 동일 SKU 접촉 15점, 마감 준수 10점으로 구성한다. 이는 사용자 목적에 맞춘 기술적 요약이며, 산업 표준이나 별도의 통계적 우월성 검정이 아니다. 점수의 높은 순위를 1차 지표의 실질적 우월성 또는 전역 최적성으로 해석하지 않는다.


## 실제 형상 확인 및 이전 프롬프트 정정

원자료의 freeze는 팔레트 폭 **1200mm**, 깊이 **1000mm**, 높이 제한 **1200mm**다. 실행 전 두 프롬프트 요약에는 폭을 1000mm로 잘못 적었다. 실제 소스·동결 입력·계산에는 1200×1000mm가 사용되었으며, 원자료를 이 때문에 변경한 것은 아니다. 설계 요약 검토가 정확한 최종 형상을 검산했다는 주장을 피하고, 실제 결과 검토에는 올바른 형상과 실제 수치를 제공한다.


## 완료된 실제 결과에 대한 별도 API 검토

`claude-results-prompt.txt`와 `claude-results-review.json`은 **최종 n=100**, 2조건×7정책=1,400회 전체 결과를 제공한 별도 호출이다. 모델은 `claude-opus-5-5`, 종료는 `end_turn`, 입력 10,224 / 출력 5,256 토큰이다. 출력 중 thinking 1,270 토큰과 서명은 공개 응답에서 제거했다. 이번 검토는 이전 n=150 계획 검토와 구분한다.

제공한 증거는 독립 감사의 완료 상태와 12개 짝비교 CI, 14개 조건·정책 셀의 개수·부피·수용률·사용 높이·envelope 밀도·column void·지연이다. 전체 원자료 감사는 1,400/1,400회, 오류·결측 0개다. 실제 계산 경과는 804.413초(약 13분 24초)다. Claude가 원자료 전체를 직접 다시 계산한 것은 아니며, 이미 감사한 요약과 지표 정의를 검토했다.

Claude의 핵심 판단은 **단일 보편 승자를 지정할 수 없으며 기본 적재량과 3D 밀도의 조건부 선택이 필요하다**는 것이다. 브랜드와 SKU 접촉, 보조 점수로 채택 순위를 정하지 않았다.

| 6 SKU | future-hybrid | 28.15 | 705.89 | 91.04% | 53.08% | 1113.0 | 6.01 |
| 8 SKU | Compact | 27.16 | 665.89 | 86.09% | 53.43% | 1048.2 | 6.32 |

Tetris−Compact의 수용률 차이는 6 SKU에서 +3.60%p, Bonferroni 동시 CI [+0.68,+6.51]%p다. 통계적으로 양수지만 사전 실질 기준인 **최소 +2%p**를 입증하지 못했다. 8 SKU는 +2.11%p, CI [−0.70,+4.91]%p로 우월성도 동등성도 확정하지 못했다. 반면 BLB·Greedy·Lookahead 대비는 두 조건 모두 동시 CI 하한이 +2%p를 넘었다.

Tetris는 두 조건에서 관찰된 평균 envelope 밀도가 가장 높다. cluster는 개수와 낮은 column void에서 유리하지만 Tetris보다 키가 크고 envelope 밀도는 낮다. future-hybrid는 8 SKU의 평균 배치 부피가 가장 크지만 사용 높이·column void·계산시간이 증가했다. Compact는 빠르고 높이·밀도 프로필이 Tetris와 가깝지만 평균 적재량이 적다. 이 밀도·개수·추가 정책 간 순위는 기술적 비교이며 사전 12개 수용률 검정의 확증 결론으로 바꾸지 않는다.

### API 결과 문구의 검증 및 정정

원문 JSON은 외부 검토의 실제 답변을 보존하되 다음 표현은 그대로 채택하지 않는다.

- 원문은 cluster의 사용 높이가 두 조건 모두 가장 높다고 썼다. 실제로 8 SKU는 future-hybrid 1146.5mm가 cluster 1132.9mm보다 높다. cluster가 **Tetris보다** 두 조건 모두 높다는 비교는 맞다.
- 원문의 "낮은 무게중심" 도입 권고는 제공한 요약에 CoG가 없으므로 이번 호출로 뒷받침되지 않는다. 실제 사용 높이와 envelope 밀도에 한정한다.
- 원문의 "낮은 높이도 Tetris가 가장 좋음"은 8 SKU에는 적용되지 않는다. 8 SKU의 최저 평균 높이는 Compact 1048.2mm이며 Tetris는 1052.3mm다.
- 상위 정책 사이의 비유의 결과는 동등성이나 비열등성이 입증되었다는 뜻이 아니다. 높이가 낮다는 이유만으로 적재량 손실이 허용 가능하다고 결론내리지 않는다.
- 하위 정책 제외 권고는 이번 두 합성 입력과 구현 범위의 파일럿 우선순위로만 읽는다. 다른 재고에서 일반적으로 무용하다는 뜻은 아니다.

다음 채택 검증은 실재고와 새 입력에서 개수·부피·밀도 목표와 허용 높이/연산시간을 미리 정한 뒤 수행한다. 군집은 기본 적재 목표가 충족될 때 추가 가치로 평가한다. 모든 정책의 관찰된 마감 초과 0건은 실제 로봇의 사이클이나 물리 안전 보증이 아니다. 이번 API 검토 이후 추가 호출은 하지 않는다.
