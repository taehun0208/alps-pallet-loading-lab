# ALPS 적재 군집 시뮬레이터

기본 화면은 세 개다. [적용 전](http://127.0.0.1:4192/#before), [적용 후](http://127.0.0.1:4192/#after), [상·하위 비교](http://127.0.0.1:4192/#compare). 실제 계산 기록으로 적재 과정을 재생하며 일시정지·탐색·배속·완료 배치를 지원한다. SKU별 6색, 바닥 접촉 지도, 적재 수량과 인식 시 줄어드는 입고 잔량을 보여준다. 기존 실험실은 `/?view=lab`에 보존했다.

현재 선정은 Compact → ALPS 군집 · 연결 우선 (`cluster-layer`), 관측 하위는 Bottom-Left-Back이다. 의도적 분산 대조군도 추가했지만 실제 최하위가 아니어서 하위 화면에는 사용하지 않았다. 선정용 40회와 별도 확인 120회, 총 160회를 완료했다. 확인 12개 시드 평균에서 동일 SKU 접촉은 38.10→52.94%, 바닥 접촉은 87.83→87.71%다. 적재율·바닥의 대응 차이 신뢰구간은 0을 포함한다.

- [선정 및 검증 보고서](docs/CLUSTER-평가와-검증.md)
- 원자료·점수·신뢰구간: `public/cluster/index.json`, `trials.csv`, `trials/`
- 독립 Python 검산: `public/cluster/audit.json` (과거 133회 + 새 160회)
- 동결 소스·선정 규칙: `public/cluster/freeze.json`
- 현재 코드 검증: `npm test` 14개 파일·97개 테스트, `npm run build`
- Claude Opus 5.5: 네트워크 연결 실패 및 권한 상승 자동 거부로 미완료. `public/cluster/claude-review-status.json`에 기록했다.

다음 내용은 이전 실험실과 Tetris v2 검증 이력이다. 현재 군집 비교의 결과와 구분해서 읽는다.

기존 실험 페이지와 분리한 단일 팔레트·로봇 1대 비교 앱. 10/12초의 목표 동작 주기 동안 다음 관측 박스의 배치를 계산하고, 기한을 통과한 실행의 적재율·공간 점유·질량 균형을 비교한다. 목표 주기와 강도 입력은 설계 가정이다.

```sh
npm install
npm run dev
```

주소: http://127.0.0.1:4192/

현재 작업 공간에서는 기존 설치 패키지를 node_modules 심볼릭 링크로 재사용한다. 앱 소스·진입점·Worker·새 실험 데이터는 이 폴더 안에 독립적으로 있다. 배포하거나 다른 폴더로 옮길 때는 패키지를 별도 설치한다.

- 비교 실험: 동일 입력의 Bottom-Left-Back, Compact, Greedy, Lookahead, Future Hybrid, UCT MCTS, ALPS Tetris. 후보/예측/반복 상한 및 계산 예산을 명시한다.
- 적용 전후 시연: 기본 방식의 적재 완료 → 재분배, 선정 후보의 랜덤 입고 → 적재 → 재분배, 선정 실험 상·하위 후보의 동시 시연. 재분배는 상부 접근과 임시 보류를 적용한 동일 규칙의 취급 시간 모델이며, 실제 매장 작업시간과 구분한다.
- 개별 적재: 저장된 실제 배치 결과를 순서대로 재생한다. 로봇 궤적은 설명용으로, 실제 관절 IK·동역학 검증 결과가 아니다.
- 매장 효율: 구역 간 잠재 방해 상자 수와 입력한 재취급 시간의 조건부 추정. 실제 매장 작업시간 실측이나 전체 매장 애니메이션은 포함하지 않는다.
- 밀도 개선: ALPS Tetris는 낮은 자리와 신규 내부 빈틈을 우선하고 후보 경계·틈 좌표를 확장한다. 같은 가상 잔여 입고로 단기 후속 부피도 비교한다. 바닥 직접 접촉률과 전체 XY 투영률을 분리하며, 최고 적재율이나 최적해 보장은 아니다.
- 그래프: 평균과 입고 시드 간 95% t 신뢰구간, SVG/4K PNG 및 새 벤치마크 CSV/JSON. 현장 성능이나 전역 최적성으로 일반화하지 않는다.

멘토 협의에 따라 **무거운 상자를 가벼운 상자 위에 놓지 않는 자중 순서 규칙은 제외**한다. 지지·허용 상재하중·정적 평형·그리퍼 접근은 공통으로 검사한다. 알 수 없는 실제 미래 입고 순서는 계획기에 전달하지 않는다.

자세한 시간 모델과 공통 엔진 출처는 [엔진 설명](src/engine/README.md), 새 벤치마크 입력·환경·원본은 `public/results/`에 기록한다. 기존 8초/100ms 결과는 이 앱에 가져오지 않는다. 100ms는 사용자가 선택할 수 있는 별도 예산 실험이다.

## 검증

새 정책을 고정한 뒤 10초 주기·1,200mm·72개 입력으로 처음 쓰는 시드 12042–12046에서 7종을 35회 비교했다. Compact 대비 ALPS Tetris의 평균 적재율은 63.19→69.19%, 바닥 접촉률은 86.83→90.05%다. 수직 공극은 3.73→5.43L로 늘었다. 대응 차이의 95% 신뢰구간이 모두 0을 포함하므로 일반적인 우월성의 증거로 표현하지 않는다. ALPS Tetris의 최대 판단 준비 시간은 464.9ms, 35회 전체 기한 실패는 0회다. `public/results/independent-improvement.json`에 대응 비교와 정의가 있다. 12초 자료는 개발에 사용했던 입력의 재평가이며 새 독립 평가와 분리한다. 원본 84회와 후속 49회의 총 133회·9,576개 판단은 보존·검산했다.

2026-10-10 독립 검증: 동결된 ALPS Tetris v2를 포함하여 `npm test`로 **11개 파일, 76개 테스트 통과**. 알고리즘 구현과 별도로 작성한 테스트에서 다음을 확인했다.

- 같은 입고의 박스 ID·수량 보존, 원본 입력 불변, 알고리즘 간 동일 입력, 실제 미래 입고 순서와 입고 난수 시드의 계획기 비노출.
- 멘토 합의에 따라 단순 자중 순서 금지는 제외하면서 허용 상재하중·지지·경계·겹침·방향·도달성·그리퍼 접근·공구 질량 포함 가반 검사를 유지.
- 7개 알고리즘의 실제 계획 함수가 공통 검사를 통과한 후보를 반환. UCT MCTS가 실제 탐색을 수행하는 작은 사례 포함.
- Worker 기한에 도달하면 이전에 검증한 후보만 사용하고 작업을 종료. 유효 후보가 없으면 미배치. 늦은 결과, 다른 결정 ID, 잘못된 박스 ID와 경계 침범 결과는 확정하지 않음.
- 계획 Worker 오류·초기 준비 실패·준비 전/계산 중 취소의 종료 동작, 교체·폐기된 화면 Worker의 늦은 오류 차단.
- 10초·12초 가정의 로봇 동작 중 2초 계획을 중첩하고 초기 준비를 한 번만 더함. 9초 계획 기한의 fallback을 검증 여유 내 확정하고 11초 결과는 10초 주기에서 제외.
- 손계산 가능한 형상의 부피·질량가중 무게중심·허용 높이 적재율·빈 공간, 미확인 강도의 `null`, Student t 신뢰구간·개별 판단 P95·입고 시드 대응 비교·Pareto 관계.
- ALPS Tetris의 유효한 바닥 배치 우선순위, 새로 묻히는 빈 공간의 정확한 기하량, 같은 높이의 인접 면·받침 연결·회전, 공통 제약과 실제 미래 순서 비노출을 전용 9개 테스트로 검증.
- 바닥 접촉 면적과 전체 수평 투영 면적을 구분하고, 겹치는 투영의 중복 제거·분리된 영역·입력 불변을 5개 테스트로 검증.
- 재분배 전용 9개 테스트로 단계별 상자 보존·상부 방해물 우선 제거·목적 구역 순서·임시 보류 슬롯 중복 방지와 재사용·동일 주기 시간 계산을 검증. 같은 구역의 방해물은 바로 목적지로 옮겨 불필요한 추가 취급을 만들지 않음.

지연과 오류의 경계 조건은 주입한 가상 시계/Worker로 검증했다. 이 테스트 수는 현장 처리량·로봇 사이클·운송 안정성·매장 시간의 실측 건수가 아니다. 성능 수치는 별도 실행 결과와 그 입력·환경 기록으로 확인한다.
